# remember-me — Memory MCP Server

## Entry point & execution

```bash
cd /path/to/remember-me
source .venv/bin/activate
python -m app.server              # HTTP mode (default, config port or 1314)
python -m app.server --stdio       # subprocess stdin/stdout
python -m app.server --data-dir /path/to/data  # config is <DIR>/config.jsonc
```

`bin/start.sh` is the recommended launcher: it sets `MEMORY_STORAGE=dual` and
sources the gitignored, host-specific `.env` (embedding provider and model
cache) if present. The configured provider must match the active embedding
profile in the data directory's `memories.db`, otherwise startup fails and requires an offline
`app.embedding_cli reindex`/`activate`.

Admin UI Debug mode defaults off and is controlled only by configuration
(`debug: true` in config.jsonc, or enable it on the configuration page and save
then refresh). This shows global/create/detail Debug buttons, Audit navigation
and Stats diagnostic entries; element inspection still requires clicking a Debug
button. Restart Server reloads the saved configuration. The `--debug` startup
option is no longer supported. Debug does not change logging or MCP tools and
has no UI effect in stdio mode.

Data directory selection: `--data-dir` > `MEMORY_DATA_DIR` > the OS per-user default
(Linux `~/.remember-me/`, Windows `%LOCALAPPDATA%\remember-me\` with a `~/AppData/Local`
fallback, macOS `~/Library/Application Support/remember-me/`); relative
directories are resolved against the project root. `<data-dir>/config.jsonc` contains
`{"port":1314,"language":"zh-CN","auto_download_model":true,"local_only":true,"debug":false,"proxy":{"enabled":false,"url":""}}`
and is created only on normal startup. Missing fields use these defaults.
JSONC supports line/block comments and trailing commas; config saves preserve
existing comments. Legacy config.json is read only when config.jsonc is absent;
normal startup adopts it into JSONC and retains the old file. Read-only/help
commands never migrate. With both files present, JSONC is authoritative and
invalid JSONC never silently falls back to JSON.
Language is stored but not yet applied to translations. `--port` temporarily overrides the
configured port; `--stdio` explicitly selects subprocess transport. Runtime paths,
logs, temporary files and local model caches are contained in the selected root.
Local providers load cached models without networking first, and download only on
a cache miss when permitted. In HTTP mode a cache miss starts the configuration
UI/MCP transport with forced maintenance (`required_reason=model_not_ready`),
then prepares the model in one owned background worker. Memory access and exiting
maintenance are blocked until loading, warmup and database validation succeed;
success allows manual maintenance exit, never auto-exits. Config UI saves proxy
and retries without restart, showing real dependency byte progress or an
indeterminate bar. GET /api/model, POST /api/model/retry and GET/POST /api/config
remain available while preparing. Config writes require no maintenance, support
all config fields and preserve JSONC comments; port/language apply after restart.
The config page puts ordinary settings above maintenance-only operations.
/api/config/model remains a compatibility alias. Shutdown
cancels and joins the worker before releasing resources. stdio/CLI remain synchronous.
HTTP/HTTPS proxies are configured solely in config;
disabled means direct access, ignoring inherited proxy variables. Loopback Ollama
always bypasses proxies. Config entrypoints override legacy provider/HF offline
variables and disable Xet to keep downloads on the configured HTTP transport.
`bin/manage embedding download-model` explicitly permits missing-model downloads
even with automatic downloads disabled. Ollama models require external `ollama pull`.
Path environment variables and CLI output paths are root-relative; external paths
are rejected. Use `bin/manage config migrate --dry-run` then stop the service and
run without `--dry-run` to copy and verify legacy paths, retaining sources. For a
new root: `bin/manage --data-dir NEW config migrate --source-data-dir OLD`. A pending
migration journal blocks startup; rerun migration to recover before proceeding.
See `docs/project-management/plans/43-config-and-data-root.md`.

Two transport modes:

| Mode | Command | Description |
|------|---------|-------------|
| **stdio** | `python -m app.server --stdio` | Subprocess stdin/stdout (explicit) |
| **HTTP** | `python -m app.server` | Starlette + Uvicorn; binds `127.0.0.1:<port>` by default (`local_only: true` in `config.jsonc`), or `0.0.0.0:<port>` when `local_only: false` (LAN-accessible, restart to apply); serves legacy SSE **and** Streamable HTTP from one instance |

HTTP endpoints (all share the same service/runtime/provider/storage):

| Endpoint | Transport | Notes |
|---|---|---|
| `GET /sse` + `POST /messages/?session_id=...` | legacy HTTP+SSE | retained for existing clients (e.g. opencode); Codex treats it as legacy |
| `POST /mcp` | MCP Streamable HTTP | `stateless=True` + `json_response=True`; no `Mcp-Session-Id`; `GET`/`HEAD`/`DELETE`/other methods return `405` with `Allow: POST` (security is checked first); Host/Origin restricted to loopback (`127.0.0.1`/`localhost`) — illegal Host `421`, illegal Origin `403`; with `local_only: false` this DNS-rebinding protection is disabled entirely (no auth, trusted LAN only) |
| `GET /read-me` | static page | LLM-facing config guide; self-references `http://127.0.0.1:<port>` (port follows `--port`; stays loopback even in LAN mode); read-only, no auth; `503` while closing |

`/mcp` is the protocol endpoint; `/read-me` only documents how to connect. See `docs/project-management/plans/29-streamable-http-and-read-me.md`.

## Key architecture facts

- **Package layout** — `config` owns configuration/Settings/JSONC; `domain` owns pure validation and query rules; `storage` owns contracts, factory, backends, locks and JSONL/recovery; `embedding` owns providers, codecs and semantic index-value resolution; `transport` owns MCP tools, receipts and Admin HTTP; `operations` owns call pools, maintenance, import coordination and model preparation; `cli` owns offline commands. Root `server.py`, `runtime.py`, `service.py`, `audit.py` and `log_config.py` retain their roles. Cross-package imports use the new module paths; domain does not import Service/Runtime/transports, and online business never imports CLI. `app.storage` explicitly exports contracts and `create_storage`; implementations import `storage.base`, and the factory lazily imports backends. Package imports must not acquire runtime resources.
- **CLI compatibility** — Six root modules (`manage_cli`, `embedding_cli`, `recover_cli`, and keyword/category/anchor `*_migrate_deepseek`) are command-only compatibility launchers. Their sole entrypoint delegates to `app.cli`; internal imports and monkeypatch targets use the implementation modules. Keep existing `python -m app.*` and `bin/` commands, exit codes and bootstrap behavior. Do not add aliases for deleted internal modules. `app/read_me.md` remains adjacent to `server.py`; Admin serves `web/index.html` and its split `web/static/` assets (CSS + ES modules) from `config.configuration.PROJECT_ROOT`.
- **`app/config/settings.py` / `app/runtime.py`** — Configuration-backed immutable `Settings.from_config()` snapshot (`from_env` remains a side-effect-free low-level helper) and explicit runtime ownership. `create_runtime(settings)` acquires nothing; `start()` configures logging/audit, creates provider/storage, validates and warms up, then starts dual sync/health/background work. `close()` waits for imports and periodic sync, attempts final outbox sync, then releases stores/locks, provider, audit and owned logging handlers. Business resources are released through one `_close_business()` that runs service → storage → provider even when one closer raises, preserving the first error. Online recovery and maintenance are runtime-owned: `start_maintenance_import()`/`maintenance_import_status()` own the import maintenance action through a single completion waiter, `maintenance_sync()` centralizes force-sync plus recovery-marker verification/removal and sticky-error clearing, and `recover_status()` returns locked snapshots of the mutable recovery jobs. Startup failure cleans up acquired resources. Imports and `python -m app.server --help` have no runtime side effects. One active runtime/audit configuration per process.
- **`app/operations/calls.py` / `app/embedding/provider_adapter.py`** — Runtime-owned `AsyncCallAdapter` bridges async transports to synchronous business: a fixed 4-worker business pool plus an independent single-worker control pool (both created lazily after `start()` and released on `close()`). Embedding, SQLite, JSONL, audit-file and config/file work run there so the event loop stays responsive; pure in-memory state/static routes stay inline. The admission context manager is entered *inside* the worker, so a call queued behind slow inference is re-checked after maintenance entered. Caller cancellation cancels only not-yet-started work (`asyncio.shield` keeps running work owned); shutdown rejects submissions, cancels queued work and waits for running work before storage/provider/audit are released. The provider is wrapped in `SerializedProvider`, one reentrant lock serializing query/document/batch/warmup/close across online requests, imports and recovery, and translating non-`EmbeddingError` provider failures into `EmbeddingError`; provider-internal batching is preserved and service still completes inference before acquiring a storage transaction lock.
- **`app/operations/import_coordinator.py`** — Service-internal `ImportCoordinator` owns import job records, one bounded history, a single active import, its worker threads and one completion `Event` per job. The worker's outermost `finally` unlinks the input file, releases the active slot and only then sets the event, so `MemoryService.wait_import()` (used by Runtime's maintenance waiter) returns a final snapshot and never polls. Thread-start failure rolls the job back and leaves the file to the caller.
- **`bin/manage` / `docs/operations/runbook.md`** — Operator entry point for offline embedding/profile maintenance, historical backfills, and CLI JSONL recovery. Read-only status can run while the service is active; independent write CLIs require graceful shutdown. The Ops UI supports online maintenance and uploaded JSONL recovery inside the active runtime.
- **Shutdown/restart** — Ops offers Restart Server and Shut Down Server after entering maintenance mode. `/api/restart` and `/api/shutdown` respond before rejecting new work and asking Uvicorn to exit; active SSE sessions end, HTTP work drains, and imports finish without a timeout. Restart execs only after cleanup; shutdown requires a terminal start. stdio EOF/SIGTERM also clean up; piped stdin uses cancellable asynchronous reads. See `docs/project-management/plans/38-runtime-lifecycle.md`.

- **`app/server.py`** — MCP transport and endpoint registration. 11 tools: `add`, `search_semantic`, `search_lexical`, `search_anchor`, `search_meta`, `get_details`, `update`, `delete`, `stats`, `report`, `list_keywords`. 2 resources: `memories://stats`, `memories://list`. Tool definitions and dispatch come from the single `app/transport/tools.py` `ToolSpec` table (`handle_list_tools` and `handle_call_tool` both read it); every invocation is recorded to the audit journal. `handle_call_tool` and `handle_read_resource` read the SDK/transport audit context on the event loop, then run the synchronous handler via the runtime's `AsyncCallAdapter` (in-worker admission; `INLINE_RUNNER` when constructed with a bare service in tests). `search_semantic`/`search_meta` responses carry a per-call `search_id` that the `report` tool uses to attach feedback on search result helpfulness. `search_semantic` accepts `keywords` and `categories` candidate filters: exact values are preferred, unmatched values are semantically resolved within the same dimension/namespace, then the resolved values filter candidates before memory-text cosine scoring. `search_semantic` and Admin semantic search also accept timezone-aware `updated_after`/`updated_before` (strict exclusive bounds, normalized to UTC); shared domain validation and SQLite integer-microsecond predicates filter candidates before cosine scoring and Top-K. Memories dates apply to both browsing and searching. Values use OR within each dimension and AND across dimensions/namespace; `filter_resolution` exposes and audits the mapping. `search_lexical` is a separate content-only BM25 primitive (literal identifiers, error codes, symbols) whose score is not comparable with cosine; `search_anchor` matches only the anchors declared in `metadata.anchors` (identity signals, not content). `search_semantic`/`search_lexical`/`search_anchor`/`search_meta` each carry a per-call `search_id` consumed by `report`. Strict anchor-validation failures return `response_code="invalid_anchors"`. `search_meta` remains exact-only and shares the same updated-time validation and integer-microsecond filtering as semantic search and Browse (including the legacy Admin list endpoint). Unknown namespaces are rejected: `search_semantic`/`search_meta` return an empty-result envelope with `response_code="namespace_not_found"` and `response_meta.known_namespaces`, while `add`/`update` refuse to write unless the caller passes the matching `confirm_codes` entry (the admin HTTP API does the same and maps it to HTTP 400). The HTTP app also serves legacy SSE (`/sse` + `/messages/`) and stateless Streamable HTTP (`/mcp`), plus the static `/read-me` config page; all transports share one `mcp.server`, runtime, provider and storage.
- **Keyword discovery** — `list_keywords` and `POST /api/keywords/query` share browse/literal/semantic modes with optional namespace and an optional exact `categories` filter (OR within categories, AND with namespace; keywords used by live memories carrying any listed category). Semantic mode accepts 1–20 concepts and reuses active keyword vectors, returns score/count candidates without exact-first suppression, and does not create a search_id. Public Stats returns `keyword_total`, never `keyword_counts`; complete vocabulary is available through the new query API without low-frequency trimming. The standalone Keywords Admin menu/page was removed on 2026-10-11; Memories keyword candidates and exact filters, Stats keyword rankings/drilldown, MCP list_keywords and the query API remain available. Before setting keywords, query semantic candidates in the target namespace and reuse only when meaning fits; new words remain allowed. See `docs/project-management/plans/36-keyword-discovery.md`.
- **`app/transport/tool_definitions.py` / `app/transport/tools.py`** — `tool_definitions.py` holds the 11 tool schemas/descriptions (kept byte-identical by the `tests/fixtures/` golden tests). `tools.py` binds each definition to a plain argument-adapter handler, its read/write and search-receipt flags, and a namespace-error mode; the shared `execute_tool` owns the state check, timing, exception mapping, search-receipt registration, hint selection and audit call, and each tool's audit policy is declared in the `app/audit.py` registry. Adding a tool means one `ToolSpec` entry plus its audit registration and the `read_me.md` list.
- **`app/audit.py`** — Runtime-owned `AuditJournal` for tool-call/background-task rolling JSONL (`data/audit.jsonl` plus `.1`…`.9` by default), thread-safe, 10MB per file / 10 files by default, never raises, never blocks tool calls. Per-tool params/result trimming lives here behind the explicit `AUDIT_EVENTS` + `PARAM_POLICIES`/`RESULT_POLICIES` registry (`_trim_params` / `_trim_result`); a tool or background event must be registered, and tests assert the MCP tool set is covered. Events record source/request/session/client context, explicit `search_id`/`source_search_id`/`keyword_query_id` links, known memory namespaces, capped confirmation codes and response codes. IDs are caller-declared associations; validation belongs to [26]. Streamable HTTP tool calls additionally carry `transport=streamable_http` and a per-request `http_request_id`, set through the dedicated `http_transport_context` ContextVar and merged by `MCPApplication._audit_context()`; `request_audit_context` (admin/SSE admission) is unchanged. Offline CLIs use separate journals; legacy module functions remain for direct low-level callers.
- Every writable service or maintenance process obtains a lifetime OS `flock` on the canonical SQLite-primary sidecar `<db>.writer.lock`; a second writer for that primary fails immediately. Read-only diagnostics remain possible. In dual mode, the NDJSON replica additionally has its own one-writer lock per replica path. SQLite outbox rows carry an internal per-memory `version`: each batch is appended and `fsync`ed before only matching `(id, version)` rows are acknowledged, so a concurrent new write remains pending. Compact/Full Sync use durable atomic replacement. Startup first syncs pending outbox rows and then performs an exact SQLite/JSONL health check; scheduled checks run every 24 hours by default, with drift/error retried after one hour and recorded in stats/audit without automatic repair. A background compact check runs at most once per 24 hours, while live Stats always verifies on-disk IDs and corrupt lines instead of treating `pending=0` as sufficient health.
- **`app/service.py`** — Explicit `MemoryService(settings, storage, embedding_provider)` instance; no global storage/provider or import workers. Business layer: memory CRUD/search, storage bootstrap, JSONL exports, and one-at-a-time background JSONL imports coordinated by `ImportCoordinator`. `wait_import(import_id)` blocks on the job's completion event and returns its final status (cleanup already done); `close()` drains every import worker. The service injects no provider-specific behavior: `embed`/`embed_query`/`embed_documents` delegate to the wrapped `embedding_provider`, and it calls the declared `MemoryStorage` surface directly (no `hasattr`/`DualStorage` probing); Full Export and Sync rely on `export_full_snapshot`/`force_sync`, whose default raises `StorageCapabilityError`. Runtime storage is strictly `sqlite` or `dual`; JSON array storage was removed, and NDJSON cannot run as a business backend. Import preserves/prefixes namespaces, regenerates memory and index-value embeddings with the target active profile, commits atomically, and preserves missing summaries as null. Namespace governance is centralized here (`known_namespaces()` / `check_namespace()`, shared by MCP and the admin API).
- **`app/domain/lexical.py`** — Minimal shared query builder for the lexical (FTS5/BM25) retrieval primitive: the single `LEXICAL_INDEX_VERSION`, query limits (4096 chars / 256 tokens) and safe MATCH construction (every term quoted and OR-combined; zero-token input returns an empty result). Tokenization here only decides which substrings count as searchable tokens for validation/limits; SQLite `unicode61` performs the matching, so CamelCase and CJK are never hand-split.
- **`app/domain/summary_policy.py`** — Model-free summary fallback. Caller summaries win; ordinary add/text-update writes derive a deterministic leading sentence/line when absent, while whitespace-equivalent or metadata-only updates preserve the old summary. Import/recovery retain null summaries, and LLM-facing search/list responses derive the same display fallback dynamically. Exception: the Admin HTTP PUT treats an explicit blank `summary` (`""`/whitespace) as an intentional clear via the internal keyword-only `clear_summary` flag, storing null even when the body also changes; MCP/Add/import/recovery and `null`/omitted keeps the existing derive/preserve policy.
- **`app/domain/anchors.py`** — Retrieval anchors (`metadata.anchors`, max 5, order preserved, case preserved). `normalize_anchors` is strict for caller input (NFKC, whitespace collapse, ASCII case-insensitive dedupe, exact non-ASCII dedupe, ≥128-char/empty/non-string/over-5 all rejected rather than dropped) and is called before embedding or storage work; `clean_anchors` is lenient for indexing/rebuild/import. Anchors are identity signals (names, classes, APIs, errors, config keys, versions), never generated by the server.
- **`app/domain/categories.py`** — Category dimension (`metadata.categories`, max 3 per memory): 20-seed canonical vocabulary (`CATEGORY_VOCABULARY`), normalization/cap helpers, and `category_counts_with_seeds` (stats always lists the seed vocabulary, count 0 when unused). Categories are a separate dimension from keywords — keywords = content concepts, categories = memory nature/classification. SQLite stores both dimensions in generic `index_values(dimension, value)` / `memory_index_values(memory_id, index_value_id)` tables and manages them through shared sync/rebuild/count/filter paths; startup migrates and drops the legacy per-dimension tables by rebuilding from authoritative `memories.metadata`. A third `anchors` dimension reuses the same relation tables but is registered with `requires_embedding=False`: it is excluded (in both Python and SQL) from index-value embedding storage, completeness checks, missing/backfill, profile reindex and semantic resolution. NDJSON carries metadata for recovery.
- **`app/domain/namespace_policy.py`** — Namespace governance. Format/type failures use `InvalidNamespace(ValueError)`; admin memory list/add/update/search distinguish these (`invalid_namespace`, HTTP 400) from request parsing errors (`invalid_request`, HTTP 400) and internal failures (HTTP 500). A namespace is just a record attribute; the known set is derived dynamically from live records (`SQLiteStorage.list_namespaces()`), plus `MEMORY_DEFAULT_NAMESPACE`, which is always valid so a fresh database can bootstrap. Names are trim-normalized, case-sensitive, Unicode-friendly, ≤64 chars and cannot be reserved words (`all`/`*`/`none`/`null`). Unknown namespaces raise `NamespaceNotFound` unless the caller passes `confirm_codes` containing the matching rule name (`namespace_not_found`); a code only bypasses its own rule and never format/length/reserved checks. No alias/registry/history-merge (tracked separately in the backlog).
- **`app/cli/category_migrate_deepseek.py`** — Offline backfill CLI for `metadata.categories` on existing memories (deepseek-v4-flash via `opencode run`, strictly serial, per-record resilience, `--dry-run` supported). No local-Ollama/qwen path by design.
- **`app/cli/keyword_migrate_deepseek.py`** — Explicit offline backfill CLI for `metadata.keywords` using deepseek-v4-flash via `opencode run`; it is not exposed through MCP or the admin UI. Normal writes rely on caller-provided `metadata.keywords`; omitted values remain absent. Shares storage assembly, opencode invocation, output parsing and cleanup via `app/cli/deepseek_cli.py`.
- **`app/cli/anchor_migrate_deepseek.py`** — Offline `draft`/`apply` anchor backfill (deepseek-v4-flash, batched, manifest-based); `draft` is read-only, `apply` writes one complete manifest in a single transaction and requires the service stopped. Shares `app/cli/deepseek_cli.py` helpers.
- **`app/cli/deepseek_cli.py`** — Shared helpers for the three offline DeepSeek backfills: `build_cli_storage` resolves the primary from `--db`/`MEMORY_STORAGE_PATH`, else the resolved data root (`MEMORY_DATA_DIR`, relative to PROJECT_ROOT, or the per-user data directory) via the side-effect-free `configuration.resolve_data_dir()`; read-only/dry-run stays SQLite-only with no writer lock or replica worker. Also provides `run_opencode`, `extract_json_array` (ANSI/fence tolerant), `format_candidates_block` and `stop_storage`; the per-CLI function facades delegate here.
- **`app/storage/base.py`** — Storage contracts. `MemoryStorage` is the full business surface every backend must implement: CRUD/search, index-value queries (`keyword_counts`/`exact_index_values`/`semantic_index_values`/`missing_index_value_embeddings`/`index_embedding_completeness`/`backfill_missing_index_value_embeddings`), `update_metadata`/`update_anchors_batch`, `rebuild_*`/`get_keyword_vocabulary`, `active_embedding_profile` (cheap, never scans a replica), `live_memory_ids` (ids only, never loads text/metadata), `storage_paths` and `stop`. `force_sync`/`export_full_snapshot` are concrete and default to raising `StorageCapabilityError`; only `DualStorage` overrides them. `SQLitePrimaryStorage(MemoryStorage)` is the narrow primary interface for outbox (`count_unsynced`/`get_unsynced_records`/`mark_synced_versions`/`mark_synced_batch`), connection swap (`close_connection`/`reopen_connection`) and embedding-profile maintenance; `ReplicaStorage` declares the replica lock lifecycle (`acquire_writer_lock`/`release_writer_lock`) but never the primary capabilities. Incomplete doubles fail at construction.
- **`app/storage/sqlite.py`** — SQLite primary plus versioned embedding profiles. Factory-created writable stores hold the process-lifetime primary writer lock and release it on `stop`/`close`; direct low-level instances opt in explicitly for tests/internal work. Dense memory-text vectors live in `memory_embeddings(memory_id, profile_id, embedding)` and keyword/category vectors in `index_value_embeddings(index_value_id, profile_id, embedding)`; both share one active profile and codec lifecycle. The first startup migrates legacy inline pickle vectors into the active profile. New BLOBs use the portable `RMEV` codec and float16 by default. Reindex builds both vector sets in a shadow profile and switches it atomically; retained profiles support rollback only when both sets are complete. The derived FTS indexes `memory_content_fts` and `memory_anchor_fts` (fts5/unicode61) are kept in sync inside the same transaction as each authoritative write (`add`/`update`/`update_metadata`/`delete`/`clear`/`import_records`/`_add_with_id`); each table's pre-existing presence is checked **before** creation, so dropping a table cannot leave an empty index hidden behind a still-valid version marker. A missing table, a missing `storage_state.lexical_index_version` or a version mismatch triggers a full rebuild of both indexes before the service enters `running`; that rebuild also backfills the derived `anchors` relation dimension from metadata (so anchor search and `anchor_total`/`memories_with_anchors` cannot disagree after an upgrade), and a rebuild failure fails startup. `search_lexical` matches memory **content only** and `search_anchor` matches **anchors only**; both accept the shared exact candidate filters (`categories`/`keywords`, OR within a dimension and AND across dimensions, no semantic resolution), strict `updated_after`/`updated_before` bounds and a non-negative `min_score` floor applied before Top-K (ties by memory id ascending), and both return the raw unrounded `score = -raw_bm25` with a `match_info` block; read-only instances skip `_init_db` and never rebuild. The NDJSON disaster-recovery replica deliberately stores no embeddings.
- **`app/storage/ndjson.py`** — `NDJSONReplica` implements the narrow `ReplicaStorage` contract only: vector-free durable batch append/tombstone, fsynced atomic snapshot replacement, compact/stats, and recovery reads. Internal SQLite sync bookkeeping (`synced`, `version`) never enters the portable JSONL format. It does not implement business CRUD/search/import.
- **`app/embedding/index_value_resolver.py`** — Exact-first semantic resolver shared by keywords/categories. Unmatched values use query embeddings against same-dimension document embeddings, restricted to values used by live memories in the requested namespace. Adaptive Top-k applies an absolute score floor and maximum gap from the best match; resolved exact values constrain the existing SQLite candidate filter and never alter memory-text cosine scores.
- **`app/embedding/embedding_codec.py`** — Versioned float16/float32 dense-vector BLOB codec with read compatibility for trusted legacy pickle data.
- **`app/embedding/embed.py`** — Provider abstraction with distinct document/query paths. Ollama remains the default; FastEmbed 0.8 is optional and performs local ONNX inference, cache/offline validation, batching, normalization, dimension checks and input-length checks.
- **`app/cli/embedding_cli.py`** — Offline embedding administration: `status`, `migrate-codec`, `download-model`, `reindex`, `reindex-index-values`, and `activate`. `status` is read-only; mutations take the shared SQLite-primary writer lock and therefore refuse to run while the service owns that database. `reindex-index-values` backfills keyword/category vectors for the active or a specified matching profile; full reindex builds both memory-text and index-value vectors. Reindex is intentionally not an MCP tool.
- Embeddings use **cosine similarity** (via numpy) for search scoring.
- **`app/storage/jsonl_transfer.py`** — Strict shared JSONL reader/validator for Import and Recovery, clean snapshot writer, tolerant integrity inspection, hashing, safe filenames, and temporary-file cleanup. Historical append-only records/tombstones resolve by timestamp and file order; transfer JSONL never carries embeddings.
- **`app/transport/admin.py`** — Web UI (admin console) routes under `/admin/console` and `/api/*` (incl. `/api/audit`). Blocking store/audit/export work runs on the runtime's `AsyncCallAdapter`; config/model reads and writes use its control pool. Ops actions require runtime maintenance mode and run one at a time; `/api/import` reserves the import action and delegates start/completion to `Runtime.start_maintenance_import()`, so Admin no longer polls job status, joins workers or touches Service/Runtime private members. The mutating memory routes (`POST /api/memories`, `PUT`/`DELETE /api/memories/{id}`) defer admission to the worker so queued writes are re-checked after maintenance entered, while reads and in-memory routes are gated by `_guard`; `/api/sync` calls `Runtime.maintenance_sync()` and `/api/recover/{id}` reads `Runtime.recover_status()`. MCP/Web ordinary memory writes return `maintenance_mode` while reads continue. `POST /api/recover` accepts uploaded JSONL and rebuilds the current primary online; database switching briefly pauses reads, then dual mode full-syncs the replica. The standalone `app.recover_cli` still requires shutdown. Frontend is `web/index.html` (structure) plus `web/static/app.css` and `web/static/js/*.js` ES modules, served through `GET /admin/console/static/{asset:path}` (path-contained under `web/static/`, extension whitelist, `no-store`); `web/static/js/main.js` is the single entry and the assembly point for cross-page navigation callbacks; `layout.js` owns the desktop shell (sidebar collapse + persistence); production exposes no test hooks (the browser regression injects a fetch-boundary harness only in tests). Unknown namespaces on add/update/search/list use HTTP 400 with the same `response_code`/`response_meta` envelope as MCP. Routes are declared in `AdminAPI.ROUTE_TABLE` with an explicit `static`/`asset`/`read`/`write`/`action`/`control`/`exempt` policy (no separate action/exempt sets or method-set inference). Standard handlers map domain exceptions through the shared `json_response`/`error_response`/`domain_error_response`/`internal_error_response` and `_maps_domain_errors`; import/export/recover/keywords/config keep their own cleanup and audit, and lexical/anchor share `_terms_search`. See `docs/project-management/plans/42-runtime-maintenance-mode.md`.

- **Memories workspace** — Browse uses `GET /api/memories/page` (read policy, registered before the memory-ID route), returning `{items, total}` from one SQLite read snapshot; the original list endpoint retains its array response. `MemoryService.memory_list_page` validates scope, page size, offsets and timestamp filters; `MemoryStorage.list_memories_page` is implemented by SQLite and delegated by DualStorage. `memories.js` assembles the workspace, `memories-data.js` owns local state/request versions, and `memories-list.js` renders rows/pagination and calls injected detail actions. Search now shares this workspace; `memories-search.js` owns search/advanced controls and drafts, while data owns submitted queries and a locally paged Top-K collection. The old Search page/module is removed. POST /api/memories/search retains arrays by default and returns `{items, filter_resolution}` only with boolean `include_resolution: true`. See `docs/project-management/plans/50.5.2-memories-browse-list.md` and `50.5.4-memories-unified-search.md`.
- **Memories common filters** — `memories-filters.js` owns Namespace/Categories/Keywords controls and the transient literal keyword candidate query; applied filters remain in `memories-data.js`, candidate data/status in `store.js`. Stats publishes category candidate `idle/loading/ready/error` state. Suggestions use `POST /api/keywords/query` with page size 20, 250ms debounce, and Namespace/selected Categories context. Filter the paged browse API using repeated `categories` and `keywords` parameters. See `docs/project-management/plans/50.5.3-memories-common-filters.md`.

## Conventions

- Tests live in `tests/` and run with `python -m pytest`. Pytest overrides inherited storage/provider settings, uses an in-memory SQLite primary and temporary audit files, and disables embedding preload; tests needing other settings must override them explicitly. Browser regression: `.venv/bin/python tests/run_admin_browser.py` (requires google-chrome; isolated in-memory service and fake vectors). No linter/formatter/typecheck config. Python stdlib style.
- New SQLite embeddings use the versioned RMEV float16 codec. Legacy pickle BLOBs remain read-compatible and are migrated transactionally into the first active profile.
- Update merges metadata (shallow merge, new keys overwrite old).
- Namespace governance: a namespace must already exist as a live record before it can be written to or queried, except the configured `MEMORY_DEFAULT_NAMESPACE`, which is always known and permits the first write in a fresh database. Names are trim-normalized, case-sensitive, Unicode-friendly, ≤64 chars, and reserved words (`all`/`*`/`none`/`null`) are rejected. A confirmation code only bypasses its own existence rule — never format/length/reserved or embedding validation. An omitted namespace on `search` means all namespaces; an omitted namespace on `update` leaves the existing namespace unchanged.
- `clear` without namespace deletes everything. `clear` with namespace deletes only that namespace.
- The docker-compose.yml uses external images (`mem0/openmemory-mcp`, `mem0/openmemory-ui`) — unrelated to this local code.
- **Whenever adding or modifying an MCP tool, audit must be considered.** Checklist: ① add its definition in `app/transport/tool_definitions.py`; ② add a `ToolSpec` entry (handler, read/write, search, namespace mode, hint) in `app/transport/tools.py`; ③ declare its audit policy in `app/audit.py` `AUDIT_EVENTS` + `PARAM_POLICIES`/`RESULT_POLICIES`; ④ keep tool description and hint consistent; ⑤ update the tool list in `app/read_me.md` so the `/read-me` guide stays accurate. Do not add a tool that is invisible to the audit journal.

## Internationalization (i18n)

Admin UI supports `zh-CN` (default) and `en`, driven solely by `config.language` and applied after a page refresh (no restart). `app/transport/ui_i18n.py` translates the fixed `web/index.html` template via explicit `data-i18n`/`data-i18n-placeholder`/`data-i18n-title`/`data-i18n-aria-label` markers, sets `<html lang>`, and injects the catalog as a non-executing `<script type="application/json" id="i18n-catalog">` node. Resources live in `web/static/locales/<locale>.json` with stable semantic keys; both catalogs must keep identical key sets and placeholders. Frontend modules call `t(key, params)` from `web/static/js/i18n.js`; runtime missing keys fall back to Chinese, but tests treat a missing key as failure. User content, protocol fields, tool names and machine payloads are never translated. `tests/test_ui_i18n.py` enforces catalog parity and that every marked key exists in both catalogs. Browser regression runs the whole matrix once per language (`tests/run_admin_browser.py`), or a single language with `--lang zh-CN|en`; `tests/browser/smoke_harness.js` exposes `t()` so one regression script asserts correctly in both languages. See `docs/project-management/plans/50.15-chinese-english-i18n.md`.
