ABOUT REMEMBER ME

记忆，是你最重要的财产。

记忆是智力的基石。我们凭借记忆理解来路、形成判断，让经历沉淀为智慧。当 AI 让知识与智能日益触手可及，你独有的经历、体验与记忆，便是你最重要的资产。

Remember Me 为你保存这份积累。每一条记忆都清晰可见，可以查看、修改，也可以导出、带走。你决定留下什么，也决定交给谁使用。

昨天是 Codex，今天是 Claude Code，明天或许是 DeepSeek Harness。工具可以随时更换，你的积累与记忆，始终属于你。

Help / 连接你的 AI

连接你的 AI

推荐让 Remember Me 独立运行，供多个 AI 助手共享记忆。

  1. 点击“复制地址”，发给 Codex、Claude Code 或 OpenCode 等支持 MCP 的 AI 助手，请它阅读说明并连接 Remember Me。
  2. 按 AI 提示确认配置；需要时重新打开会话。
  3. 问它：“请读取 Remember Me 的记忆数量。”返回实际数量就表示连通，0 也正常。
/read-me

/read-me 是接入说明，不是 MCP 连接端点。请让 AI 按说明选择适合它的连接方式。127.0.0.1 和 localhost 只适用于同一台机器；另一台电脑、容器或云端的 AI 需要它能访问的地址。

完整接入请求与详细说明 
请读取当前服务的 /read-me，按其中的接入指引选择当前 AI 工具支持的连接方式，帮我连接已独立运行的 Remember Me，保留已有配置，避免重复连接。需要我操作时，逐步告诉我怎么做；完成后读取记忆数量验证。若不支持或连接失败，请说明原因。
打开 Agent 接入说明
连接不上怎么办？

AI 读不了网页：打开接入说明，把内容复制给它。AI 在云端或另一台电脑：请安装者提供它能访问的地址。页面显示“模型未就绪”：先到配置页完成准备。普通聊天工具未必支持 MCP。

需要自己启动服务？

安装完成后，在 Remember Me 程序文件夹的终端执行 bin/start.sh，保持运行。推荐独立服务，方便多个助手共享；stdio 适合单客户端。同一份记忆已有服务运行时，不要再启动 stdio 进程。

Help / 给记忆起个分组名

给记忆起个分组名

Namespace 就是分组名。为当前工作取一个名字，例如“网站改版”，填入下一步的记忆规则。

同一项目换 AI，沿用同一个名字；不同项目，用不同名字。首次使用新名字时，按 AI 提示确认。

例如：Codex 和 OpenCode 都使用“网站改版”，就能围绕同一分组检索和保存项目记忆。

分组用于整理记忆，不是访问权限隔离。

Help / 让 AI 记住使用规则

让 AI 记住使用规则

连接成功说明 AI 已能访问记忆。把使用规则保存为当前项目会持续加载的长期指令，才能引导它在日常工作中检索、保存和更新；只在当前聊天中发送一次，不等于长期保存。

  1. 在 AI 中打开你的工作项目。
  2. 点击“复制保存请求”，粘贴到聊天框，把 <项目 Namespace> 换成分组名，再发送。
  3. 按 AI 提示重新打开项目会话，问：“我的记忆分组叫什么？请查一下里面的记忆。”
查看保存请求 
请把下面的记忆规则保存为当前工作项目的长期指令。找到当前 AI 工具会加载的指令文件，没有就创建；保留原文，合并重复规则。分组名未填写时先问我，不要设为所有项目的默认值。完成后告诉我文件完整路径和生效步骤；无法保存时，说明原因并给出手动操作方法。

查看或单独复制记忆规则 
使用 Remember Me 管理项目长期记忆。Namespace：<项目 Namespace>。未指定 Namespace 时先询问，不擅自设置跨项目默认值。

1. 主动回忆：在理解问题、分析方案和执行任务时，自然联想相关记忆；信息不足时，尝试不同线索继续检索，必要时读取全文。找到足够依据或继续检索已无明显价值时停止，不编造历史信息。
2. 复用经验：需要探索环境、寻找操作方法或反复尝试前，先回忆是否存在已有做法，核实后优先复用。下一步方法明确可靠时无需机械检索。
3. 决策与行动：重要决策前回忆历史经验、既有约束和失败教训；执行提交、部署、删除等关键操作前，检查相关的长期行为规则（如 action-rule），即使操作方法已经明确。
4. 主动积累：用户明确要求记住或长期沿用的信息应及时保存。工作中发现重要决策、经验、解决方案或可复用知识时主动保存；阶段结束或上下文压缩前检查是否遗漏。单纯要求总结不等于要求持久保存。
5. 提炼知识：以独立知识点组织记忆，保存有价值的事件、知识和抽象原则，必要时引用相关记忆 ID。区分事实、推测和待验证结论，注明依据与适用范围，避免过度泛化。自行归纳的长期行为规则须经用户确认后保存。
6. 去重与演进：写入前检索已有记忆，判断新增、更新或跳过。保留有独立价值的事件，合并重复知识，持续完善已有原则；修正过时或错误结论时保留必要的原因与证据。
7. 组织与反馈：保存、检索时使用本项目 Namespace，不擅自跨项目混写。合理填写 Categories、Keywords 和 Anchors，优先复用合适的现有分类。实际使用或评估检索结果后，通过 report 如实评价有用程度；无法判断时不强求评分。
8. 事实与安全：以当前事实和用户明确指令为准，核实记忆的适用性，遇到重要冲突时说明。不保存密码、密钥或无关隐私；删除、清空或覆盖记忆前取得明确授权。工具失败时如实说明，不声称未完成的操作已经成功。

查看与修正

在 Memories 浏览或筛选记忆，点击一条记录，在详情抽屉中查看全文、编辑修正，或通过 More 菜单复制和删除。

组织与筛选

Namespace · 所属空间
用于区分项目或用途。选择已有空间，或在新建/编辑时填写新名称并在保存时确认创建；All 表示浏览全部空间。
Categories · 记忆性质
说明这条记忆属于什么类型，例如需求、设计或问题修复，每条最多 3 项。
Keywords · 内容概念
说明记忆涉及哪些主题。优先选择含义合适的已有词，避免仅因拼写不同而重复创建。
Anchors · 具体标识
填写内容中有辨识度的名称、接口、错误码或版本号，每条最多 5 项。保留原拼写，便于以后定位。

同一类筛选中选中多个值时，匹配其中任意一个即可；不同类筛选需要同时满足。日期筛选依据记忆的更新时间，并同时作用于浏览和搜索。

Help / 检索 · Retrieval

检索 · Retrieval

找回你想要的记忆。

Semantic · 按意思找
例如“网站改版为什么选择暖色？”用自然语言描述想找的内容，适合概念问题或记不清原文时使用，也适合中文检索。
Lexical · 按正文词语找
例如搜索正文中的 HomePage-v2。适合英文名称、错误码或代码标识符。连续中文的匹配有限，中文问题优先使用 Semantic。
Anchor · 按标识找
例如搜索已填入 Anchors 的“首页方案 B”。仅搜索记忆中填写的具体标识。正文里出现但未填写为 Anchor 的内容不会被此模式命中。

输入内容后点击 Search 或按 Enter。Advanced 可调整返回数量和分数门槛；不同搜索模式的分数不能直接比较。Clear search 清除搜索内容并回到浏览，已有筛选仍然保留。

没有结果时，先检查筛选范围和日期，再尝试减少条件或更换搜索模式。

Web 检索供你手动查找；AI 的检索由它实际调用的工具和使用规则决定。

Help / 统计 · Stats

统计 · Stats

看看记忆积累了什么，检索又带来了什么。

Stats 提供 Memory 与 LLM Retrieval 两种视图，帮助你了解积累与使用情况。无需为了使用记忆而持续关注这些数字。

记忆积累 AI 检索

记忆积累 · Memory

Overview 显示记忆数（Memories）、分组数（Namespaces），以及分类、关键词、标识的不同值数量。Namespace Distribution 展示记忆在各分组的分布。

Top N · 排名
查看分类、关键词和标识中使用较多的值；点击项目可查看对应记忆，点击分组可按该分组查看记忆。
Unique Count · 不同值数量
有多少种不同的分类、关键词或标识，不是有多少条记忆。
Coverage · 填写比例
有多少比例的记忆至少填写了这一类字段。例如 10 条记忆中有 8 条带关键词，关键词覆盖率就是 80%。

AI 检索 · LLM Retrieval

可按 Namespace 和最近 7 / 30 / 90 Days 查看检索活动；当天可能还没结束，数据只覆盖已发生的活动。

Searches / Search Activity
检索调用次数及其随时间的变化，包含成功与失败的调用。
Search Modes
Semantic、Anchor、Lexical、Meta 四类检索的使用分布。
Rated Searches · 已获评分的检索
至少有一项有效评分的检索次数；同一次检索中多条结果获评分，仍算一次。
Feedback Coverage · 反馈覆盖率
已获评分的检索，占有结果的检索的比例。它不是检索准确率；没有可计算的检索时显示 —。
Average Rating · 平均评分
对有效的结果评分取平均，范围为 −10 至 +10。一次检索可以有多项结果评分；这个平均数不代表所有检索结果的质量。没有评分时显示 —。
Positive / Neutral / Negative
有效评分中，大于 0 为正向，等于 0 为中性，小于 0 为负向。

日常设置 · Settings

Appearance · 外观
浅色与深色主题立即生效，无需保存。
HTTP Port · 端口
保存后重启生效；如果启动时指定了 --port，该次启动优先使用指定值。
Language · 语言
当前只保存偏好，尚未应用到界面翻译。
Localhost Only · 仅本机服务
默认仅服务所在机器可访问。取消后保存并重启，才会开放局域网访问。服务没有账号密码，只应在可信网络中开放。
Debug Mode
显示 Debug、Audit 和诊断入口；保存后刷新页面生效，无需重启。检查页面元素还需点击 Debug，不改变日志或 MCP 工具。
Auto-download · 自动下载
决定下一次模型准备时是否允许下载缺失的模型。已有缓存仍可使用；关闭自动下载不等于可以跳过模型准备。
HTTP/HTTPS Proxy · 代理
保存后供后续模型准备和下载使用，可重试而无需重启。关闭时直接连接，同时保留已存地址；地址不回填以保护凭据，输入留空保留已存地址。

配置保存不要求进入维护模式。除主题外，修改后点击“保存配置”，并按页面提示刷新、重启或重试模型准备。

维护工具 · Maintenance

打开这个页签不会自动进入维护模式。执行需要维护的操作前，手动进入；完成且状态允许时，手动退出。

Model Management · 模型准备
查看准备进度、错误原因并重试。模型未就绪时先完成加载与验证；准备成功后仍需手动退出维护。
Data Transfer · 导入与导出
Import JSONL 导入新记录，可加分组前缀。Export JSONL 下载完整备份或指定分组的快照，便于保存与带走自己的记忆。完整备份需要服务支持灾备同步。
Data Management · 数据管理
Sync Backup 将主库完整同步至灾备 JSONL；Migrate Namespace 移动指定分组中的全部记忆。同步能力取决于服务的存储配置。
Server · 服务控制
Restart 重启并读取保存的配置；Shut Down 关闭服务，之后需要在终端重新启动。

维护期间普通新增、编辑和删除暂停。模型已就绪时仍可浏览、检索和查看详情；模型未就绪时记忆访问受限，恢复切换期间也可能短暂不可用。

危险操作 · Danger Zone

JSONL Recover 从备份覆盖当前数据库的全部记忆，与导入新记录的 Import 不同。Clear Memories 删除全部或指定分组的记忆。

操作不可撤销。先保存备份、核对范围，再按配置页要求输入随机确认码。Help 只提供说明，不执行这些操作。

连接与设置

AI 无法打开 /read-me？

确认服务运行中，且 AI 能访问页面地址。127.0.0.1 / localhost 指向访问者自身，另一台机器、容器或云端 AI 可能无法使用它。如 AI 不能读网页，可打开说明并手动复制给它。

服务怎么启动？

安装完成后，在 Remember Me 程序目录执行 bin/start.sh，保持运行。同一数据库已有 HTTP 服务时，不要再启动 stdio 写入实例。

记忆与检索

为什么保存按钮不可用？

配置保存需要有实际改动且输入有效。记忆保存还需要正文等必填项有效，并且服务允许写入。查看表单提示及顶部服务状态。

为什么搜索不到记忆？

先检查分组、日期和其他筛选，再减少条件或切换模式。Anchor 只查已填写的标识；中文或概念问题优先使用 Semantic。

模型未就绪怎么办？

服务尚未完成模型加载与验证，记忆访问暂不可用。到配置 → Maintenance → Model Management 查看准备状态，完成准备后手动退出维护。

服务与配置

模型下载失败怎么办？

检查网络、代理、自动下载选项及模型状态。在配置 → Maintenance → Model Management 查看错误并重试；仍失败时，按提示检查网络、磁盘或模型初始化问题。关闭自动下载不会免除模型准备；Ollama 模型需由安装者在 Ollama 中准备。

为什么看不到 Audit 或 Debug？

这些入口仅在配置中启用 Debug 并保存、刷新页面后显示。普通使用不需要开启 Debug。

代理地址为什么没有显示出来？

已保存的代理地址不会回填，以保护凭据。输入留空会保留已保存地址；关闭代理后地址也会保留。

为什么另一台设备打不开管理页面？

默认“仅本机服务”只允许在服务所在机器访问。需要局域网访问时，在 Settings 取消此选项并确认、保存、重启，再使用服务机器的局域网地址访问。管理页面没有账号密码，仅在可信网络中开放。

顶部显示“状态不可用”怎么办？

检查服务是否仍在运行，以及当前地址和端口是否正确。重启时稍等片刻；关闭服务后从终端启动。状态恢复前，执行控件会保持禁用。
