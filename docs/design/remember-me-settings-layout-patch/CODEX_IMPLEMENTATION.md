# Codex 实施与验收计划 — 仅 Settings 布局

## 前置要求

执行之前先只读检查当前 Configuration / Settings 的模板、样式和交互绑定，确认哪些容器负责 Settings 卡片左右分栏。先给出拟修改文件清单与简短方案；不要自行改动后端或跨越本补丁范围。

## Phase 1 — 局部布局调整

1. 保留已有 Appearance 和 Service Configuration 控件节点、字段名、事件绑定及帮助说明。
2. 仅替换 Settings 卡片内部的布局容器或对应 CSS class：标题区上移、内容区全宽。
3. Service Configuration：HTTP 端口和语言使用响应式两列，其他开关纵向排列，保存操作靠右。
4. 如需添加布局 class，尽量使用 Settings 范围内的 class，避免影响共享卡片与 Maintenance。

## Phase 2 — 视觉微调

1. 对齐两张卡片的标题、图标、说明和内容区的垂直节奏。
2. 控件及文字保持与现有全站设计系统一致；开关行分割线轻量，不造成过度密集。
3. Light / Dark 两种主题下对比度与边框色一致；禁止写死主题颜色。
4. 代理开启时的展开区域不破坏表单宽度和保存按钮位置。

## Phase 3 — 回归与验收

请验证：

- [ ] Settings 与 Maintenance Tab 可正常切换；Maintenance 的结构、内容和行为无变化。
- [ ] Appearance 标题位于顶部，主题控件位于其下方且即时生效。
- [ ] Service Configuration 标题位于顶部、表单占据下方全宽；没有左侧大面积空白。
- [ ] HTTP 端口与语言桌面双列、窄屏单列，无横向滚动。
- [ ] 仅本机、Debug、自动下载、代理这四项开关与原值、说明、验证、保存行为一致。
- [ ] 禁用仅本机服务时安全提示与保存确认仍然有效。
- [ ] 代理地址按需展开；原凭据不泄露、不被脱敏值意外覆盖；关闭再开启仍保留地址。
- [ ] 保存按钮修改后启用；成功反馈、错误反馈、待重启提示正常；不自动重启。
- [ ] Debug 不依赖 `--debug` 参数（如代码仍有支持，标注为现有功能差异，不在本次 UI 改动中擅自修改启动代码）。
- [ ] Light / Dark 两种主题截图一致；大屏、普通桌面和窄屏没有布局回归。
- [ ] Shell 顶部状态与导航无变化。

## 完成时输出

- 实际修改文件清单与改动概述。
- Light / Dark Settings 截图（如本地环境允许），以及窄屏检查结果。
- 测试/手工验收结果；若任何项目未验证，请明确标记。
- 如发现需要新增或调整 API、数据结构、启动参数或后端规则：**先报告并等待用户确认，不擅自修改**。
