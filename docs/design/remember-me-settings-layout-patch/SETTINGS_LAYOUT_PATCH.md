# Settings Tab 布局调整规范

## 1. 已确认的目标

将当前“卡片左侧固定标题/描述 + 右侧全部控件”的双栏结构，改为“卡片顶部标题/描述 + 下方全宽表单”的标准表单布局。

仅适用于 **Configuration → 常规设置（Settings）Tab**。Maintenance Tab 保持现状。

## 2. 布局约束

- 保持现有页面内容容器、两个 Tab、卡片外观、圆角、边框、间距系统；不可把 Settings 与 Maintenance 改为两种页面宽度。
- 两张 Settings 卡片均使用**顶部紧凑标题区、下方内容区**，不再给标题/说明保留固定比例的左侧列。
- Appearance 主题三选一，继续保留原有控件及浏览器 localStorage 行为；一行摆放有余量时可将标签和控件同行，窄屏自动换行。
- Service Configuration 中 HTTP 端口和语言在桌面尺寸为等宽双列；窄屏退化为单列，禁止横向溢出。
- 开关按“仅本机服务 → Debug → 自动下载 → HTTP/HTTPS 代理”纵向排列。每项的说明紧随开关文字；采用细分割线使行距一致。
- 代理输入区域仅在代理开关开启时显示；已保存密码/URL 不回填明文，也不回填脱敏 `***@` 字符串。禁用代理时保留后端保存的地址，不修改既有语义。
- 保存按钮位于 Service Configuration 卡片右下角；没有更改或校验不通过时沿用现有禁用规则。
- Light/Dark 均遵循现有主题变量，不用硬编码浅色背景、深色文字或危险色。
- 警告、错误、成功、待重启反馈保留原有行为及可见性，不因布局重构而隐藏。

## 3. 不变的业务行为

- 主题仅影响当前浏览器、立即生效、无需保存，遵循 `remember-me.theme.v1` 和系统主题偏好监听。
- HTTP 端口保持 1–65535 的整数验证；`--port` 启动参数优先，重启才会采用配置端口。
- 语言仅保存 `zh-CN` / `en`，当前不引入 i18n 翻译实现。
- `local_only` 取消时立即显示安全警告；从仅本机改为非本机并保存时仍需要明确的二次安全确认；保存后重启生效。
- Debug 只读取/保存持久化配置；默认 false，**不支持 `--debug` 启动参数**。保存后刷新页面生效，无需重启。
- 自动下载与代理配置作用于下次模型准备；模型未就绪时保存触发当前已有的重试机制。
- 配置保存无需进入维护模式；保存不自动重启；需要重启的更改给出待生效提示。
- 代理 URL 的合法性验证、凭据保留、防止脱敏回填等行为均不改变。

## 4. 明确禁止

- 不要修改 Maintenance Tab 的左右分栏、展开表单、Danger Zone 或卡片排序。
- 不要改变 Shell 顶部状态胶囊、侧边导航、全局头部、路由和 API。
- 不要新增 gRPC 端口、Storage Path、Logging 等此前生成示意图中误出现的配置项。
- 不要调整后端权限与安全保护，或修改其他页面。
- 不要为了视觉一致强迫 Maintenance 改成标准表单布局。

## 5. 响应式和可访问性

- 桌面：两张卡片同宽；字段双列；表单填充卡片可用宽度。
- 窄屏：HTTP 端口与语言单列；长说明自然换行；按钮不遮挡控件；页面不得水平溢出。
- 保持现有 label/checkbox 的点击区域、键盘操作、focus-visible 样式和错误提示关联。
