# Remember Me MCP — Memory List Card 精修实施说明

## 1. 目标与边界

以 `reference/current_full_page.png` 和 `reference/current_cards_closeup.png` 为**真实现状**，以 `reference/target_light_dark.png` 为**视觉方向参考**。在现有 Memory List 的卡片组件及样式上做局部精修，不重构页面。

**本次仅修改**：卡片的布局/间距、文本层级、Metadata 展示样式与溢出策略、边框/颜色、悬停和键盘聚焦表现，以及卡片点击热区（在保留既有行为的前提下）。Light/Dark 同步适配。

**禁止修改**：Shell、导航、顶部 Search / Filters / Advanced / Count / Sort、搜索模式（Semantic / Lexical / Anchor）、Detail Drawer 的内容和行为、后端 API、数据模型、记录排序、实际 Memory 文本和任何不相关组件。效果图里的顶部导航/搜索控件和示例文字不作为实施目标。不要引入新依赖或不必要的新组件。

## 2. 卡片结构（沿用现有）

每条 Memory 的视觉结构为：

1. 低权重文档图标（保留现有图标，不替换类型）与 Summary 在首行。
2. Content 位于 Summary 下方。
3. Metadata 位于 Content 下方，字段排列顺序固定为 Namespace → Categories → Keywords → Anchors。
4. 右侧箭头始终可见、垂直居中；更新时间在卡片右下角。

Summary、Content、Metadata 的**文字内容区域左边缘对齐**；文档图标占据独立的左侧小列，不使下面两行顶到图标下方。右侧为日期和箭头预留空间，避免长文遮挡。保持原文，不借效果图替换内容。

## 3. 排版与尺寸

| 元素 | 样式要求 |
|---|---|
| Summary | 14px / font-weight 600 / 主文字色；最多 2 行，超出省略 |
| Content | 13px / font-weight 400 / 次级文字色；最多 2 行，超出省略；提升现有截图中的文字对比度 |
| Metadata 字段名 | 12px / font-weight 400 / 辅助文字色 |
| Metadata 值 | 12px / font-weight 400 / 依字段使用对应样式 |
| 更新时间 | 12px / font-weight 400 / 辅助文字色；格式 YYYY-MM-DD（沿用既有数据源） |
| 文档图标 | 沿用现有 icon，建议 14–16px，低饱和蓝灰；顶部与 Summary 对齐，无背景框 |
| 卡片内边距 | 16px |
| Summary → Content | 8px |
| Content → Metadata | 12px |
| 卡片之间 | 8px |
| 卡片圆角 | 8px |

卡片高度**自适应**，不固定高度；长内容使用行数限制控制视觉高度。遇到较小屏幕应能正常响应，不出现横向溢出。

## 4. Metadata 规则

- **保留字段名**，使用当前界面的中文名称：`空间：`、`分类：`、`关键词：`、`锚点：`。
- Namespace 为普通文本（非 pill 标签），其值仍显示，例如 `remember-me`。
- Categories：低饱和淡蓝背景的标签。
- Keywords：中性浅灰背景的标签。
- Anchors：透明背景 + 浅灰细边框的标签。保留源值，不改变大小写或字符。
- 字段没有值时，**整组隐藏**，不显示 `—`。
- 字段间使用轻微间隔或细分隔符，避免过度密集。
- **按字段分组换行**：优先保持字段名与其第一个值在一起；组过长时允许组内内容流式换行。不能为防止换行而挤压/裁切文本。
- 整个 Metadata 显示区域**最多两行**；无法放下的标签用末尾**统一一个 `+N`** 表示，`N` 是实际未展示的标签个数（Categories + Keywords + Anchors 中被隐藏的标签，不包括字段名或 Namespace）。
- `+N` 需要与实际可见标签的边界一致：字体加载、容器 resize、不同语言内容均应正确统计。不允许仅按固定“显示前三个标签”等近似规则假装是两行。
- `+N` 点击打开该条 Memory 的既有 Detail；不新增面板。点击时避免重复触发卡片点击。
- `+N` 出现时须完整可见，不能自己被两行省略。若当前代码实现精确测量需要复杂逻辑，应先核对现有实现并选用可测试且维护成本合理的方法，不要为了 UI 引入沉重依赖。
- 除 `+N` 外，Categories / Keywords / Anchors **仅用于展示**，不提供点击筛选、模式切换、搜索跳转或其他新行为。

## 5. 色彩（Light）

以下为建议 token，优先复用项目中已存在的语义变量；若已有规范接近，避免定义冗余全局变量：

| 用途 | 建议 |
|---|---|
| 页面背景（仅参考，不在本次修改） | `#F7F8FA` |
| 卡片背景 | `#FFFFFF` |
| 卡片边框 | `#E5E7EB`（1px） |
| 主文字 | `#1F2937` |
| Content | `#596579` |
| 辅助文字 | `#8491A3`（注意实际小字号可读性） |
| 品牌强调参考 | `#2563EB` |

正常卡片**不加阴影**。Categories 的淡蓝色、Keywords 的中性灰色、Anchors 的浅边框必须低饱和、克制；不要额外新增多组显眼颜色。

**Dark**：采用对应语义层级的深色背景、边框与文字色，而不是对 Light 值做机械反色；确保正文、字段名、标签、日期和 Focus 状态可读。不得直接将效果图中的颜色当作逐像素验收标准。

## 6. 卡片交互

- 整张卡片可点击，打开与当前右侧箭头相同的 Detail 页面/抽屉；保持项目现有路由和打开逻辑。
- 保留右侧箭头，始终可见、垂直居中，建议使用现有组件。
- Hover：卡片背景不变；边框轻微变成蓝灰色，增加**极轻微**阴影。不得使用上浮、缩放等运动效果。
- 鼠标：可点击卡片显示 pointer。
- Keyboard：卡片可通过 Tab 聚焦，通过 Enter（必要时 Space）打开，显示清晰可见且不被裁切的 Focus Ring。注意避免在同一张卡片里产生重复且无意义的 Tab 停靠点。
- 纯展示标签不显示 pointer。`+N` 如果可以点击，必须具备可访问名称与键盘操作。
- 已有卡片内部其他可操作元素时，不可因扩大热区而覆盖其原有点击行为。

## 7. 更新日期

卡片右下角显示 `YYYY-MM-DD`；数据来源沿用既有“更新时间”字段。保留原有时区/日期语义，不要通过简单字符串切片造成跨日偏差。完整时间仍由原有 Detail 展示（本次不修改 Detail）。

## 8. 实施步骤

1. 在项目中定位 Memory List 的卡片渲染模板、Metadata 标签生成逻辑、日期格式化和相关主题样式；先阅读现有规则，避免破坏既有交互。
2. 局部调整卡片结构布局，保留现有文档图标、内容和详情入口。
3. 落实排版、间距、边框、标签样式；适配 Light/Dark。
4. 落实按字段分组的两行 Metadata、准确 `+N` 计数，以及窗口 resize 后行为。
5. 落实整卡点击、Hover、Focus 与键盘支持。
6. 运行现有测试，并用浏览器核对 Light/Dark、大屏/窄屏、长中文/英文、空字段、很多标签等情况。
