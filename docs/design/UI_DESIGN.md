# Remember Me UI 设计规范

本文定义 Remember Me 管理界面的视觉与布局规范。实施流程和阶段边界见同目录 `UI_IMPLEMENTATION_RULES.md`。

## 1. 目标与首阶段范围

产品面向开发者，用于管理 memory 和观察 retrieval。界面应传递：**专业、科技、内聚、精确、好用**。

首阶段实施 **Application Shell + Memory List（Memories 列表页）**，同时支持 Light / Dark / System。Search、Audit、Stats 等页面的专项重设计安排在后续阶段。

本次是现有界面的视觉重构。保留现有业务行为、API、字段、路由和功能；不根据效果图新增业务功能。Logo 暂不设计、不作为配色依据；现有标识可保留或使用简单文字品牌占位。

解释顺序：用户明确要求 → 实施规则 → 本文 → 参考图。现有业务功能与参考图冲突时，保留功能并应用其视觉语言。

## 3. 视觉方向

整体采用冷中性色、低饱和度、克制的蓝色强调。界面是一个连续的工作环境，主要通过间距、排版、细边框和轻微背景差异区分区域。

设计原则：**Color explains, not decorates.**

- 顶栏与侧栏安静，正文内容与操作清楚。
- 大部分区域使用 neutral tokens，蓝色主要表达交互与选中状态。
- 各区域共享同一套字体、间距、圆角和控件尺寸。
- 使用紧凑列表与表格；不把每条记录做成带强阴影的大卡片。
- 主要按钮易于识别，次要操作克制，但不能因低对比而难以发现。
- 避免大面积渐变、霓虹、玻璃效果、强阴影和大块高饱和背景。
- 图中可能存在的渐变或光晕不需要复刻；应用背景以稳定纯色为主。

内聚不意味着所有背景和文字使用相同颜色。区域层次应微妙，但操作、正文、选中与焦点必须清楚。

## 4. Application Shell

### 4.1 结构与尺寸

采用 **顶部通栏 + 可折叠左侧导航 + 右侧工作区**。

| 项目 | 基准值与规则 |
| --- | --- |
| 顶栏 | 单行约 52–56px；允许根据内容自动增高 |
| 侧栏展开 | 180px |
| 侧栏折叠 | 64px |
| 工作区内边距 | 默认 20px，狭窄窗口可降到 16px |
| 页面标题与工具栏间距 | 16–20px |
| 常规控件高度 | 32–36px |
| 导航项高度 | 32–36px |

使用现有技术栈实现。推荐 CSS Grid 管理外壳，顶栏为 `auto` 行，下方为 `minmax(0, 1fr)`；工作区设置 `min-width: 0` 和 `min-height: 0`，避免内容撑开视口。

桌面端顶栏、侧栏始终可见，主要纵向滚动发生在工作区。避免 body 与工作区同时纵向滚动。侧栏项目超过可用高度时，允许导航区域独立滚动以保持可访问。

右侧使用剩余宽度，不设置全局 `max-width: 1200px` 或居中外边距。表单和长文本可按可读性局部限制宽度，不能因此限制整个工作区。

### 4.2 顶栏

左侧放品牌名称与现有服务信息；右侧放现有全局状态、Refresh、Debug 等全局动作。页面级 Add、Filter、Sort 等动作放在页面内部。

状态必须来自真实数据。保留现有运行中、维护中、模型未就绪、状态不可用等语义，不能为了效果图显示虚假的 Ready。

状态使用文字配合小圆点或图标；完整说明可通过 tooltip、可聚焦提示或现有详情入口查看。

空间不足时，顶栏在自身容器内换行，Shell 自动适应高度，不能覆盖工作区。不要为复刻参考图新增账户、头像或登录功能。

### 4.3 侧栏

- 保留现有菜单名称、路由、权限与可访问功能，不在本轮重新设计信息架构。
- 使用统一线性 SVG 图标；优先复用现有图标方案，避免混用 emoji、实心图标和不同线宽。
- 选中项使用浅蓝/深蓝灰底色，配合蓝色图标、文字或窄标记；不使用整块亮蓝背景。
- 当前页、hover 与键盘 focus 要有不同表现。
- 默认展开，由用户手动折叠；不根据窗口宽度自动改变用户选择。
- 折叠状态保存到 `localStorage`；读取失败或不可用时使用内存状态。
- 折叠后保留图标、可访问名称、hover/focus 提示；当前页与键盘焦点仍清楚。
- 折叠侧栏时保留页面及表单状态。
- 若旧实现依赖导航 ID、`data-page` 或事件绑定，迁移时必须保持兼容。

窄窗口可以调整工作区排布、让工具栏换行，但不允许截断关键操作。桌面工具不要求本阶段改造成完整移动端产品。

### 4.4 页面框架

主要页面遵循 **Page Header → Toolbar / Filters → Content**。

标题左对齐，主操作通常位于右侧；描述文字简短且次要。工具栏与内容紧密连接，避免每层都包一张卡片。

页面切换时工作区回到顶部；同页筛选、分页、编辑返回等操作沿用现有行为，不统一强制滚动。

详情、编辑和确认弹窗不受列表滚动容器裁切；使用现有 overlay/portal 机制覆盖正确区域。没有永久右侧栏。

## 5. 主题与语义颜色

Light 与 Dark 使用同一组语义 token。组件不得直接散布主题 HEX 值，也不要用简单颜色反转实现暗色主题。

以下是**可实施的初始色板**，不是从图片精确取色得到的最终品牌规范。实现后通过浏览器截图与对比度检查微调，并统一修改 token。

| Token | Light | Dark | 用途 |
| --- | --- | --- | --- |
| `--bg-canvas` | `#F7F9FC` | `#0E161E` | 应用底色 |
| `--bg-shell` | `#F2F5F9` | `#111C25` | 顶栏与侧栏 |
| `--bg-surface` | `#FFFFFF` | `#16212B` | 输入、列表表面 |
| `--bg-elevated` | `#FFFFFF` | `#1D2B37` | 菜单、弹窗 |
| `--bg-hover` | `#EDF2F7` | `#1B2C39` | hover |
| `--bg-selected` | `#E7F1FC` | `#17364A` | 选中行与导航 |
| `--border-subtle` | `#E1E7EF` | `#293B49` | 非交互区域分隔 |
| `--border-control` | `#8795A6` | `#718597` | 必要控件轮廓 |
| `--text-primary` | `#182332` | `#E8EEF4` | 正文与标题 |
| `--text-secondary` | `#556579` | `#B0BFCC` | 次要信息 |
| `--text-muted` | `#64748B` | `#93A7B7` | 时间、元数据 |
| `--accent` | `#0969B7` | `#66BBFF` | 交互文字、图标、focus |
| `--accent-solid` | `#0969B7` | `#1379BC` | 主要按钮底色 |
| `--accent-solid-hover` | `#075A9D` | `#0E68A3` | 主要按钮 hover |
| `--on-accent` | `#FFFFFF` | `#FFFFFF` | 主要按钮文字 |
| `--accent-subtle` | `#E7F1FC` | `#17364A` | 轻量交互背景 |
| `--success` | `#18794E` | `#55D49A` | 成功、健康 |
| `--warning` | `#8A5A0A` | `#EABD64` | 警告 |
| `--danger` | `#B42332` | `#FF8791` | 错误、危险操作 |

`--border-subtle` 用于装饰性分隔，不应单独承担控件识别。控件通过轮廓、背景和标签保持清楚，需要明确轮廓时使用 `--border-control`。

根据实际需要添加 `--danger-subtle`、disabled、focus、retrieval 等语义 token；添加时同时定义两种主题。不为了凑色阶生成大量未使用 token。

状态色只表达状态，不能作为任意装饰。普通类型/profile 标签优先使用中性灰；类别色若保留，固定映射且低饱和。Semantic、FTS、Anchor 的专用色属于后续 Search 阶段，本阶段不把这些标签加入 Memory List。

### 5.1 主题行为

- 支持 `light`、`dark`、`system`；若无已保存设置，默认 `system`。
- 记住用户选择；`system` 跟随系统变化，手动选择不被系统覆盖。
- 刷新时尽量在首次绘制前应用主题，避免明暗闪烁。
- 覆盖原生输入、下拉、checkbox、滚动条和弹层，按需设置 `color-scheme`。
- 切换主题不能清空查询、筛选、选择或当前编辑状态。

## 6. 排版、间距与控件

| 项目 | 基准 |
| --- | --- |
| UI 字体 | 现有系统字体栈，包含中文 fallback；无需引入远程字体 |
| 页面标题 | 20–22px，600–700 |
| 正文、控件、列表标题 | 13–14px；正文行高约 1.5–1.6 |
| 时间和元数据 | 12px，不能为了密度继续缩小 |
| 间距 | 主要使用 4 / 8 / 12 / 16 / 20 / 24 / 32px |
| 控件圆角 | 6px |
| 面板、弹层圆角 | 8px，最大约 10px |
| 标签圆角 | 4–6px；真正的 chip 可使用 pill |
| 分隔线 | 1px |
| 阴影 | 仅浮层等需要表达覆盖关系的区域使用轻阴影 |

ID、代码和技术片段可用等宽字体；时间或数字可用 tabular numerals。不要把整个界面变成终端字体。

按钮需要 normal / hover / active / disabled / focus-visible 状态。主要操作为实色蓝按钮；次要操作为中性描边或轻量按钮；删除使用明确危险语义。每个局部操作区域只突出一个主操作。

输入框有明确标签或可访问名称，placeholder 不替代标签。Icon-only 按钮必须有可访问名称，tooltip 同时支持键盘 focus。

## 7. Memory List：首阶段的代表页面

### 7.1 布局与信息层级

采用参考图浅色 Memories 区域的**紧凑列表语言**。关闭详情时，列表使用完整工作区，不保留空白详情栏。

页面结构：

1. 标题 `Memories` 与简短描述；若现有功能支持 Add，则将既有添加入口放在页面级操作区。
2. 列表查询、现有筛选与排序工具栏。
3. 连续的 memory rows。
4. 现有分页或加载更多控件。

只有现有界面和数据支持的控件才进入实现。参考图中的 Profile、Type、Sort、checkbox 不意味着必须新增这些功能。

列表查询沿用现有匹配行为。不能将列表筛选擅自改为 semantic retrieval，也不能为了统一视觉改变后端搜索机制。

### 7.2 单行结构

| 层级 | 内容与规则 |
| --- | --- |
| 第一层 | 现有标题；若无标题字段，使用现有 summary 或展示规则，不新增数据库字段 |
| 第二层 | 简短摘要或内容预览，默认 1–2 行；保留现有可获取完整内容的入口 |
| 第三层 | 少量现有元数据，如 profile/type、更新时间；ID 为次要信息 |
| 操作 | 沿用现有打开详情、编辑、删除等入口；明确显示或提供可键盘访问的操作菜单 |
| 选择 | 仅在既有批量选择功能存在时显示 checkbox；选择状态与当前打开行状态不同 |

建议 row 纵向 padding 为 10–12px，文字层间距为 4–6px。高度随内容自然变化，不把所有记录拉成大卡片，也不为了固定高度裁掉按钮。

row hover 为轻背景；当前打开行使用选中底色和必要的细边框/标记。普通 row 通过细分隔或轻背景区分，不使用强阴影。

摘要负责浏览，完整内容通过现有入口查看。支持长中文、英文单词、代码、URL 和缺失元数据，避免超出列表宽度。

如果复用现有表格更适合保留行为，可使用紧凑表格实现上述层级；计划中说明与参考图列表表现的差异，不为外观替换整个数据层。

### 7.3 详情边界

参考图右侧详情区域是**按需打开**的效果参考，不是永久导航栏。

首阶段保留现有详情展示方式和功能，仅做 Shell 兼容、主题适配以及必要样式修复。将 modal/整页详情改为 drawer、新增 Detail/Edit/Related/Audit tabs、关联记忆或详情专属功能，都属于后续独立决策，不能自动实施。

若现有系统已经使用 drawer，继续按需打开；关闭后恢复列表可用空间。窄窗口中的 drawer 不应把列表挤成无法操作的窄列。

### 7.4 数据状态

必须覆盖 loading、空库、筛选无结果、请求失败、正常结果及现有分页状态。

- 空库与筛选无结果使用不同说明；清除筛选入口仅在有筛选时显示。
- loading 不造成明显布局跳动，不展示假的成功或示例数据。
- 失败说明与重试行为沿用真实错误机制，不吞掉异常。
- 翻页、刷新、编辑、删除后保持现有选择和定位语义。
- 行内部按钮、checkbox 与打开详情事件不能相互误触。

## 8. 可用性与验收基线

- 正文及有效元数据对比度目标至少 4.5:1，大字至少 3:1；必要控件边界和焦点指示目标至少 3:1。具体组合要检查，不能仅因使用 token 就假定达标。
- 不仅靠颜色区分状态；保留文字、图标、标记或选择语义。
- 键盘可操作导航、主题控件、工具栏、列表已有操作和弹层；焦点清楚。
- 若既有 modal/drawer 存在，保留 Escape、焦点管理和关闭后返回触发元素的行为。
- 至少检查 1440×900、1280×800、1024×768 的桌面视口，以及一个约 768px 宽的窄窗口。
- 明暗主题、侧栏展开/折叠下均无关键内容遮挡，无非预期整页横向滚动。
- 共享 Shell 的变化不能使未重设计页面不可用。

最终验收以实际浏览器中的界面、真实数据和既有行为为准；效果图只提供方向。
