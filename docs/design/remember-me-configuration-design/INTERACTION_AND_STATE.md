# Configuration — Interaction & State Contract

## 1. 状态驱动与安全边界
通过现有 `/api/maintenance` 快照推导：运行中 / 维护中 / 模型未就绪 / 维护异常 / 状态不可用。Shell 共用这份状态，不要制造前端第二权威来源。轮询失败按「不可用」处理，写操作默认禁用，恢复成功后再重新判定。

现有门控规则必须保留：
- Enter Maintenance：仅运行中可用；进入时等待活动写入结束；对整个服务生效而非仅当前 Tab/浏览器。
- Exit Maintenance：维护中、已就绪、无错误、无模型待办、无冲突任务时可用。
- Import / Export / Clear / Migrate / Recover：仅维护中就绪且无错误、无模型待办、空闲时可执行；互斥串行。准备好的表单不会自行触发操作。
- Sync：维护空闲且无模型准备要求时可执行；维护错误下仍允许修复，不得一概禁用。
- Restart / Shutdown：在维护中，或模型未就绪且空闲时允许，须遵守当前后端允许的具体条件；在当前工作完成后执行。
- Model Retry：仅模型未就绪且未处于下载、验证、取消/上次任务结束过程时可用；修改代理再重试时沿用现有重建客户端逻辑。**模型未就绪自动进入维护的行为保留**，不与「用户手动触发维护」原则冲突。
- Save Configuration：无需维护模式，配置加载且校验通过、有更改时可用。
- 任意任务结束后保持当前维护模式，用户手动 Exit；切换 Settings Tab 或离开页面不自动退出。

## 2. 表单校验
现有可写字段范围为 `port`, `language`, `proxy`, `auto_download_model`, `local_only`, `debug`。Debug 已完整接入配置，默认 false，保存刷新生效，不支持 --debug；直接复用现有契约。后端既有严格未知字段拒绝规则不得放宽成任意写入。

- `port`: 1–65535 整数。
- `language`: `zh-CN`、`en`。
- `proxy.enabled`: true 时必须存在有效的当前或已保存地址；URL 仅 http/https，有 hostname，端口若提供必须合法，path 仅允许空或单个 `/`，不得有 query/fragment/空白。
- 代理修改字段为空表示保留已保存地址；脱敏 `***@` 绝不可当输入值提交，后端当前会拒绝；不向 UI 泄露敏感代理凭据。
- 取消本机服务即时出现风险说明，保存时如本次转向非本机监听，二次确认。
- 如果某些服务端值未在响应中提供（如是否已有代理），应先确认响应契约，不推断。

## 3. Data Transfer
**Import**：选择 `.jsonl` / `.ndjson`，限制 64 MiB / 10,000 条 live 记录；可选 Namespace 前缀；轮询进度。完成保留「导入 N / 跳过 N / 重命名 N」，必要时刷新 Memory/Stats。

**Export**：展开选择 Full Export 或指定 Namespace；Full Export 先刷新并验证灾备 JSONL 再下载；Namespace Export 产生独立局部快照；下载文件名遵循响应头 `Content-Disposition`，记录数读取 `X-Memory-Count`。按现有后端条件只在维护中操作。完成保留结果，不自行收起。

## 4. Data Management
**Sync Backup**：直接触发主库 SQLite→灾备 JSONL 的完整同步；双模式时展示主路径→副本路径，结果清晰反馈。

**Migrate Namespace**：源 Namespace 下拉包含记录数，目标可输入/选择建议名称；执行前弹出确认，明确源、目标、记录数与不可撤销；不要求随机码；成功后刷新数据视图与统计。

## 5. Server
**Restart**：确认后等待进行中操作收尾，保留启动参数。页面自动等待服务恢复、重新读取状态与配置；有限时重试，若端口/访问范围变化提示使用新地址，不无限旋转。

**Shutdown**：危险色确认，明确需在终端手工启动；关闭后显示失联状态，不继续提供执行控件。既有状态门控保持不变。

## 6. Danger Zone
**JSONL Recover**：选择 `.jsonl` / `.ndjson`，明确将**覆盖当前数据库全部记忆**；执行前通过随机 8 位确认码模态框确认。成功刷新 Memory/Stats；失败显示原因并仍留维护中。

**Clear**：选择 Namespace，留空或「全部」代表全库；执行前通过随机 8 位确认码模态框确认，明确不可撤销；成功刷新 Memory/Stats。两者均不可被普通浏览器 confirm 替代。

## 7. Model Management
展示缓存缺失、加载/下载、验证、已就绪、失败、结束前一任务等状态。已知总量显示文件名、完成量、总量、百分比；未知总量使用不确定进度；失败显示错误。已就绪时压缩信息密度，重试按钮禁用。不要凭空造独立模型清单或版本号，除非真实 API 已提供。

## 8. 失败与确认
所有危险确认应描述实际对象与影响而不是笼统「确定吗」。API 返回的错误信息应该在相关操作区域就地显示；高风险错误不能仅展示短暂 toast。前端禁用只是 UX，后端仍需最终校验维护状态与任务互斥。
