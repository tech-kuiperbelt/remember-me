# Memories — Search / Filters UI 视觉精修实施规范

## 1. 目标与实施边界

- 目标：现有 Memories 页搜索操作区改为专业、紧凑、内聚的一行式桌面布局；Advanced 按需在下方展开；Light/Dark 主题一致；窄屏可靠折行。
- 参照：`reference/current-search-expanded.png` 是**现有实现事实**；`reference/approved-visual-direction-light-dark.png` 是**视觉风格参考**。如果效果图与现有功能不符，以本规范及当前代码的业务行为为准。
- 仅在 Memories 页的 Search/Filters/Advanced/Results toolbar 及这些局部区域必需的样式内修改。**不修改** Shell、Memory Card、Detail Drawer、数据接口、请求参数、搜索/过滤/排序算法、数据存储。
- 不因示意图中的文字或假控件更改现有 UI 功能。例如现有 **Keywords 是下拉筛选器**，不应因为生成效果图画得像文本框就改成文本输入框。

## 2. 当前组件/行为（全部保留）

1. 搜索模式：`Semantic / Lexical / Anchor` 下拉选择（当前位于搜索输入框左端）。
2. 输入查询 + `Search`、`Clear search`；输入提交与清除语义严格维持现状。
3. 常规过滤器：`Namespace`、`Categories`、`Keywords`；保留选项、联动、状态、菜单定位与键盘交互。
4. `Advanced` 折叠/展开：Top-K、最低相似度、Updated after、Updated before、`Apply`。原有验证、单位/范围、默认值、生效条件和调用时机全部保留。
5. 结果区域：记录数量，`Sort` 下拉，`+` 新建按钮；保持原事件处理、权限控制、禁用状态与入口。

## 3. 目标布局

### 3.1 Desktop / 宽屏（空间足够时）

- `Memories` 标题仍在顶部，不对 Shell 做调整。
- **主搜索栏为一条紧凑的水平行**，建议视觉顺序：
  `[Semantic ▼] [🔍 Search input, flexible] [Namespace ▼] [Categories ▼] [Keywords ▼] [Search] [Clear search] [sliders icon Advanced ▾]`
- Search mode 与输入框应保持紧密关联；可以继续放在**同一个组合控件**内（现有实现模式），而不是破坏功能再重新发明交互。
- 搜索文本输入框是弹性元素，优先占用剩余横向空间；过滤器、操作按钮有合适的内在宽度，统一控件高度、纵向居中和间距。不可让输入框被压缩到难以使用。
- 放大镜位于**搜索文字输入区域左侧**，与搜索模式下拉的方向保持清晰分隔；图标为辅助识别，不是单独按钮，不改变焦点/提交行为。
- Advanced 默认折叠，其入口与主搜索控件位于**同一行的末端**，图标使用通用 sliders/tune 图形 + `Advanced` 文字 + 展开状态箭头。
- `Clear search` 仍可保留既有完整文案和既有禁用逻辑，不强行将它缩写为图标。
- 主搜索区域紧贴结果工具栏但保留适度间距；不用额外的高对比卡片嵌套或重阴影。

### 3.2 Advanced 展开（内嵌向下推开）

- 展开时在主搜索栏**下方**显示高级条件，推动下方工具栏及列表向下；**不使用浮层、popover 或覆盖式定位**。
- Top-K、最低相似度、Updated after、Updated before、Apply 尽可能组成紧凑的横向一行，标签位于对应输入框上方，控件底边对齐。
- Top-K 和最低相似度为较窄字段；日期条件应有足够宽度展示输入格式和日历图标。
- 保留原字段帮助文本/提示的含义（如“仅搜索时生效”、“0–1”、“浏览与搜索均生效”），可以统一视觉样式、减少空白，但**不能删除必要的解释或让它归属不明**。
- 日历图标沿用原日期控件自带的图标或现有实现，避免叠加第二个图标。日期格式、选择器与输入合法性不变。
- Apply 保持原有生效边界：不要自动应用未提交的 Advanced 修改，除非现有代码本来如此。
- Advanced 展开区尽量使用同一背景/轻量边界，不新增独立厚重卡片；也不用明显的彩色填充。

### 3.3 Results toolbar

- 保留**独立一行**：左侧 `1237 memories` 形式的动态结果计数；右侧 `Sort` 标签 + 现有排序控件 + 原 `+` 新建按钮。
- 对齐并收紧与首条 Memory Card 间距（建议 8–12px），按钮样式与现有主色一致；不得把排序或新增按钮塞进搜索栏。
- 计数始终来自真实数据，不写死示例值。

### 3.4 Responsive

- 以**可用宽度**而非固定截图像素控制：宽屏优先单行；无法容纳时合理折行/分组，不能通过极小输入框、文本挤压或横向溢出来强行维持一行。
- 中等宽度优先保证 Search input 可输入、主要按钮可触达，过滤器/Advanced 可移到下一行；更窄时控件完整换行；Advanced 参数也可自然分两行及以上。
- 测试下拉面板、日期控件不会被祖先 `overflow: hidden` 截断；不要因为紧凑化引入 viewport 边界问题。
- 中英混合标签和浏览器缩放（至少 100%、125%）不发生遮挡或意外错位。

## 4. 图标规范

**“在不增加学习成本的前提下，优先使用一眼能理解的通用图标。”**

- 搜索输入框：放大镜（约 14–16px，低对比蓝灰色），保留可理解的 placeholder；**不要用单独图标完全取代文字提示**。
- Advanced：sliders/tune 图标 + `Advanced` 文案 + 状态箭头；不用齿轮替代，以免与全局设置混淆。
- 日期：原日历图标；新增：原 `+`；下拉：常见 chevron。
- Namespace/Categories/Keywords 不额外增加装饰性图标；Sort 文字和方向足够清晰，无需堆叠新图标。
- 图标沿用项目现有 icon 系统，避免引入不必要依赖或新的视觉语言。

## 5. 视觉风格与主题

- 延续已确定的冷蓝灰视觉方向：细边框、淡色背景、清晰文字对比、适度圆角、轻量间距。
- 控件高度、圆角、内边距、字重一致；用层级和对齐体现精致，不堆叠阴影。
- Light / Dark 使用**语义主题变量**（优先复用现有 tokens），避免只为 Light 写死颜色或暴力反色。
- 聚焦态需要明显可见，禁用态不能看似可点击；Hover/Focus 不造成布局跳动。
- 示意图的中文翻译、顶部布局和列表内容不是强制改动项。保留当前产品既有语言、术语和卡片视觉方案。

## 6. 交互与可访问性（不得退化）

- Enter 提交、搜索模式切换、Clear search、过滤器选择、Advanced 展开/折叠、Apply、Sort、新建等已有行为全部回归测试。
- 图标本身不额外抢键盘焦点；组合搜索控件、下拉菜单有明确的 focus 样式与可访问名称。
- Advanced 开关应有正确的展开状态（如 `aria-expanded`），控件标签明确绑定；隐藏时避免 Tab 进入不可见字段。
- 保持错误/空结果/loading 等既有状态样式可读，不让动态消息挤压主控件。
- 不新增自动提交、快捷筛选、额外快捷键或改变默认检索模式。

## 7. 验收清单

- [ ] 真实宽屏下 Search mode、放大镜搜索框、Namespace、Categories、Keywords、Search、Clear search、Advanced **紧凑同行**。
- [ ] 窄屏/浏览器缩放后合理折行，无水平滚动或控件遮挡；输入框仍可用。
- [ ] Advanced 默认折叠；展开向下推开内容而非覆盖列表；五个既有控件都完整可用。
- [ ] Top-K/最低相似度的帮助信息和现有参数行为不变；两个日期控件与日历选择器可用。
- [ ] 搜索输入框显示放大镜 + placeholder；Advanced 显示滑杆图标 + 文案；无新增需要学习的图标。
- [ ] 结果数量左对齐，Sort 和 `+` 右对齐，且保留独立工具栏。
- [ ] Light/Dark 均清晰、统一；键盘 Tab、聚焦反馈、下拉位置和弹层边界正常。
- [ ] 搜索、清除、筛选、排序、新建、Advanced Apply 等业务语义及请求参数未改变。
- [ ] Memory Card、Shell、Detail Drawer 未被改动；如触及共享 CSS，验证其他页面无回归。
- [ ] 项目现有相关测试与构建检查通过；报告无法验证的项目。

## 8. 实施顺序与 Codex 约束

1. 阅读当前 DOM/组件与样式，确认 Search、Filters、Advanced、Results toolbar 的真实代码边界和已有测试。
2. 先小范围调整布局与响应式，再加入放大镜及 Advanced 滑杆图标；保持现有事件绑定/参数。
3. 完成 Light/Dark、折叠/展开、不同宽度、键盘操作回归。
4. 汇报改动文件、前后截图（如可获取）、测试结果以及任何有意偏离规范的地方。

**禁止：**重新设计 Shell / Memory Card / Drawer、删掉 Keywords 下拉、改变检索模式选择逻辑、为了贴合效果图重写数据或替换搜索 API、顺手重构无关组件、引入新视觉组件库。
