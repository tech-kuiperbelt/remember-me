# Remember Me · Help 设计规范

> 版本：2026-10-14 · 状态：设计交接（非实现说明）
> 依据：现有 `help-page.md`、当前 Help / Memories / Stats / Configuration 页面截图、已确认的讨论决定，以及当前 `/read-me` 文本。

## 1. 产品定位与设计目标

Remember Me 是配合 LLM Agent 使用的个人长期记忆 MCP 服务。**Agent 是记忆的主要生产者、检索者和使用者；Web UI 是用户查看、理解、修正、整理和控制记忆的窗口**。Help 是一份简洁、友好、随时可查的个人软件使用指南，不是企业级文档门户，也不承担完整 API Reference 的职责。

核心原则：**Agent-first, Human-in-control**。

设计成功的标志：初次接触的用户能快速明白产品价值，知道将 `/read-me` 地址交给 Agent；碰到 Namespace、Anchor、Coverage 等术语时能快速弄懂；使用或维护界面时不容易误操作。

### 内容取舍规则

- 优先解释「为什么」「什么情况下使用」「如何操作」；不追求所有实现细节。
- 凡是 Agent 可代做的技术配置，优先引导用户委托 Agent。
- 只解释用户在实际 Web UI 中会看到、且可能不理解的术语、指标与行为。
- 基础内容直接可见；复杂配置、手动步骤和故障排查按需展开。
- 任何危险操作必须解释后果、保护措施；Help **不能直接执行**这些操作。
- 不编造 UI 字段、指标、控件、Agent 兼容性或业务能力。

## 2. 信息架构

```text
Help 首页
├─ About Remember Me（首页完整品牌介绍 + 西部世界引文）
├─ Getting Started（三个轻量卡片）
│  ├─ Connect AI（以 /read-me 地址为主）
│  ├─ Namespace（给记忆分组）
│  └─ Memory Rules（让 Agent 在长期指令中使用记忆）
├─ Reference（轻量文字入口，不做大量视觉卡片）
│  ├─ Memory
│  ├─ Retrieval
│  ├─ Stats
│  └─ Configuration
└─ Troubleshooting（轻量文字入口）
   ├─ Connection & Setup
   ├─ Memory & Search
   └─ Service & Configuration
```

首页阅读顺序：**记忆为什么值得保存 → 如何让 Agent 用起来 → 有疑问去哪里查**。

详情页使用现有应用主工作区，顶部为 `Help / 当前主题` 的简洁面包屑；点击 Help 返回首页。不引入第二套固定侧边栏、文档专属顶栏或复杂导航树。较长详情页可提供很短的页内锚点导航。

## 3. 首页布局

- **About**：首页最重要的区域。宽屏左右双栏，左侧完整品牌理念，右侧《西部世界》引文与出处。允许极轻的背景层次或渐变；不得用浓烈科技纹理、插画、大幅装饰抢夺注意力。窄屏纵向堆叠。
- **Getting Started**：三张横向卡片（Connect AI / Namespace / Memory Rules），短说明 + 进入指南入口；突出简单性，避免承载完整的操作配置。
- **Reference**：四个轻量文字链接（Memory / Retrieval / Stats / Configuration），可以双列排列；图标可省，不应让这一区域看起来像第二个 Dashboard。
- **Troubleshooting**：首页底部一个低视觉权重入口，不默认展开全部 FAQ。

使用比现有单列 1000px 文档更灵活的宽屏容器，但**不要将长段正文拉宽**：宽度由多列布局利用，文字块依然保持舒适的行长。无需预先锁死像素宽度，按现有应用 Shell、响应式断点及视觉测试决定。

## 4. 详情页规范

| 页面 | 主要形态 | 必须保留的要点 |
|---|---|---|
| Connect AI | 三步引导 + 突出的 URL 复制区域；可局部双栏 | `/read-me` 是说明地址而非 `/mcp` 端点；动态 URL；完整接入请求为次级选项；通过 Agent 调用 MCP 验证 |
| Namespace | 简短说明 + 跨 Agent 同组示例 | 同项目同分组、不同项目不同分组；Namespace 不等于权限隔离 |
| Memory Rules | 步骤 + 组合复制操作 + 按需展开工具说明 | 八条规则原意完整保留；写入项目长期指令，而非仅当前聊天消息；规则保存后验证 |
| Memory | 说明 Agent 生成来源 + 教学记忆示例 + 管理说明 | Agent 主要保存；Web 主要浏览、筛选、修正、删除；手动新建为辅助功能 |
| Retrieval | 三种模式横向对比 + 使用说明 | Semantic、Lexical、Anchor；Search/Clear/Advanced/日期过滤；分数不可跨模式比较 |
| Stats | Memory / LLM Retrieval 两节，解释指标 | 只解释实际 Stats UI 中出现的指标，不复制完整仪表盘；不引入 Hit@1/Hit@5 |
| Configuration | Settings / Maintenance 两节 + 简短 Danger Zone 提醒 | 说明功能与生效方式；Help 全部只读；维护模式需手动进入；危险操作仅解释不执行 |
| Troubleshooting | 按三类分组的折叠 Q&A | 连接、保存/搜索、服务/配置、模型下载失败与未就绪 |

## 5. 交互规则

- 导航：Help 首页 → 独立详情页 → 面包屑返回；路由与刷新行为接入现有应用约定，保持浏览器后退/前进一致。
- 文案语言：面向中文普通用户，以通俗中文说明，首次遇到专业术语时附英文原名。
- 地址：`/read-me` 展示为**当前可获取的实际地址**；示例不可冒充运行时地址。尤其要提示 `127.0.0.1` 只适用于同机客户端，跨机器需可访问且安全的地址。
- 复制：实际可复制 URL、完整接入请求、保存规则；提供成功/失败反馈；失败可手动选择文本。不要让不同复制按钮的行为难以区分。
- 长说明：用原生或同等可访问性的折叠区，保留键盘、焦点及语义标签。
- 敏感操作：Help 禁止直接触发 Recover、Clear、Shutdown、进入维护等操作；需要时仅跳转对应配置页。
- 不引入不必要的搜索框、角色体系、文档版本选择器、企业知识库功能。

## 6. 视觉规范

- 延续 Remember Me 现有 Light/Dark 配色、字体层级、卡片半径和全局 Sidebar，不另建视觉体系。
- 页面应像一本**精致、安静、易用的小手册**：少量重点卡片、适当留白、明确标题与段落节奏。
- 首页 About 可以比日常参考区更有排版表现力，其它区域克制，避免密集小卡片和过多图标。
- 信息优先级：About 与 Connect AI 主入口 > Getting Started > 参考说明 > 高级排错。
- 图标只服务辨识；不要为每一行解释增加图标。
- 警示色仅用于实际风险提示，不要整个页面变成危险态。
- Light/Dark 同一信息层级、结构和间距，不以某一种主题单独设计布局。
- 触屏窄屏时三列、两列自然收为单列，保留文字换行与按钮可操作尺寸。

## 7. 视觉参考的正确使用

`mockups/` 中的图片仅为**风格与布局参考**，并非像素级实现稿。部分生成图含不应采用的独立文档导航侧栏、顶部搜索、过多装饰性图标、英文占位或虚构控件。**以本文件、HELP_CONTENT.md 和真实应用页面为准**，不得照图实现这些偏差。

## 8. 非目标与边界

- 不修改 MCP 工具、传输协议、`/read-me` 的业务行为、记忆数据库、统计模型、Maintenance 功能或现有配置语义。
- 不把 Help 做成手动维护记忆的主要操作入口。
- 不在 Help 复制完整 MCP API 说明；必要时引用现有 `/read-me`。
- 设计文案中对 Agent 行为的表述应是「可以」「在设置相应规则后」，避免承诺连接成功后无条件自动保存。
