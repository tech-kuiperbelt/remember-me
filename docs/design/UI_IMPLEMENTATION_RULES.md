# Remember Me UI 分阶段实施规则

与同目录 `UI_DESIGN.md` 一起使用。视觉参考为 `remember-me-ui-reference.png`，布局参考为 `remember-me-layout-reference.png`。

## 1. 当前授权与工作方式

当前首阶段目标为 **Shell + Memory List**，不是 Shell + Search。

**先检查现有项目并提出计划。在用户明确批准计划之前，不修改应用代码、配置或依赖。** 本文描述后续实施范围，不构成提前执行代码修改的许可。

可以执行只读检查、阅读文件、查看参考图，以及不修改受版本控制文件的现有构建/验证命令。不要在计划审批前执行 formatter、生成器、安装依赖或会改写源文件的修复命令。

用户批准首阶段计划后，可在该范围内自主完成实现、修复和验证，不需要逐个控件重复询问。新增业务功能、替换框架、改变数据语义或扩展到其他页面，需要单独明确批准。

## 2. 全程边界

- 保留现有框架、路由、业务逻辑、API、数据结构、权限与功能。
- 优先复用组件、事件、图标和数据获取逻辑，避免因视觉重构换技术栈。
- 允许为布局、主题和组件复用进行必要的前端结构调整，但不得改变业务行为。
- 不修改后端，不新增字段、endpoint、示例业务数据或假状态。
- 不根据图片新增登录、头像、retrieval score、批量操作、关联记忆或详情 tabs。
- 不自行移除 Add 等既有入口；信息架构变更应在计划中单独提出。
- Logo 暂不设计。
- 不自动部署、发布，也不自动实施后续页面。
- 不覆盖用户已有未提交改动。发现冲突时先解释具体影响。

## 3. 阶段 0：只读检查与实施计划

### 检查内容

1. 阅读仓库约束和现有开发说明。
2. 确认框架、构建方式、路由或页面切换机制、样式组织与可用验证命令。
3. 查看参考图片，理解明暗主题与布局，不仅阅读文件名。
4. 定位 Shell、顶栏、侧栏、Memories 列表、主题以及弹层的实现文件。
5. 梳理列表现有的查询、筛选、排序、分页、选择、详情、添加、编辑、删除行为，区分已存在与缺失功能。
6. 识别 ID、`data-page`、全局样式和事件绑定等兼容约束，记录共享样式可能影响的页面。

如果参考图无法读取，明确报告并请求补齐，不声称已经看过。可以继续检查现有代码，但不能将猜测写成图中事实。

### 计划交付物

提交一个可 review 的具体计划，至少包含：

- 当前前端结构与 Memory List 已有功能摘要。
- 将修改的文件/组件及每项修改的目的。
- Theme tokens、Shell 滚动、侧栏折叠、主题持久化的实现方案。
- Memory List 的结构与现有字段映射。
- 现有详情、编辑、删除和添加入口如何保留。
- 全局样式对其他页面的影响与兼容处理。
- 与规范/参考图的必要差异，以及需要用户决定的实质性问题。
- 可执行的验证命令、浏览器验证方式、回归范围与回退方式。

优先按现有技术栈提出最小合理方案。没有必要引入新依赖时，不增加依赖。

**提交计划后停止，等待用户明确批准。**

## 4. 阶段 1：实施 Shell + Memory List

本阶段只在计划获批后开始。按下列顺序逐步完成，在范围内持续验证，不需要每个子步骤再次审批。

### 1A. Theme 与基础视觉

- 建立语义 design tokens，并定义 Light / Dark。
- 实现 Light / Dark / System 切换、持久化和首次绘制主题初始化。
- 统一基础文字、按钮、输入、select、checkbox、边框、圆角和 focus。
- 优先将共用控件接入 token，不通过大面积全局选择器强制覆盖所有页面。
- 暗色主题覆盖已有菜单与弹层，防止白色控件残留。

### 1B. Application Shell

- 顶部通栏，左侧手动可折叠导航，右侧工作区。
- 默认侧栏 180px，折叠 64px；状态保存，存储不可用时降级。
- 顶栏与侧栏保持可见，工作区独立纵向滚动。
- 工作区铺满剩余宽度，移除全局 1200px 居中约束。
- 顶栏拥挤时正常换行并自动增加高度。
- 保留真实服务状态、既有 Refresh / Debug 行为和导航功能。
- 保留导航事件契约、当前页、表单状态和 overlay 兼容性。

### 1C. Memory List

- 按 Page Header → Toolbar → List → Pagination 组织页面。
- 实现紧凑、连续的列表层级，使用现有字段、操作与数据。
- 应用标题/摘要/元数据的字体层级，以及 hover、selected、focus 状态。
- 保留查询匹配、筛选、排序、分页、选择和数据刷新语义。
- 处理 loading、空库、无匹配、失败、正常数据、长内容和缺失字段。
- 保留添加、详情、编辑、删除等现有入口，并确保行内控件不误触。
- 关闭已有详情时不为参考图预留永久空白区域。

### 本阶段明确不包含

- Search、Audit、Stats、Keywords、Settings 等页面的专项重设计。
- 将现有详情机制改成 drawer，或新增详情 tabs。
- 新的业务筛选、批量操作、retrieval 可视化或后端能力。
- 品牌 Logo、导航结构重排、全站组件大规模重写。

Shell 与共用 token 自然会影响其他页面；必须修复因此造成的功能破坏、裁切或主题不可读问题。这属于兼容工作，不能借此扩展其他页面的设计范围。

## 5. 阶段 1 验证与交付

### 验证矩阵

| 维度 | 必须检查 |
| --- | --- |
| 主题 | Light、Dark；System 跟随系统，手动选择不被覆盖 |
| 侧栏 | 展开、折叠；刷新后保存；存储不可用时可使用 |
| 桌面尺寸 | 1440×900、1280×800、1024×768 |
| 窄窗口 | 约 768px 宽，工具栏换行，主要操作可达 |
| 列表 | 正常、loading、空库、无结果、失败、长内容、缺失字段 |
| 行为 | 现有查询/筛选/排序/分页/选择，以及打开、添加、编辑、删除 |
| Shell | 顶栏换行、滚动边界、页面切换、overlay、不遮挡 |
| 回归 | 其他已有页面导航和主要功能可用，明暗主题无明显不可读区域 |
| 键盘 | 导航、折叠、主题、工具栏、行内操作、现有弹层焦点行为 |

截图使用测试数据或经允许的现有数据，不通过修改生产数据制造验收场景。

运行项目现有且适用的 build、lint、typecheck 和相关测试。只在新交互或回归风险确有需要时增加测试；不要为纯颜色和间距编写机械测试。验证失败应修复或说明真实阻塞原因。

### 交付物

1. 代码变更摘要：改了什么、为什么，以及兼容影响。
2. 验证结果与未解决问题，不把未执行项写成通过。
3. 实际浏览器截图：同一数据下的浅色/深色 Memory List、侧栏折叠，以及至少一张窄窗口效果。
4. 本地运行/预览方式，让用户能实际 review。
5. 任何与批准计划的差异及理由。

若无法运行浏览器或获取截图，明确记录限制与已完成检查；不能用生成的效果图代替实现截图，也不能宣称视觉验收通过。

**完成 Shell + Memory List 后停止，提交结果供用户 review。不要自动进入下一阶段。**

## 6. 阶段 2：首阶段视觉校准

仅在用户 review 后明确要求继续时开始。围绕实际截图调整 tokens、间距、密度、控件和交互状态，完成首阶段遗留问题。

此阶段仍限于 Shell + Memory List。必要时微调共享 token，并做对应回归；不扩展页面范围。

根据浏览器效果确认最终色板与尺寸，更新 `UI_DESIGN.md` 中的实际值，避免文档与代码分离。

完成后再次交付明暗主题截图和验证结果，停止等待后续指令。

## 7. 阶段 3：后续页面，另行授权

由用户选择下一个页面或功能，再提出该阶段计划并获批。可选方向包括 Search、Audit、Stats、Keywords、Settings、Memory Detail。

将已稳定的视觉语言扩散到所选页面，不把“统一风格”解释为一次性重写全站。新增 drawer、详情 tabs 或 retrieval 表现需确认真实数据能力和业务需求。
