## 模块与执行顺序

| 步骤 | 实施位置 | 职责与验证 |
|---|---|---|
| 1 | `detail-model.js` | 从权威记录创建草稿；字段差异、Unicode 校验和最小 PUT。正文变化额外携带摘要与 anchors；历史维度未改时不清洗 |
| 2 | `markdown.js`、`static/vendor/` | 本地固定 Marked／DOMPurify，受限 HTML、严格 URL、图片文字链接、代码复制和表格滚动；记录许可证与包完整性 |
| 3 | `memory-value-picker.js`、`memories-filters.js` | 共享实例化能力；列表保留既有 ID、20 项上限；详情使用 3 分类／不限关键词、新增动作和独立请求版本 |
| 4 | `detail.js`、`index.html`、`app.css` | 响应式模态抽屉（用户宽屏 review 后改为 60vw，下限 640px、上限 1040px）、查看／编辑／Preview、脏判定、离开守卫、单次写入、PUT→GET、删除确认、焦点和滚动所有权 |
| 5 | `router.js`、`main.js`、`memories.js`、`memories-list.js`、`ui.js` | 同步路由 continuation；列表按 ID 选中、通知驱动重取、滚动恢复；多个 Debug 入口 |
| 6 | `tests/browser/detail_regression.js`、现有浏览器 runner | 迁移旧弹窗的 Save 后关闭、直接 Delete、旧 Namespace dropdown 断言；新增契约／错误／竞争测试及明暗视觉场景 |
| 7 | 设计包、路线图、backlog | 记录实际验证和截图，明确前后端及联调状态 |

## 状态和跨模块约束

- `closed/loading/load-error/view/edit/saving/reloading/saved-error/not-found/deleting`；edit 的 clean/dirty 由纯函数计算。另有 menu、picker、discard/delete confirmation 子状态。
- 打开、关闭、重读更新请求版本，旧响应不覆盖当前会话。保存／删除期间拒绝离开和重复提交。
- `requestLeave(action)` 同步协调离开；dirty 只保留第一个 continuation，确认后执行一次。路由先验证目标，再在 continuation 中准备筛选并切换，取消时不提前改状态。
- 保存成功立即解除草稿 dirty，发出一次 Memories／Stats 通知，然后读取权威记录。读取失败保持只读，Retry 仅 GET。
- 元数据只提交变更维度；普通正文变更携带当前 summary（空白为 `""`）和 anchors（空为 `[]`）。不暴露 `clear_summary`，不修改 MCP schema。
- 列表由既有数据模块重新执行当前 Browse／Search，不推断分数或记录是否已退出筛选。选中按 ID，不按行号。
- 模态固定覆盖，背景 inert；已折叠 details 的内部按钮不得进入 Tab 循环。嵌套菜单／picker／确认先处理 Escape；IME Escape 忽略。

## 实施复核修正

- 排除关闭的 details 内部控件，确保 Tab 能真正闭环。
- 保留背景滚动条，避免隐藏 overflow 使列表变宽 10px。
- Debug 退出优先恢复抽屉内可达控件；Tab 允许进入模态焦点管理。
- 历史非法／超限维度完整显示且可移除，未编辑时不擅自清洗。
- Preview 保留精确源码、选区和编辑区滚动位置。
- 保存后重读错误保持只读，Retry 只发 GET；列表重取不抢抽屉焦点。
- 路由筛选准备与 Clear 的目标 Namespace 预选放入离开 continuation，取消不提前变更目标页状态。
