# [50.1] 前端第一阶段：保持行为的模块拆分

基线：`a2f2201`（[50] 路线图已记录，尚未实施）。状态：第一阶段已实现并验证，未部署。

本文件是 [50] 第一阶段（保持行为的小范围重构）的实施细节，不改变 [50] 的路线定位。
第一阶段的界面、布局、功能和交互行为保持不变；本阶段只整理职责与结构。

## 决策

1. JavaScript 采用原生 **ES modules**，事件绑定改为 `addEventListener`，移除全部内联
   `onclick`；不引入框架或构建工具。（用户确认）
2. 静态资源由后端单条 `{asset:path}` 路由提供，做路径限界与扩展名白名单，沿用
   `Cache-Control: no-store`。（用户确认）
3. 生产页面**不暴露测试控制接口**；浏览器回归在 `fetch` 请求边界拦截并驱动页面操作，
   跨页跳转回调由入口 `main.js` 装配注入，功能模块之间不互相导入。（评审修正，替代最初
   的 `window.__admin` 方案）

## 目标目录

```
web/
  index.html                  # 仅结构 + <link> + <script type="module" src=.../main.js>
  static/
    app.css                   # 原 <style> 全部内容
    js/
      core.js                 # $、esc/escapeHtml、formatTime、formatBytes、deriveSummary、truncateJson
      api.js                  # api()、isNamespaceNotFound、confirmNamespaceCreation
      ui.js                   # toast、showError、弹窗基座、debug 辅助
      store.js                # 命名空间注册表（list+counts）与维护态，订阅通知
      router.js               # switchPage + 页面注册（替代 if(name===...) 硬编码）
      detail.js               # 详情/编辑弹窗（memories、search 共用）
      memories.js             # 记忆列表、排序、分页、ns-tabs、clearNamespace
      search.js               # 语义/精确双模式、关键词下拉、结果渲染
      keywords.js             # keywords 浏览/分页/语义
      add.js                  # 新增记忆
      stats.js                # 统计页
      ops.js                  # 配置、维护、模型准备、import/export/sync/recover/migrate、重启/关机
      audit.js                # 审计页
      clear.js                # 清空确认码弹窗
      main.js                 # 唯一入口：初始化、事件绑定、维护轮询、启动
```

文件划分依据现有功能与耦合，可在实施中合并（如 detail 并入 memories）；不预设完整组件体系。

## 状态归属

| 状态 | 归属 | 说明 |
|---|---|---|
| `namespaces` / `namespace_counts` | `store.js` | 订阅式；删除 `loadStats` 对四个页面更新函数的扇出 |
| 维护态（state/action/model/error） | `store.js`（维护子 store） | banner、`btn-add-submit`、`btn-clear-ns`、ops 按钮统一订阅 |
| 列表/分页/排序/当前命名空间 | `memories.js` | 模块内 |
| 双模式查询、关键词下拉请求序号与偏移 | `search.js` | 模块内 |
| 关键词浏览请求序号与偏移 | `keywords.js` | 模块内 |
| `_currentDetailText`、`_copyBtnTimer` | `detail.js` | memories 与 search 共用 |
| 清空确认码、配置保存标志 | `clear.js` / `ops.js` | 模块内 |

跨页跳转（关键词→搜索、记忆→运维）不由功能模块互相导入，而由 `main.js` 通过
`mount({ showKeyword })` / `mount({ preselectClearNamespace })` 注入回调；其余共享状态
经 `store` 订阅。

## 初始化与事件

- 各模块导出 `mount()`；`main.js` 在页面启动时各调用一次，注册页面 `onShow`、
  注入跨页回调、启动单个 `setInterval`。当前 `mount()` 不保证重复调用时幂等。
- `router.register(id, {onShow})` 替代 `switchPage` 中的 `if(name===...)` 分支。
- 移除全部内联 `onclick`，避免重复绑定与全局函数泄漏；生产代码不向 `window` 暴露任何
  业务函数或共享状态。

## 后端静态资源

- `AdminAPI.ROUTE_TABLE` 增加
  `_Route("/admin/console/static/{asset:path}", ("GET",), "handle_asset", "asset", errors="none")`；
  `tests/test_admin_routes.py:ALLOWED_POLICIES` 增加 `asset`，`EXPECTED_ORDER` 同步。
- `handle_asset`：`Path.resolve()` 后必须位于 `web/static/` 内，扩展名白名单
  （`.css`、`.js`、`.map`、`.svg`、`.png`、`.woff2` 等），返回 `FileResponse` 并沿用
  `Cache-Control: no-store`；越界或不在白名单返回 404。
- `/admin/console` 继续逐字返回 `web/index.html`，保证资源定位回归不变。

## 实施结果

- 前端拆为 `web/index.html`（结构 + 资源引用）、`web/static/app.css` 与
  `web/static/js/` 下 15 个 ES module（core、api、ui、store、router、detail、
  memories、search、keywords、add、stats、ops、audit、clear、main），`main.js` 为唯一入口。
- 移除全部内联 `onclick/onchange/oninput/onkeydown/onsubmit`；导航改 `data-page`，
  事件由 `main.js` 在启动时调用各模块 `mount()` 注册一次；`switchPage` 改为页面注册表，
  `loadStats` 的跨页扇出改为 `store` 订阅；跨页跳转由 `main.js` 注入
  `showKeyword` / `preselectClearNamespace`
  回调，`keywords`/`memories` 不再导入 `search`/`ops`；生产代码不向 `window` 暴露接口。
- 后端新增 `asset` 策略与 `GET /admin/console/static/{asset:path}`：路径 resolve 后限定在
  `web/static/` 内、扩展名白名单、`no-store`；`/admin/console` 仍逐字返回 `index.html`。
- 测试适配：新增 `tests/test_frontend_assets.py`（白名单、MIME、no-store、越界、引用资源可加载）；
  `conftest.frontend_source()` 聚合前端源码，改写 `test_summary_input`、`test_keyword_migration`、
  `test_ndjson_replica` 的 UI 字符串断言。`run_admin_browser.py` 由**正式 `/admin/console`
  路由**提供页面与资源，仅测试运行中以 ASGI 中间件注入 `smoke_harness.js`（fetch 边界拦截）
  与 `admin_regression.js`（DOM 操作驱动）。
- 验证：全量 `pytest` 710 项通过；隔离 Chrome 浏览器回归通过；`test_admin_routes` 路由表与
  `ALLOWED_POLICIES` 已同步 `asset`。已更新 `AGENTS.md` 与 backlog 状态。
