## 1. 目标与设计修订

升级现有详情弹窗，完成查看、Markdown、编辑、未保存保护、保存和删除。沿用原生 ES Modules、既有主题及路由，不引入前端框架或构建流程。

| 设计问题 | 确定方案 |
|---|---|
| 遮罩关闭与直接点击其他记录冲突 | 采用模态抽屉，背景不可操作；先关闭，再选择其他记录 |
| 图示宽度未固定 | 按用户宽屏 review 调整：宽度为视口的 60%，下限 640px、上限 1040px，最大 100vw；固定右侧占满视口高度，头部固定，正文独立滚动 |
| 只有摘要／正文标签，缺少 anchors | 增加独立 Anchors 查看及编辑，最多 5 个 |
| Summary 无法清空 | 使用后端新契约；支持清空，修改正文时保留表单当前摘要 |
| 筛选器限制不同于记录字段 | Categories 最多 3 个；Keywords 不采用筛选的 20 项限制；允许明确新增值 |
| Markdown 图片与代码图示 | 图片显示文字及安全链接，不自动请求；代码块可复制，首版不做语法高亮 |
| 更新响应不是记忆 | PUT 成功后 GET 重读，独立处理重读失败 |
| 图示 Source、tabs、字符上限 | 不实现虚构字段、tabs 或 500／100,000 字符配额；真实输入限制以 API 为准 |

标题按既有摘要／正文回退派生，不新增 title；详情不显示空的 Score 字段。首版无自动保存、持久化草稿或版本冲突检测。

## 2. 展示、编辑与 Markdown

### 2.1 页面结构

- 信息顺序：头部 → Summary → Content → Categories → Keywords → Anchors → Technical details。
- 头部：简短标题、Namespace、更新时间；查看态为 Edit／更多／关闭，编辑态为 Cancel／Save changes／关闭。时间使用既有本地格式并提供完整 title。
- 标题单行省略，完整值可悬停查看；Summary 为完整纯文本，无值显示“无摘要”。
- 更多菜单保留复制正文并提供 Delete；复制始终复制原始正文，不复制渲染 HTML。复制失败要提示，不能因 Clipboard API 缺失抛未处理异常。
- Categories 全部展示；Keywords 默认 5 个，+N 在抽屉中原地展开全部并可收起；Anchors 全部展示并保留大小写，三者具有独立标题。
- Technical details 默认折叠，展示完整 ID、创建／更新时间及只读 metadata JSON；提供复制 ID、Debug 开关，不展示 embedding。
- 所有长值安全换行；普通文本通过 textContent／现有转义输出。

### 2.2 编辑器及候选选择

Namespace、Summary、Content、Categories、Keywords、Anchors 可编辑；ID／时间只读。Content 默认编辑 Markdown 源码，Edit／Preview 仅替换正文编辑区，其余字段仍可编辑。切换保留精确源码、选区及编辑区滚动位置，Preview 渲染当前草稿，不调用保存 API。

- Namespace 输入框提供已有值候选，允许新值；不能用空值表达 All。未知空间保存时复用确认创建流程，取消确认留在编辑态。
- Categories 候选来自既有 Stats；支持搜索和新增规范化值，最多 3 个。Keywords 使用远程 literal 搜索，250ms debounce、每页 20 个、加载更多，不加载全词库。
- 两个维度明确显示“新增此值”动作，规范化后已有的值不重复添加。无候选、候选错误或重试均不清除已选项。
- 关键词查询使用草稿 Namespace／Categories；上下文变化丢弃旧响应并保留已选值。新 Namespace 未知时不发 scoped 请求，提示可手动新增，保存确认后再查询。
- 提取支持独立实例、ID 前缀、挂载容器、maxSelected 和创建回调的选择器能力；列表保留自身 20 项筛选上限及既有 ID／交互。抽屉弹层挂载在其焦点管理范围内，不挂到被 inert 的背景。
- Anchors 使用可添加／移除的独立输入，最多 5 个；按后端 Unicode 规则校验，字符数使用 Unicode code point，不能误用 UTF-16 长度。修改正文时提示检查锚点准确性，不自动生成。
- 不修改的历史 metadata 不擅自清洗或截断；若显式编辑维度含历史非法值，展示并要求修正后保存，不静默丢弃。

### 2.3 Markdown

本地分发固定版本的 Marked 和 DOMPurify；实施时核验官方版本与安全公告，记录来源、版本、许可证、校验值。使用现有静态资源可服务的 `.js` 文件，不依赖运行时 CDN。

参考：[Marked 安全说明](https://marked.js.org/using_advanced)、[DOMPurify 官方文档](https://github.com/cure53/DOMPurify)。查看和 Preview 共用一个渲染入口及以下配置：

- 支持段落、标题、列表、引用、行内／围栏代码、表格、分隔线、链接。
- 原始 HTML 转义为文本；渲染结果通过 DOMPurify 的受限 HTML 允许列表清理，禁止脚本、iframe、表单、SVG／MathML、事件属性、内联样式及内容提供的 id／name。
- 链接只允许绝对 HTTP／HTTPS 和 mailto；网页链接使用新标签与 `noopener noreferrer`。相对、协议相对及其他协议显示文本。
- 图片转为替代文字与符合上述规则的链接，不生成 img 或其他外部资源加载节点。
- 代码使用等宽字体、复制按钮和局部横向滚动；表格独立横向滚动，长 URL 可换行。使用现有明暗主题 token，不套整块灰色正文卡片。
- 渲染失败显示内联错误与纯文本回退，不丢失源码。代码复制按钮通过受控 DOM 创建，不拼接不可信属性。

## 3. 状态、焦点和数据流

### 3.1 状态与 Dirty

状态包括 CLOSED、LOADING、LOAD_ERROR、VIEW、EDIT_CLEAN、EDIT_DIRTY、SAVING、RELOADING_AFTER_SAVE、SAVED_RELOAD_ERROR、NOT_FOUND，以及独立的菜单／选择器／放弃确认／删除确认子状态。模块持有 selectedMemoryId、originalMemory、editDraft、previewMode、requestVersion、pendingLeaveAction。

- 每次打开、切换目标或关闭使旧读取失效；迟到响应不得重开或覆盖抽屉。
- Dirty：正文按原文比较；Namespace／Summary 按 trim 后值比较（摘要 null 与空白表单等价）；Categories／Keywords 按规范化集合比较；Anchors 按规范化后的有序数组比较。
- 改回原值恢复 clean；Save 在 clean 或已知校验失败时禁用。Cancel 直接丢弃草稿，回到最后一次服务端确认的 VIEW。
- 关闭按钮、遮罩、Escape 和程序性切换目标都经同一个离开守卫。dirty 时显示 Keep editing／Discard changes，记录请求动作，确认后只执行一次；新动作不能覆盖已显示确认的目标。
- dirty 时注册 beforeunload，离开 dirty 状态解除。草稿不写 localStorage。

### 3.2 模态与可访问性

- 打开时关闭列表标签／筛选弹层，保存背景滚动和原焦点；背景 inert，锁定其滚动，列表宽度不变，不插入永久空白。
- 抽屉采用 dialog／aria-modal／标题关联，初始聚焦关闭按钮，进入编辑聚焦 Namespace。加载／错误状态也有可达的关闭与重试操作。
- 焦点只在当前最上层弹层内循环。Escape 先关闭选择器／菜单／确认框，再处理抽屉；组合输入时不处理退出快捷键。确认默认聚焦 Keep editing 或 Cancel。
- 保存／删除进行中锁定业务操作和关闭；浏览器退出仍使用相应 beforeunload 保护，不能承诺可阻止所有强制关闭。
- 关闭恢复原记录焦点；记录不存在则到结果栏。保存后的列表刷新不抢抽屉焦点。
- 程序性导航离开 Memories 需经过守卫；避免改变现有 router 的同步行为约定，新增明确的离开协调入口并核对调用者。
- 重要区域使用稳定 detail-* ID；保留可兼容的既有 detail-modal、detail-title、detail-body、edit-text、edit-namespace 等 ID。动态标签用维度与索引区分。
- 抽屉 Technical details 提供 Debug 开关，共用 ui.js 状态；Debug 识别多个开关，退出恢复可达的触发焦点。模态背景的原 Debug 按钮不可成为退出焦点目标，开启前后布局和内容不变。

### 3.3 保存与错误

接口以 [50.6.1](50.6.1-memory-detail-backend.md) 为唯一契约来源：

1. 校验草稿，只提交发生变化的字段；metadata 只包含变更维度。正文变化时额外提交当前 Summary 和 Anchors，空摘要为 `""`，空锚点为 `[]`。
   此规则有意改变旧弹窗行为：原 summary=null 的记忆仅修改正文时也发送 summary=""，存储继续为 null，不再自动派生存储摘要；已有摘要保留表单值。前端不发送 null 表达清空，null／省略仍是后端旧策略。列表／LLM 的展示回退保持，详情仍显示“无摘要”。Anchors 从 GET 原值回显，改正文时明确回传，不能因未编辑锚点而省略。
2. 锁定表单，发出一次 PUT。未知 Namespace 先按现有确认流程处理，确认后带对应 confirm_codes 重试；取消不丢草稿。
3. PUT 成功即标记已保存，清除 dirty，发出一次列表／统计更新通知，再 GET 当前记忆。
4. GET 成功用权威记录替换 originalMemory，返回 VIEW，抽屉保持打开。
5. PUT 失败保留草稿并恢复操作，内联显示错误；404 明确提示记录已不存在，保留复制草稿能力。
6. PUT 成功但 GET 失败进入 SAVED_RELOAD_ERROR，显示“已保存，详情刷新失败”，仅重试 GET，不重新 PUT，也不展示草稿为服务端最终值。GET 404 显示不存在状态，保留关闭。

### 3.4 列表同步与删除

- 沿用数据模块及既有变化通知，避免同时直接刷新与 emit 导致重复请求。重新执行已应用的 Browse／Semantic／Lexical／Anchor；不根据新字段自行推断语义结果或分数。
- 保留查询草稿、已应用查询／筛选／排序、页大小及当前页；页码越界时退到最后有效页。仅清空摘要也更新 updated_at，可能使记录在默认 Browse 中前移至顶部或改变时间筛选匹配；这是正常更新行为，不强制跳页寻找该记录。null／空白等价时表单保持 clean，不单独发起无效清空。
- 刷新期间保持列表滚动容器所需高度，完成后恢复原 scrollTop 并限于有效范围；打开／关闭本身不重取列表或重排布局。
- 选中样式按 memory ID 管理，重渲染后仍准确；结果移除时不把相同位置的其他记录误标选中。保存后目标不在当前页不等于不匹配，不显示未经证实的“已退出筛选”提示。
- 列表刷新失败独立显示错误，不能将旧结果标为最新，也不能将成功保存误报失败。
- Delete 仅在 VIEW 更多菜单显示，确认框含标题和完整 ID，默认 Cancel。请求期间禁用重复确认；成功后关闭抽屉、清除选中、发出一次列表及统计刷新通知，展示成功提示。
- 删除失败保持确认框和详情，显示错误，可重试或取消；不乐观移除。404 提示记录已不存在，用户关闭后允许刷新列表核对。

## 4. 实施步骤、验证与交付

### 4.1 模块职责与步骤

detail.js 负责抽屉会话与业务编排；Markdown 和可复用 picker 逻辑独立为模块，不把所有职责继续堆入 detail.js。Memories 数据模块负责结果重取，列表模块负责选中展示，路由负责离开协调，ui.js 管理共享 Debug。抽屉样式限定作用域，避免影响 Clear 等既有弹窗。

依次完成，每步定向验证后继续：

1. 抽屉结构、加载／错误、焦点、滚动及选中行。
2. 查看、安全 Markdown、复制、Technical details 与区域 ID。
3. 编辑表单、复用选择器、Anchors、Preview、Dirty 与离开保护。
4. 后端完成后联调 PUT／GET、列表同步、删除及异常路径。
5. 全量回归、真实只读浏览器复核、截图与文档收尾。
