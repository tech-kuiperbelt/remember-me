## 目标与边界

承接已完成的主题基础和 Shell，推进 UI 路线的第三步：**统一 Memories 的浏览、搜索、筛选和列表展示**。

以 [Memories 设计包](../../design/remember-me-memory-ui-package/README.md)的文字规范为主、三张图片为视觉参考，复用现有主题、桌面布局及原生 ES Modules。保持现有 MCP 行为，不引入前端框架。

本轮不重新设计详情、编辑、删除；保留已有能力。收藏、网格视图及图片中的其他菜单不纳入范围。

本计划属于 [前端路线图](50-frontend-refactoring-and-ui-roadmap.md)中第二阶段的 Memories 专项，不是路线图第三阶段的结构复核。

先形成可执行的详细设计，再修改代码。

- 明确列表标题、摘要、标签、Namespace 和时间的字段映射及缺失值回退，避免标题与摘要重复。
- 列出 List／Search 的筛选、排序、总数和分页能力差距。区分浏览的完整结果总数与搜索的 Top-K 结果数量，禁止把截断结果当作全量命中数。
- 确定最小必要的 Admin API 扩展及兼容方案；优先复用已有关键词查询接口，不修改 MCP 协议。
- 明确现有 Search 页的 Top-K、阈值、更新时间过滤等功能如何迁移；移除独立 Search 导航之前完成迁移。

**交付与验收：** 功能迁移表、接口能力表、状态与交互规则、具体文件边界及测试清单。接口和产品语义未闭合前，不进入完整实现。

## 第二步：打通浏览列表

对应 3.2 子阶段，详见 [50.5.2 浏览列表计划与实施记录](50.5.2-memories-browse-list.md)。已完成，隔离回归、实际服务只读验证与截图检查通过，review 问题已处理。

完成一个可使用、可单独验收的浏览版本。

- 建立 Memories 内部的状态、数据请求、筛选控件和列表渲染职责边界，避免再次集中到一个大文件。
- 实现页面标题、浏览控件、结果栏及紧凑列表行，接入真实 List 数据；搜索区域随第四步统一搜索一起上线。
- 完成服务端支持的排序、总数、分页与每页数量；不以当前页的局部排序冒充全局排序。
- 实现加载骨架、空数据、请求失败与重试。
- 行点击连接现有详情能力，保留现有编辑删除的可达入口，不放置无反馈的占位按钮。

**验收：** 无搜索条件时可正常浏览；长内容和标签溢出可控；切页、排序及错误恢复正确；浅色、深色均可用。

## 第三步：接入共用筛选

执行计划及记录见 [50.5.3 共用筛选](50.5.3-memories-common-filters.md)。

- Namespace 单选，Categories 可搜索多选。
- Keywords 使用远程搜索添加，不预加载整个词库；闭合态展示少量选中项及溢出数量。
- 不同维度 AND，同一维度 OR；筛选变化回到第一页。
- Namespace／Categories 变化更新候选建议，保留已选条件；确需失效处理时明确提示。
- Reset 只清除筛选，不清除搜索内容。
- 补齐键盘操作、弹层关闭、焦点管理及请求竞态保护。

**验收：** 筛选结果与后端语义一致；快速切换条件时旧响应不能覆盖新结果；候选加载失败不丢失选择。

## 第四步：合并搜索与完成迁移

详细执行计划见 [50.5.4 统一搜索与迁移](50.5.4-memories-unified-search.md)，已完成，独立 review、隔离回归及实际服务验证通过。

- 区分正在输入的 `inputQuery` 与驱动结果的 `submittedQuery`。
- Enter／Search 提交后搜索；清空输入立即返回浏览，保留筛选。
- 搜索与浏览复用列表展示，搜索分数仅作为辅助信息。
- 按第一步确定的契约实现搜索排序、结果数量及分页。
- 将 Keywords 的记忆跳转改为打开 Memories 并设置精确筛选。
- 迁移完现有 Search 功能后，移除独立导航、旧页面和失效绑定。
- 全局 Refresh 与记录变更刷新当前查询，保留用户工作上下文。

**验收：** 输入未提交不触发搜索；模式切换和跨页跳转正确；现有功能无意外丢失。
