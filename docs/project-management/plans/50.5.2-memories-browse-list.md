## 1. 范围与阶段边界

## 2. 后端：提供准确的分页接口

新增 `GET /api/memories/page`：

| 参数 | 规则 |
|---|---|
| `namespace` | 省略表示全部；遵循现有 Namespace 校验 |
| `limit` | 默认 20，允许 10／20／50 |
| `offset` | 默认 0，非负整数 |
| `sort_by` | `updated_at` 或 `created_at`，默认前者 |
| `keywords`、`categories` | 重复参数表示多值，同维度 OR、跨维度 AND |
| `updated_after`、`updated_before` | 可选时间范围，沿用浏览查询语义 |

返回 `{items, total}`，其中 `total` 是相同筛选条件下的完整记录数；超过末页返回空数组和准确总数。

实现要求：

- Admin 负责解析参数及错误映射，通过 Service 调用 Storage。
- 新增分页查询契约，由 SQLite 实现、DualStorage 委托。
- 计数和取页在同一个数据库读取快照中完成，共用筛选条件构造。
- 排序按真实时间降序、ID 升序；更新时间缺失／非法时回退有效创建时间，无有效时间置末。时间过滤仍针对更新时间，不使用创建时间回退。细则见 3.1。
- 新路由注册在 `/api/memories/{id}` 前。
- 保持原列表接口的数组响应，供现有 Search 页面继续使用。

## 3. 前端：模块与页面实现

明确三个模块的职责：

| 模块 | 职责 |
|---|---|
| `memories.js` | 初始化、事件协调、跨模块回调、Refresh 和记录变更响应 |
| `memories-data.js` | 查询状态、分页请求、请求版本、结果及错误状态 |
| `memories-list.js` | 列表行、分页、加载／空／错误状态的展示 |

页面结构依次为：

1. Memories 标题及低强调的 Clear Namespace 入口。
2. Namespace 单选。
3. 结果数量及排序。
4. 紧凑列表。
5. 当前范围、页码、上一页／下一页及每页数量。

列表行采用以下规则：

- 主行显示 summary，缺失时使用现有 `deriveSummary()`。
- 次行按 3.1 的前缀去重规则显示正文预览；去重后为空时省略。
- Categories 优先、Keywords 补充，最多三个标签，剩余显示 `+N`。
- Namespace 单独显示，右侧展示更新时间。
- 文本安全渲染，长内容单行省略，标签不换行。
- 行通过鼠标或键盘打开详情；由 `main.js` 注入详情回调。
- 详情模块增加按 ID 打开的导出入口，旧表格绑定继续供 Search 使用。

复用现有主题变量和 Shell，列表标准行高控制在设计建议的 72–96px 内。

## 4. 状态与刷新行为

- 初始状态：全部 Namespace、更新时间降序、第一页、每页 20 条。
- Namespace、排序或每页数量变化时回到第一页。
- 页面切换保留本次会话的查询状态；本阶段不新增 URL 或本地持久化。
- 加载时保留控件，结果区显示骨架并设置忙碌状态。
- 快速连续操作以最后一次请求为准，旧响应不能覆盖新结果。
- 请求失败保留查询条件，结果区提供 Retry。
- 全部范围为空显示“暂无记忆”；指定范围为空显示“当前范围没有记忆”。
- Refresh 和增删改后刷新当前条件；当前页超过末页时回退并重新取页。
- Namespace 消失时保留选择并提示错误，提供返回全部范围的操作。
- Clear Namespace 继续跳转 Ops 并预选命名空间，沿用现有可用性规则。
