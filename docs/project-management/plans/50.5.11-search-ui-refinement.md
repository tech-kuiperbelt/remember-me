## 实施

- 主栏统一 40px 高、8px 间距。宽屏顺序为模式＋输入框、Search、Clear search、Namespace、Categories、Keywords、Advanced；模式＋输入框目标宽度 480px，可缩至 320px，整体靠左，搜索操作组与筛选组之间留 24px；模式保留 112px 宽及箭头间距，输入区域增加装饰性放大镜 SVG。Namespace 最大宽度 220px。
- 按 Memories 容器实际宽度响应：至少 1200px 时同行；低于 1200px 时搜索与按钮在第一行、筛选和 Advanced 在第二行；低于 640px 时输入框独占一行、操作按钮及筛选分别换行。已选标签、移除按钮、溢出入口及 Reset 保留；宽屏按完整筛选区的自然单行宽度判断：搜索框可缩至 320px，仍放不下时整组移到下一行；选中标签本身不再触发换行。语义主题变量与局部选择器沿用，未改共享详情筛选样式。
- Advanced 由原生 details 改为带 `aria-expanded`／`aria-controls` 的按钮和隐藏面板，保留既有字段 ID 与独立表单。滑杆 SVG＋文案＋状态箭头作为入口；展开参与文档流，向下推动列表。五个控件及帮助／错误文字完整保留，参数宽屏同行，低于 900px／640px 分组换行。
- 收起面板不清空或应用草稿，不发请求；面板内焦点在收起时回到入口。校验错误仍自动展开并聚焦首个错误字段。日期仍使用原生 datetime-local 和日历图标。
- 搜索按钮通过 `form` 关联原搜索表单，避免与 Advanced 嵌套。既有模式切换、IME、查询与参数草稿、Clear、筛选、Apply、Sort、新建和 Debug 逻辑保留；无接口、请求参数或数据结构变更。
- 数量／Sort／加号继续使用独立结果工具栏，保留与首卡片 10px 间距。

应用改动：`web/index.html`、`web/static/app.css`、`web/static/js/memories-search.js`，以及 `memories-search-layout.js`、列表装配和共享筛选组件的定位接口。浏览器测试改用展开按钮，增加真实键盘及布局断言。

## 搜索分组反馈

2026-10-09 用户认为宽屏输入框过长，并要求 Search／Clear 紧跟输入框，与其余控件略作分隔。已按确认计划限制宽屏组合搜索框在 320–480px，组内间距 8px，Clear → Namespace 间距 24px；其余空间留在右侧，中窄屏布局继续自适应且不保留额外横向分组间距。DOM 与键盘顺序同步调整。最终搜索功能、10 项明暗布局及 4 项真实缩放复验通过，1920px Light 额外核对真实 Enter／Tab。用户已授权提交，随本次提交归档。

## 按实际空间整组换行

2026-10-09 用户要求有空间就同行，放不下才让全部过滤一起换行，换行后的布局沿用当前样式。已移除按已选标签存在与否的 `:has` 强制换行规则。

- 新增搜索布局组件，在不带重复 ID、不可交互且不可见的临时副本中测量完整筛选区自然宽度，包含已选标签与 Reset。结合容器宽度、操作按钮和间距计算同行条件；宽屏搜索框在 320–480px 间调整，仍不足则整组换行。测量副本随测随移除，避免当前布局反过来影响结果。
- ResizeObserver、筛选区 MutationObserver 和字体加载通知触发重算，requestAnimationFrame 合并更新；隐藏时跳过，恢复后重算。布局变化调用筛选组件的 reposition，仅更新菜单位置，不改变选择、焦点或请求。
- 换行后 Advanced 保持上方，完整筛选区使用下一行；区内空间仍不足时沿用内部折行。操作按钮保持单行，避免 Clear search 被挤成两行导致阈值变化。
- 最终搜索功能、动态换行专项、10 项明暗宽窄布局及 4 项真实缩放共 16 项通过。专项覆盖短分类同行、长标签整组换行、菜单保持与定位、Reset 恢复、临界宽度上下 2px、扩大恢复和稳定性，以及无重复测量 ID。早期短标签夹具未达到实际换行阈值，改为确定长标签；临界检查发现 Clear 文案折行影响测量，固定按钮单行后复验通过。
