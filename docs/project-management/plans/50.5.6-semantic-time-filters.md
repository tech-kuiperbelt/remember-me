# [50.5.6] Memories 浏览与语义搜索共用时间过滤

2026-10-02。状态：实施及重启后验证完成。代码尚未提交。

## 1. 问题与范围

Updated after／Updated before 原来只作用于 Browse，进入 Search 后禁用。统一工作区却无法组合“某段时间内的某个概念”，筛选语义不一致。本次让时间范围同时作用于 Browse、Admin 语义搜索及 MCP `search_semantic`。

不增加检索模式、数据库字段、索引迁移或新 MCP 工具；不扩展 lexical／anchor 检索。本次同时保留此前已调整的 Advanced 紧凑布局、Apply 对齐和“最低相似度”标签。

## 2. 后端契约

| 项目 | 规则 |
|---|---|
| 参数 | `updated_after`、`updated_before`，可选；省略、null、空白代表无该边界。MCP schema 的非空参数为 string |
| 时间格式 | 带时区 ISO 8601，支持 Z；归一化为 UTC，保留微秒 |
| 边界 | 更新时间严格大于 after、严格小于 before；双边界须 after < before |
| 历史数据 | 存储中无时区时间按 UTC 解释；缺失／非法更新时间在有边界时排除，不用创建时间补足 |
| 组合 | 时间、Namespace、Keywords、Categories 之间 AND；各索引维度内部仍 OR |
| 执行顺序 | 先校验边界，再解析维度／嵌入查询；SQLite 先筛候选，再 cosine、threshold、Top-K |
| 兼容 | 不传时间维持既有行为；Admin 数组／映射信封不变；MCP 搜索信封、search_id、report 及审计链路保留 |
| 错误 | 复用 InvalidSearchFilter；Admin 返回 400 invalid_request；MCP 沿用既有工具执行错误通道 |

Browse 与语义搜索复用 domain 时间校验和 SQLite UTC 整数微秒谓词，不使用会舍入微秒的 julianday。关键词／分类语义解析的词表仍由维度与 Namespace 限定；解析结果与时间条件共同筛选记忆，不改解析语义。

## 3. 前端交互矩阵

| 操作 | 日期与请求 |
|---|---|
| 修改日期 | 只改草稿；两种模式均可编辑 |
| Search／搜索框 Enter | 非空查询时校验并原子应用查询、Top-K、最低相似度及日期草稿，发一次搜索 |
| Search 中 Apply／高级字段 Enter | 应用搜索参数及日期草稿，继续使用已提交查询，不提交查询草稿 |
| Browse 中 Apply | 只应用日期草稿，发一次浏览；不提交查询草稿 |
| 无效日期／范围 | 展开高级区、字段报错并聚焦；不请求、不改变已应用条件 |
| 共用筛选／Refresh／Retry | 使用已应用日期，保留日期草稿 |
| 清空查询返回 Browse | 保留已应用日期和草稿，不自动应用草稿 |
| Reset／空结果 Clear filters | 清除日期已应用值与草稿，刷新当前模式；保留已提交查询与搜索参数 |
| Keywords 精确跳转 | 沿用既有规则，清日期、查询与旧筛选后进入 Browse |
| 并发响应 | 使用既有版本保护；旧时间窗口的成功／错误不得覆盖新窗口 |

日期提示为“浏览与搜索均生效”；Top-K／最低相似度仍“仅搜索时生效”。保留现有控件 ID、Debug 标注、主题和桌面分辨率规则。搜索空结果若有时间条件，提供 Clear filters。

## 6. 后续修复：search_meta 时间过滤一致性

2026-10-02，经用户确认，修复既有 `search_meta` 路径的时间过滤差异。这是原 50.5.6 范围之外的独立行为修正。

`MemoryService.memory_list` 复用 `normalize_updated_range`；`SQLiteStorage.list_memories` 复用同一 UTC 整数微秒候选谓词。相同的时间边界现在在 search_meta、search_semantic 与 Browse 中得到一致的候选集合，支持不同时区表示、微秒严格边界及单边界。MCP 说明、golden fixture、read-me 和架构说明同步更新。

兼容变化：search_meta 与旧 GET /api/memories 接口现在拒绝无时区、非法类型／时间和 after >= before；省略、null、空白仍表示无边界。有时间限制时，无效／缺失的历史更新时间被排除，无时区的历史存储时间按 UTC 解释。旧 Admin 列表将校验失败映射为 400 invalid_request，MCP 沿用既有工具错误通道。

新增 15 项回归在修复前全部失败、修复后全部通过；覆盖与分页及语义候选一致性、偏移等价、微秒边界、非法参数在访问存储前拒绝、空白兼容、MCP search_id／report／审计及旧 Admin 列表响应。Python 全量 **789/789** 通过（7 项既有依赖弃用警告）。本次后续修复需要再次重启服务加载，实际进程验证待重启后进行。代码尚未提交。
