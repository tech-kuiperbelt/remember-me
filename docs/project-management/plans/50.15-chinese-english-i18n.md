## 1. 目标与文案原则

Remember Me 管理界面支持简体中文（`zh-CN`）与英文（`en`）。中文环境优先使用自然、明确的中文，英文环境提供完整且一致的英文表达。

- 菜单、按钮、字段、说明、反馈、确认弹窗和无障碍名称采用当前语言。
- MCP、JSONL、HTTP、BM25、SQLite、产品名、代码符号和协议字段保留原名。
- 用户记忆的正文、摘要、分组名、分类值、关键词、锚点和自定义元数据保留原文。
- 英文品牌介绍保持已确认中文文案的含义和语气，不额外添加功能承诺。
- 使用完整句子和参数占位符表达动态消息，避免拼接碎片造成语序、量词或单复数问题。

## 3. 语言选择与生效方式

### 3.1 配置是唯一来源

- 继续使用现有 `language` 字段和 `GET/POST /api/config`。
- 语言属于当前 Remember Me 服务的共享配置；不同浏览器刷新后使用同一设置。
- 默认中文，不通过浏览器语言、URL 参数或 localStorage 自动覆盖配置。
- 语言选择器始终显示 `中文` 和 `English`，方便用户切回熟悉的语言。

### 3.2 保存后刷新页面生效

1. 用户在“配置 → 常规设置 → 语言”中选择语言。
2. 点击“保存配置”；保存成功前，当前界面语言不变。
3. 保存成功且新语言不同于当前页面语言时，显示“语言设置已保存，刷新页面后生效”及“刷新页面”按钮。
4. 用户主动刷新后，页面首屏和后续动态内容使用新语言。
5. 刷新按钮发现配置表单又有未保存修改时，确认是否放弃修改；沿用现有编辑草稿保护。

语言变化无需重启服务。端口与访问范围仍按照各自的生效规则提示重启；语言从重启提示的字段清单中移除。保存失败保留语言草稿和当前界面，不显示成功提示。

刷新前，当前页面继续统一使用原语言，后台轮询也使用原语言，避免页面中途混用两套文案。其他已打开页面同样在下次刷新时采用新语言。

## 6. 技术方案

### 6.1 集中语言资源

- 使用现有原生 JavaScript 与 Python，不新增前端框架、构建工具或翻译服务依赖。
- 在 `web/static/locales/` 维护中文和英文资源，采用稳定的语义键，例如 `nav.memories`、`memory.delete.confirm`、`config.language.saved`。
- 两种语言的键集合和占位符保持一致。修改措辞时保留语义键。
- 新增 `web/static/js/i18n.js`，提供 `t(key, params)` 和当前 locale。
- 参数只插入一次，作为普通数据处理；不再次当作翻译键或模板解析。
- 服务端和前端使用相同查找顺序：当前语言 → 中文 → 语义键。前端注入数据必须包含实际中文回退词条，仅包含备用语言名称不足以实现回退。
- 对已接入的键，验证时将缺失键视为失败；运行时回退用于容错，不代替资源完整性检查。

第一阶段确立语义键规则，不以原始文案查找翻译。修改中文措辞不会改变英文映射，相同原文在不同上下文中也可以使用独立译法。

### 6.2 静态首屏与动态文案共用资源

- 静态模板用显式翻译标记声明需要翻译的节点与属性，例如 `data-i18n`、`data-i18n-placeholder`、`data-i18n-title`、`data-i18n-aria-label`。
- 服务端在现有控制线程中读取已保存语言，翻译固定模板，输出正确的 `<html lang>`。
- 页面首屏直接使用目标语言，避免加载后由中文整页闪换成英文。
- 服务端将本页使用的语言资源安全嵌入非执行 JSON 节点，JavaScript 模块初始化时读取，不额外发起语言资源请求。
- 保持主题首屏初始化与 favicon 逻辑顺序，词表注入不能干扰现有主题启动。
- 动态消息在生成位置显式调用翻译函数；不扫描或替换用户内容所在的 DOM。
- 带链接、强调文本和图标的文案保留结构，分别标记文本片段；不通过翻译一个父节点覆盖其子节点。
- 翻译默认作为文本写入。JSON 注入处理 `</script>` 等边界；已有 HTML 拼装继续转义插入值。

### 6.3 按钮、文本与标签的统一接入方案

| 内容类型 | 接入方式 | 需要保护的行为 |
| --- | --- | --- |
| 纯文本按钮 | 在文字节点或纯文本按钮上声明 `data-i18n="common.save"` | 点击事件、disabled 和按钮 ID 使用固定标识 |
| 图标与文字按钮 | 保留 SVG，将文字放入带翻译标记的独立 `span` | 不替换整个按钮内容，图标与事件继续有效 |
| 普通 text、标题、说明 | 用 `data-i18n` 标记专门承载文本的节点 | 不遍历或替换用户记忆内容 |
| 表单 label | 在 label 的文字节点上标记，保留 `for` | 输入框 ID、关联、必填标记与错误关联保持有效 |
| placeholder、title、aria-label | 使用对应的显式属性翻译标记 | 可见文案与辅助技术提示使用同一语言 |
| select / option | 翻译 option 显示文本 | `value` 继续使用协议枚举；语言选项使用各语言自己的名称 |
| 动态按钮、文本、校验提示 | 渲染时调用 `t(key, params)`，以 `textContent` 或文本节点写入 | 用户参数只插值一次，不翻译参数内容 |
| 含链接或强调的富文本 | 由代码维护结构，标记独立完整文本；参数允许译文调整语序 | 不提供任意翻译 HTML 执行入口，链接目标由代码控制 |
| 数字、时间和数量 | 提供共用 locale 格式化与完整消息模板方案 | API 值、时区和计算逻辑使用原有规则 |

第一阶段以配置语言区域为主要接入样例，补充一个带图标按钮、label、placeholder/aria-label 和动态参数消息的实际样例。样例放在已有功能中，不增加面向用户的演示页面。其余控件在第二阶段按同一规范接入。

静态标记由服务端在页面加载时处理；动态节点在生成时显式调用翻译函数。当前切换模型是保存后刷新，不额外引入全页面实时重绘、DOM 观察器或后台自动翻译。

### 6.4 展示文本与程序标识分离

重点检查当前根据英文标签生成程序标识的位置：

- 统计卡片的 `data-metric` 与图标 key。
- 详情的创建时间、更新时间节点 ID。
- 分类、关键词、锚点字段的图标选择。
- 检索模式值、配置枚举、工具名称与事件状态。

这些标识使用固定内部值，翻译只作用于显示文字。DOM ID、CSS 选择器、事件绑定、API 参数和测试定位不依赖译文。

### 6.5 数字、时间与动态句子

- 面向用户的日期、时间和数字采用所选语言对应的 `Intl` 格式。
- 保留现有时区、时间筛选边界和传给 API 的 ISO 格式。
- 技术详情中的原始 ISO 时间、审计 JSON、ID、路径和模型名称保留原值。
- 数量消息采用完整模板，处理英文单复数或采用自然的数量标签表达。
- 保留搜索得分、百分比和评分的数值语义，语言切换不改变计算与排序。

### 6.6 错误与诊断

- 前端校验、网络失败和业务状态提示提供两种语言。
- 对已有稳定 `response_code` 的常见错误，在前端给出对应语言的说明，继续保留完整错误 payload 供处理。
- 原始服务、模型和第三方错误保留为诊断详情，外围提示使用当前语言，不机械替换错误文本中的标识符或用户数据。
- 不为翻译改变 HTTP 状态、错误码、重试行为或确认码契约。

### 6.7 Help 与复制内容（第二阶段）

- Help 所有主题纳入语言资源，长段落和完整记忆规则使用独立的语义键。
- 复制内容来自当前语言的渲染结果，连接地址继续取实际服务 origin。
- 保留工具名、指令文件名、协议路径、命令和外部链接。
- 《西部世界》引文：中文显示中文意译、英文原文与出处；英文只显示英文原文与出处，避免重复引用同一句话。
- 同步更新“语言尚未应用翻译”等过时说明。

## 8. 执行步骤

### 第一阶段：框架、切换与接入机制

1. **核对现有实现**：检查资源结构、语义键、首屏注入、前端查找和语言配置，确认可复用部分。
2. **统一资源契约**：确定 `t(key, params)`、中文回退、参数插值、数字日期格式化与缺失键检查；服务器和浏览器行为一致。
3. **打通语言切换**：保存成功后提示刷新；语言不进入 `restartKeys`；失败保留草稿；刷新前保护未保存修改。
4. **完善静态和动态接入**：按第 6.3 节落实按钮、text、label、属性、option 和带参数提示的实际样例。
5. **处理两条框架审查意见**：修复语言保存后错误提示重启的问题；补齐前端实际中文回退词表和查找顺序。
6. **验证并记录**：对框架做专项验证，检查已接入页面的兼容性，形成可供第二阶段使用的接入规范。

交付：可运行的 i18n 机制、可验证的语言切换链路、控件接入样例、资源维护说明和框架验收记录。

第一阶段验收通过后单独收尾；全站翻译覆盖率不属于本阶段的完成条件。

### 第二阶段：具体页面与文案

第一阶段完成后，再确定需要处理的页面与顺序。候选范围见第 4 节，工作包括文案提取、中文措辞整理、英文翻译、动态状态覆盖、Help 长文与复制内容、双语布局调整及页面验收。

交付：按确认顺序逐页完成的双语页面与回归记录。具体翻译和批量页面迁移暂缓。

## 9. 验证与验收标准

### 9.1 第一阶段：配置与资源

- 默认中文；中文与英文分别保存、刷新后生效；非法语言继续被拒绝。
- 新页面首屏语言正确，`<html lang>` 与动态消息一致。
- 语言保存保留 JSONC 注释；写入失败保持已保存语言不变。
- 语言单独变化不提示重启；与端口一起变化时只提示端口需要重启。
- 缺失键、缺失语言和占位符不一致能在验证阶段被发现。
- 用户插入值包含 `{name}`、HTML 字符或 `</script>` 时，不发生二次插值或脚本执行。

### 9.2 第一阶段：控件接入与兼容性

- 按钮文本、图标按钮、label、placeholder、title、aria-label 和 option 在两种语言下按约定渲染。
- 图标、label 与输入关联、焦点、点击处理和选项 value 不因翻译改变。
- 静态首屏与随后生成的动态提示采用同一 locale；刷新前后台轮询仍使用当前页面语言。
- 人为移除英文条目后，前端和服务端均返回中文；两者均缺失时才返回语义键。

### 第一阶段必须修正的问题

1. **P2：译文文本和属性转义不完整。** `ui_i18n.py` 的 `handle_data` 将译文直接输出为 HTML。例如 `<project namespace>` 会成为标签而不是文字；`_set_attr` 只处理双引号，译文中的 `&lt;literal&gt;` 会被浏览器再次解码。应按文本与属性上下文分别转义，保证词条按字面值显示。
2. **P2：同一节点可能重复翻译。** 标记节点中的 `A &amp; B` 被解析成多个片段，当前每个非空文本片段都会输出完整译文，实际得到 `Translated&amp;Translated`。应以标记节点为单位只替换一次，正确处理原文本中的实体与注释。
3. **P2：空节点和含子控件节点缺少明确处理规则。** `<span data-i18n="x"></span>` 不会填入译文；`input` 等 void 元素被压入普通元素栈，而结束标签仅无条件弹栈，包含 input 的标记 label 会漏译。应正确维护 HTML 元素层级并支持空文本容器；混合图标/输入/文本的控件优先使用独立文本 span，并明确校验不支持的标记方式，避免静默错误。

上述问题均用独立的最小模板实际复现，共 5 个失败场景（文本转义、属性转义、实体拆分、空节点、label 内的 input）。这些问题属于框架机制，不以第二阶段页面翻译覆盖率为依据。
