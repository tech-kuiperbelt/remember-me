## 4. 桌面视觉与缩放口径

以 `window.innerWidth >= 1024` CSS px 为验收下限，不以屏幕物理像素判定。不要求 Pad／手机。100%、125%、150% 指浏览器页面缩放，不能以 `deviceScaleFactor` 代替。

| 矩阵 | 组合数 | 内容 |
|---|---:|---|
| 桌面布局 | 24 | 1024×768、1440×900、1920×1080 CSS 视口 × Light／Dark × 侧栏展开／折叠 × Browse Advanced／Search 映射 |
| 筛选弹层 | 4 | 1024×768 × Light／Dark × Categories／20 个已选 Keywords |
| 页面缩放 | 12 | 1920×1080 基准内容区域 × 100%／125%／150% × Light／Dark × Browse／Search；等效 CSS 视口约 1920×1080、1536×864、1280×720 |
| 原有回归 | 35 | 原有功能、主题、Shell、筛选和搜索；原有 @1.25／@1.5 标签表示 DPR，不是页面缩放 |

完整 runner 共 75 个场景。新矩阵使用隔离 Chrome profile 的页面缩放偏好，设备缩放保持 1，检查实测 DPR 和 CSS 宽度；校正浏览器窗口装饰所占高度，CSS 尺寸允许 2px 舍入误差。缺失视口指标或不符合目标尺寸均失败。

长标题、摘要、Namespace、20 个长标签、长搜索词和筛选映射不能造成横向溢出。搜索映射可能占用多行，需要纵向滚动；本阶段不增加折叠映射功能。弹层在视口内、内部内容无横向溢出；控件需可达。截图用于人工查看，几何检查在页面内执行，不把截图图片像素当作 CSS 视口。Chrome 命令行截图阶段会改变视口，可能触发既有 resize 关闭弹层；因此弹层几何断言在截图前执行，另保留实际服务 1024×768 的 live-categories-1024.png 与 live-keywords-1024.png 作为展开态截图。
