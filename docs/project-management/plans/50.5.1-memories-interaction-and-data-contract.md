## 2. 列表字段与展示

列表与搜索结果使用同一种行结构，72–96px 标准行高，信息依次为主行、正文预览、元数据，右侧为时间及搜索分数。

| 展示位置 | 数据规则 |
|---|---|
| 主行 | trim 后非空 summary 优先，否则使用 core.js 的 deriveSummary(text)；仍为空显示“空内容记忆” |
| 次行 | 正文压缩空白后的预览，最多取 256 个 Unicode 字符；规则见下文 |
| 分类标签 | metadata.categories 中的非空字符串，按既有类别规则 trim／lowercase／去重，保持顺序 |
| 关键词标签 | metadata.keywords 中的非空字符串，trim／lowercase／去重，保持顺序 |
| 标签溢出 | Categories 优先、Keywords 补充，最多展示 3 个；按“维度＋值”计数，剩余显示 +N |
| Namespace | 独立文本／徽标，不占用三个标签名额 |
| 时间 | 有效 updated_at 优先，否则有效 created_at，否则显示 — |
| 检索上下文 | 仅 Search 显示 String(score) 原始分数，标注 Semantic／FTS／Anchor；不转换成概率 |

主行与正文都将连续空白合并成一个空格。为避免重复，先从主行末尾去掉 deriveSummary 的截断省略号：正文若以该非空文本开头，次行使用去掉这一前缀的剩余正文；否则使用完整正文预览。去掉前缀后的内容为空时省略次行。处理只影响显示，不写回数据。整行高度保持一致。

主行和次行单行省略，标签不换行。原始字符串通过 textContent 或现有安全转义渲染。主行完整值可通过 title 查看，行的可访问名称包含主行；时间 title 提供本地完整日期时间。相对时间按不足 1 分钟“刚刚”、分钟／小时／天向下取整，7 天起显示本地日期；未来时间显示完整日期。刷新或重新渲染时更新时间，不新增全局定时器。

标签是信息展示，不点击施加过滤。+N 使用可聚焦按钮，点击／Enter／Space 打开全部标签的小弹层，Escape 或点击外部关闭并恢复触发按钮焦点。没有溢出不显示按钮。整行的详情触发排除弹层和标签按钮事件。

## 3. API、业务与存储契约

### 3.1 浏览分页

新增 GET /api/memories/page，返回对象；原 GET /api/memories 保持数组响应和原有参数行为。

| 参数 | 默认及校验 |
|---|---|
| namespace | 省略／空白表示全部；非空遵循现有格式、大小写及已知 Namespace 校验 |
| limit | 默认 20，仅允许十进制整数 10、20、50 |
| offset | 默认 0，范围 0 至 2^63−1 的十进制整数，不允许小数或负数 |
| sort_by | 默认 updated_at，仅允许 updated_at、created_at |
| keywords、categories | 重复参数为多值，不按逗号分割；trim／lowercase／去重，空值忽略；规范化后每维最多 20 个 |
| updated_after、updated_before | 省略／空白表示无边界；非空须为带时区的 ISO 8601 时间，接受 Z；双边界必须 after < before |

标量参数重复出现、未知参数或不符合以上规则，返回 HTTP 400 / response_code=invalid_request，附 detail 及 response_meta.reason。Namespace 格式错误为 invalid_namespace；未知 Namespace 为 namespace_not_found，沿用 requested_namespace／known_namespaces 元数据。内部异常沿用现有 HTTP 500 响应，不能把所有 ValueError 一律当作请求错误。

成功响应：
```json
{"items": [], "total": 0}
```

items 是现有 memory_list 相同的记录形状，保留正文和 summary；去掉 embedding／deleted／synced／version。total 是筛选后、分页前的存活记录总数，为非负整数。越界 offset 返回空 items 与准确 total。全部范围的 total 不依赖 Stats；Stats 不用于估算分页总数。

过滤语义：Namespace 与各维度 AND，关键词维度内 OR，类别维度内 OR；浏览仅精确匹配。时间条件针对有效 updated_at，after 为严格大于、before 为严格小于，不用创建时间补足时间过滤。

新增 Service.memory_list_page 与 MemoryStorage.list_memories_page，使用一致签名：

```python
def memory_list_page(self, namespace=None, limit=20, offset=0,
                     sort_by="updated_at", updated_after=None,
                     updated_before=None, keywords=None, categories=None): ...
# Storage 使用同样的参数，方法名为 list_memories_page，返回 {items, total}。
```

Service 负责业务规范化及 Namespace 校验，对非 Namespace 的无效查询参数使用现有 InvalidSearchFilter，沿用其 invalid_request HTTP 映射；不得引入 Service 对 transport.InvalidRequest 的依赖。Admin 先检查原始参数的重复／未知字段及整数格式，用 InvalidRequest 报解析错误，再经 _run 进入既有业务线程池调用 Service。Storage 负责 SQL 查询。分页路由声明 read 策略，注册在动态 memory_id 路由前。

SQLite 在既有 RLock 内使用一次读事务／SAVEPOINT 执行 COUNT 和取页，确保同一个读取快照；异常回滚本次 SAVEPOINT，不提交或回滚调用者已有事务。筛选条件构造共用一个内部函数，COUNT／取页不能复制不同版本的 WHERE。DualStorage 委托 primary，Replica 不增加业务查询。

排序比较真实时间（通过 SQLite 自定义函数转换为 UTC 整数微秒，保留微秒精度并支持不同时区的历史时间；历史无时区时间按 UTC 解释）：updated_at 排序采用有效更新时间，否则有效创建时间；created_at 排序采用有效创建时间。无有效时间置末，时间降序，id 升序打破平局。更新时间范围使用同一微秒比较规则。读操作不迁移历史数据。原数组接口沿用原行为；新排序规则只约束分页接口。

增加抽象分页契约时同步更新所有 MemoryStorage 测试替身及契约覆盖。无需 DB schema 迁移或向 MCP 添加工具。

### 3.2 搜索与实际筛选映射（3.4 实现）

继续使用 POST /api/memories/search。工作区请求传入 query、k、threshold、namespace、keywords、categories，以及新增可选布尔 include_resolution=true。旧请求省略／false 时仍返回数组；true 时调用既有 Service.memory_search(return_resolution=True)，返回：
```json
{"items": [], "filter_resolution": null}
```

filter_resolution 有筛选时使用现有 resolver 的 config／keywords／categories 结构；每项包含 input、match_type（exact／semantic／none）、matches。include_resolution 非布尔值返回 invalid_request。此扩展不改变现有 resolver 的排名、阈值或 Namespace 处理。

工作区 Top-K 默认 10，整数范围 1–100；threshold 默认 0，有限数字范围 0–1。输入无效在前端阻止提交，显示字段错误；不改变旧调用的既有 k 校正规则。查询 trim 后为空使用浏览接口。

搜索保留“精确优先、未匹配值近义解析”的后端语义，不把 Browse 的精确匹配行为当作搜索承诺。只有 semantic／none 项才在结果数量下方显示说明：如“关键词：locking → optimistic-lock”；没有可接受映射显示“关键词 locking 未找到匹配值”。不改动选中项、不回写记忆，不显示精确命中项。映射说明使用文本并具备礼貌的状态播报。

返回数组是完整的本次 Top-K 集合，前端保存后分页。数量文案为“本次搜索 N 条 · 最多 K 条”，不声称全部命中数。三模式搜索固定保持 API 相关性顺序，排序控件只显示 Relevance 并禁用。切页、调整每页数量在完整 Top-K 集合本地分页，不重复调用搜索。

50.5.9 扩展：单选 Semantic／Lexical／Anchor。Semantic 使用上述信封；Lexical／Anchor 分别 POST `/api/memories/search/lexical`、`/api/memories/search/anchor`，返回数组。均发送 query、k、已应用公共筛选与时间范围；BM25 门槛为可选 `min_score`（有限非负，空白省略）。仅 Semantic 保存／展示 filter_resolution。结果分数以 `Semantic <score>`、`FTS <score>`、`Anchor <score>` 原样显示。详细交互及验收见 [50.5.9](50.5.9-memories-search-modes.md)。

### 3.3 前端统一结果

```text
MemoryResultPage {
  items: 当前页记录,
  total: 当前可分页集合数量,
  page: 从 1 开始,
  pageSize: 10 | 20 | 50,
  totalKind: "exact" | "top_k_results",
  filterResolution: null | resolver 结果
}
```

Browse 使用服务端 total，Search 使用保存集合的长度；Browse 的 filterResolution 恒为 null。请求状态独立为 idle／loading／ready／error，不能用 items 是否为空判断是否加载成功。

## 4. 状态与控件行为

默认全部 Namespace、无关键词／分类／时间条件、每页 20、页码 1、Browse 更新时间排序；Search 默认为 Semantic，三模式分别保存 Top-K（默认 10）及分数门槛（Semantic threshold=0；Lexical／Anchor minScore=null）。状态属于本次前端会话，不进入共享 store，不写 URL／localStorage。store 继续只承载现有跨页事件、Namespace／Categories／维护快照。

| 事件 | 状态变化 | 数据请求 |
|---|---|---|
| 输入非空查询 | 仅更新 inputQuery | 不请求 |
| Enter／Search | 校验高级搜索字段；submittedQuery=inputQuery.trim()；page=1 | 空词 Browse，否则 Search |
| 清空／输入仅空白 | 清空 inputQuery 和 submittedQuery；page=1，保留筛选 | 即时 Browse；已处于相同浏览条件时不重复请求 |
| 修改 Namespace／Categories／Keywords | 保留输入词及 submittedQuery；page=1 | 根据 submittedQuery 刷新当前模式 |
| 修改排序 | 保存 Browse 排序；page=1 | Browse 请求；Search 固定相关性且禁用排序控件 |
| 搜索模式切换 | 保留查询和各模式参数草稿 | 已提交查询非空时用目标已应用参数检索并重置第一页；否则零请求；同模式无操作 |
| 修改 pageSize | page=1 | Browse 请求；Search 本地切页 |
| 翻页 | 更新 page | Browse 请求；Search 本地切页 |
| Reset | Namespace=全部、分类／关键词／时间清空；page=1 | 保留搜索词、k／threshold／排序，刷新当前模式 |
| 高级选项 Apply | 校验并应用当前模式支持的字段；page=1 | 使用 submittedQuery，绝不提交未提交的输入词 |
| Retry／Refresh | 保留条件和页码 | 刷新当前模式 |
| 增删改通知 | 保留条件和页码 | 刷新当前模式；越界页回退 |
| 切离／返回页面 | 保留全部工作区状态 | 返回时刷新一次，事件绑定只执行一次 |

高级区域默认收起；时间范围在 Browse 和 Search 均可编辑并生效，k／threshold 仅搜索时生效。datetime-local 按浏览器本地时区转成 UTC ISO。Search／Enter 同时校验并应用日期草稿与搜索参数；Apply 应用当前模式参数及日期草稿，使用已提交查询，不隐式提交查询草稿。时间过滤在候选阶段、相似度排序及 Top-K 之前执行；详细扩展见 [50.5.6](50.5.6-semantic-time-filters.md)。

页码为 first／last／current±1 的去重集合，缺口显示不可交互省略号，上一页／下一页在边界禁用。页大小为 10／20／50；0 条时范围显示 0–0 of 0，无页码按钮。非空时显示 (page−1)×pageSize+1 至 min(page×pageSize,total)。

每个结果请求携带不可变条件快照与递增版本；只有最新版本能修改结果、映射、分页、错误和加载状态。条件变化立即替换结果为骨架，分页导航禁用；搜索／筛选控件保持可操作，可产生新的请求。不保留可点击的旧结果。返回超出末页时按最新 total 回退到 max(1,ceil(total/pageSize)) 并重新取页；最多纠正一次，再次越界显示可重试错误，避免数据持续变化造成循环。

全局 Refresh 保持 Stats 刷新并且仅调用一次 Memories.refresh。Stats 更新候选注册表只刷新控件选项，不额外触发结果查询。关闭详情／删除后焦点返回原行；原行已不存在则回到结果栏。历史页面显示期间继续使用其既有刷新行为。

## 5. 筛选与交互规则（3.3／3.4）

Namespace 单选候选来自 store 的现有列表，始终包含“全部”。候选更新时保留当前选择；选择已不在列表时显示临时“已不可用”项，保留后端错误，提供“返回全部范围”。

Categories 候选为 Stats.category_counts 键名（已经合并种子与实际值），按名称排序，本地不区分大小写搜索。首版不显示范围内计数、不因 Namespace 而裁剪分类。Stats 加载失败时显示重试状态，不擅自把候选失败当空词库。

Keywords 关闭态展示前两个选中项和 +N；无选中项显示 Keywords。打开后有搜索框、完整已选区域和建议列表。空输入不查询词库，提示“输入关键词查找”；非空 trim 输入延迟 250ms 请求 literal 查询，每次 limit=20，携带 Namespace 和已选 Categories，offset 从 0 开始，有更多时提供加载更多。

Namespace／Categories 变化重置建议 offset、刷新当前非空候选输入；不删除已选值。关键词建议与结果请求采用各自的版本标记。每维最多选择 20 项，到达上限禁用未选项并说明；仍允许取消选择。Categories／Keywords 值按既有 trim／lowercase 规则规范化。同值在不同维度分别计数。

类别弹层用原生 checkbox 与 label；关键词建议使用具有名称的添加按钮，已选项有移除按钮。弹层打开时聚焦搜索框，关闭时返回触发控件；Escape／点击外部关闭。筛选弹层采用对话框语义及正常 Tab 次序，不强行套用需要另一套键盘规则的 ARIA combobox。筛选选择立即生效，无另设 Apply；高级选项才使用 Apply。

加载只替换结果区；无筛选 Browse total=0 显示“暂无记忆”，其他空结果显示“当前搜索或筛选没有匹配的记忆”。Clear filters 只显示于有筛选时，执行 Reset；纯搜索无结果提供“清空搜索”。错误保留全部输入条件，显示 API detail 与 Retry；unknown Namespace 另提供返回全部范围。
