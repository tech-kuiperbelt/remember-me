## 一、明确列表展示与功能迁移

采用已确认的三个选择：

- **复用现有字段**：`summary` 作主行，正文预览作次行；没有 summary 时由正文派生主行，重复的次行省略。不新增 title。
- **Top-K 内分页**：搜索对返回的结果集合分页，明确提示受 Top-K 限制。
- **保留高级选项**：Top-K、阈值和时间过滤移入默认收起的高级区域。

形成字段映射表，确定以下规则：

- 主行与正文预览统一压缩空白，单行截断；完整内容通过现有详情查看。
- 元数据最多展示三个标签，Categories 优先、Keywords 补充，剩余数量显示 `+N`。Namespace 单独展示，方便跨命名空间浏览。
- 时间使用 `updated_at`，缺失时回退 `created_at`；显示相对时间，提示中提供完整时间。
- Browse 不显示分数；Search 显示次要的语义分数。

形成完整迁移表：

| 现有能力 | 目标位置 |
|---|---|
| Memories 列表与 Namespace tabs | 统一工作区及 Namespace 单选 |
| Search 语义搜索 | 顶部搜索框 |
| 精确查询 | 无搜索词时的浏览与共用筛选 |
| Top-K、阈值 | 高级选项，仅搜索时生效 |
| 更新时间范围 | 高级选项，仅浏览时生效；搜索时保留值并标注暂不生效 |
| Limit、Offset | 页码与每页数量 |
| View／Edit／Delete | 行点击打开现有详情，编辑删除继续从详情进入 |
| Clear Namespace | 保留跳转 Ops 的能力，放入低强调的工作区操作区 |
| Keywords 跳转 | 打开 Memories，清空搜索、设置 Namespace 和精确关键词筛选 |

## 二、明确 API 与结果契约

浏览和搜索分别使用真实数据能力，前端统一为 `items、total、page、pageSize、totalKind`。

- 浏览新增 `GET /api/memories/page`，接受 Namespace、Keywords、Categories、时间范围、排序、limit 和 offset，返回 `{items, total}`。计数与取页使用相同条件和一致的数据快照。
- 现有 `GET /api/memories` 保持数组响应；新增分页路径在动态 ID 路径之前注册，避免路由冲突。
- 浏览只提供“更新时间降序”和“创建时间降序”，默认更新时间；排序增加稳定的 ID 次序。暂不提供标题排序。
- 搜索复用现有 `POST /api/memories/search`，保留 Top-K、阈值及语义筛选行为。收到结果后前端分页，`totalKind` 为 `top_k_results`。
- 搜索默认按相关性排序；可在整个 Top-K 集合中按更新时间排序，明确这是当前搜索结果集的排序。
- Keywords 候选复用 `/api/keywords/query` 的 literal 模式，携带 Namespace、Categories，每次最多返回 20 项。
- Categories 首版采用现有规范词汇与 Stats 中实际出现值的并集，本地搜索；不承诺 Namespace 内的分类计数。

文档列出必要的 Service、Storage 契约扩展、DualStorage 委托和测试替身更新。新增能力通过业务层和存储层实现，Admin 不直接查询 SQLite。

## 三、明确状态、交互和模块职责

- 工作区拥有输入词、已提交词、筛选、高级选项、排序、页码、每页数量及请求状态。
- 非空输入只有 Enter／Search 才提交；清空立即回到浏览。筛选变化使用已提交词，不自动提交正在编辑的输入。
- Namespace、Categories、Keywords、查询和排序变化回到第一页；每页数量为 10／20／50，默认 20。
- Browse 与 Search 分别保留排序选择；Reset 清除 Namespace、Categories、Keywords 和时间范围，保留搜索词、Top-K 和阈值。
- 请求采用递增版本标记，过期响应不得覆盖当前结果；搜索翻页不重新执行语义检索。
- 全局 Refresh、记录变更刷新当前工作区；删除导致当前页超出范围时回退到最后有效页。
- 保留零计数或当前范围外的已选筛选，不静默移除；未知 Namespace 按现有错误语义提示，用户通过 Reset 返回全部范围。
- 行通过点击或键盘打开现有详情；详情模块暴露按 ID 打开的入口，不再依赖表格行结构。

模块边界确定为：Memories 入口负责协调，独立状态／请求模块负责数据，筛选模块负责候选及弹层，列表模块负责展示。跨页面回调仍由 `main.js` 装配；旧 Search 页在功能迁移完成后移除。

## 四、设计验收

文档必须能逐项判定以下场景：

- 有／无 summary、重复正文、多标签、缺失时间及特殊字符。
- 输入未提交、清空、筛选变化、Reset、模式切换及高级选项生效范围。
- 浏览完整计数、稳定排序、最后一页；搜索 Top-K 截断说明及集合内分页。
- 快速连续请求、候选失败、列表重试、删除后页码修正。
- Keywords 跳转、全局 Refresh、详情编辑删除、维护状态及 Clear Namespace 迁移。
- 键盘操作、浅色／深色、侧栏展开／折叠，以及 ≥1024 CSS px 桌面视口。

完成标准：迁移表无遗漏，API 与状态规则无待定项，所有验收场景都有预期结果。通过文档 review 后进入浏览列表实现。
