- 移除侧栏 Add Memory、`page-add`、旧 `add.js` 的挂载和路由注册；查找并迁移代码、浏览器测试及文档中的旧入口。未知／旧 add 路由安全返回 Memories，不自动创建记录。
- 新增、查看、编辑共用单个右侧模态抽屉，宽度沿用 `clamp(640px,60vw,1040px)`、最大 100vw。背景 inert、滚动和列表宽度保持。
- 创建态标题为 `New Memory`，按钮为 Cancel／Create memory／关闭。正文必填，其他字段按下文规则处理。ID、创建／更新时间和删除操作仅在有权威记录时显示。
- 空白草稿可直接关闭；修改后 Cancel、关闭、遮罩、Escape、程序导航均经过同一放弃确认。取消后回到原列表和 New Memory 按钮。

## 2. 表单、默认值与复用

共用 Namespace、Summary、Content、Categories、Keywords、Anchors 表单，以及 Markdown Edit／Preview、标签候选／新增、锚点输入、校验、焦点管理和离开保护。保持查看／编辑现有稳定 ID；单实例抽屉避免新增与详情重复 ID。

- Namespace：从当前已应用的精确 Namespace 筛选初始化；All 时使用服务实际配置的默认 Namespace。打开时记录初值，此后统计更新不得覆盖用户草稿。不得把字符串 `default` 当作配置值，也不得取已知列表第一项推测。
- 现有 store／Stats 没有默认 Namespace 字段。计划在 Admin `GET /api/stats` 增加 `default_namespace`，由服务持有的 Settings 提供，前端 store 缓存；不改变 MCP Stats schema。默认值尚未加载时显示加载／重试状态，用户仍可明确输入 Namespace；拿到默认值前不以猜测值提交。新增字段及失败路径需定向后端测试。
- 只继承 Namespace；不自动填入当前搜索词、分类、关键词或日期条件。
- Summary 为空时不发送该字段，沿用新增的后端自动摘要策略；提示“留空将从正文生成摘要”。非空摘要 trim 后提交。详情编辑的显式清空语义继续独立处理。
- Content 保留原始源码；纯空白不能提交，长度限制以服务契约为准，不虚构字符配额。
- Categories 最多 3 项；Keywords 不采用列表筛选的 20 项上限；Anchors 最多 5 项，每项遵循现有 Unicode 规则。
- 关键词候选跟随草稿 Namespace／Categories；未知 Namespace 允许手动新增，不发无效 scoped 查询。
- 保留旧新增页自定义 metadata 能力：折叠的“其他 metadata”JSON 编辑区，只接受对象；categories／keywords／anchors 由专门字段管理，JSON 中出现这些键时明确报错并指导使用上方字段，不静默覆盖。其他键原样保留。该区参与校验与 dirty；查看态沿用只读完整 metadata。
- 创建态也提供可达的 Debug 开关，不依赖尚不存在的 Technical details。区域、控件、动态标签、Preview 和错误提示有稳定 ID；开启 Debug 后悬停显示、点击隔离，退出恢复焦点。

## 3. 创建与错误处理

现有 `POST /api/memories` 接受 text、metadata、namespace、summary、confirm_codes，返回 `{id, created}`（HTTP 201）。`created=false` 表示同 Namespace／正文已有记录，现有记录不会被本次 metadata 或摘要覆盖。

1. 校验草稿，构造独立 `buildCreatePayload`；不要使用更新流程的差异 PUT payload。
2. 发出一次 POST，期间禁用重复提交和关闭；沿用维护门禁和 beforeunload。创建未完成时无 selected memory ID。
3. 未知 Namespace 使用现有确认流程，确认后携带对应 confirm_codes 重试；取消确认或明确失败均保留草稿。
4. `created=true`：保存返回的 ID、解除 dirty，按现有事件机制各通知一次列表与统计，然后 GET 权威记录，原抽屉转为查看态。成功创建即使重读失败也不能再次 POST。
5. POST 成功但 GET 失败：显示“已创建，详情加载失败”，保留 ID，仅允许重试 GET／关闭；GET 404 明确提示记录已不存在。
6. `created=false`：显示“相同正文的记忆已存在，本次摘要和 metadata 未写入”，保留草稿并提供 Copy draft、继续修改、查看已有记忆。查看已有记录若会丢弃修改，经过离开守卫；不得伪装为本次创建成功，也不自动 PUT 覆盖。
7. 网络中断等无法确定写入结果的失败：提示结果未确认、保留草稿，不自动重试。用户重试由后端现有同 Namespace／正文去重处理；不承诺新增幂等协议。
8. 维护拒绝、模型不可用、非法字段、过长输入等明确错误内联显示；恢复后允许重试。

## 4. 列表与会话行为

- 成功后重执行当前 Browse／Semantic／Lexical／Anchor 查询，保留已应用条件、查询草稿、排序、页大小及有效当前页；不自动跳首页、清筛选或把新记录硬插入结果。
- 新记录可能不在当前页／结果中；抽屉仍展示权威详情，不显示未经核实的“不匹配筛选”结论。
- 列表刷新和详情 GET 错误独立处理；成功创建不能因列表刷新失败被误报为创建失败。
- 新增入口清除旧详情选中 ID，创建成功后按真实 ID 选中；关闭恢复 New Memory 焦点。异步响应采用会话版本防止迟到结果覆盖另一记录。
- 如程序请求从有未保存草稿的详情切到新增，先通过现有离开守卫，再初始化创建草稿；取消不得改变当前会话或列表条件。
