# [50.5.3] 3.3：Memories 共用筛选

2026-10-02。状态：已完成，Python、隔离浏览器回归及独立 review 通过。

依据 [50.5.1 交互与数据契约](50.5.1-memories-interaction-and-data-contract.md)和[设计包](../../design/remember-me-memory-ui-package/README.md)，在 3.2 浏览工作区接入 Namespace、Categories、Keywords 筛选，为 3.4 搜索模式复用筛选状态。

## 实施范围

- Namespace 单选；Categories 搜索式复选；Keywords 远程搜索添加。选择即时生效，同维 OR、维度间 AND。
- Reset 清空筛选并保留排序／每页数量；筛选空结果提供清筛选入口。
- 选中项不因候选变化而丢失；每维最多 20 项。
- 分类候选来自共享 Stats `category_counts`。注册表暴露 idle／loading／ready／error 和 `hasData`，候选刷新不额外查询列表。
- 关键词复用 `/api/keywords/query` literal 模式，输入防抖 250ms、每页 20 项；携带 Namespace 和 Categories。候选请求与分页数据请求独立保护竞态。
- 弹层使用对话框语义与键盘操作，处理焦点返回、滚动／缩放定位及离页清理。
- 后端 API、存储及 MCP 无需变化；分页 GET 透传重复的 categories／keywords 参数。

## 职责

- `memories-data.js` 保存并提交已应用筛选，负责分页 API 查询。
- `memories-filters.js` 管理筛选 UI、弹层和临时候选查询。
- `memories.js` 负责装配；`store.js` 保存共享分类候选状态；`stats.js` 发布候选加载状态。

## 验收

- 分类和关键词各自 OR，两个维度、Namespace 互相 AND；逗号关键词仍作为单一值传递。
- 改筛选回到第一页；Reset 只触发一次列表请求且保留排序和每页数量。
- 候选刷新失败／恢复、已选值失去候选、空输入、加载更多失败重试均可判定，选择不丢失。
- 旧候选响应不能覆盖新输入／范围；离开页面取消防抖和弹层。
- 验证 20 项上限、错误空结果、未知 Namespace、键盘选择与焦点、旧 Search 和 Keywords 页面兼容。
- 隔离 Python 与浏览器回归通过；1024 CSS px 及以上桌面视口、Light／Dark、侧栏两态无横向溢出。
