# 50.11 Configuration UI refinement — Coding Plan

日期：2026-10-11。状态：已实施，待用户视觉验收；依据用户确认的 Configuration 设计包及当前后端行为。

## 目标与契约

现有配置页改为 Settings / Maintenance 双 Tab，统一 Shell 五态、维护工具分组及前端交互。文档优先于图片；不新增 gRPC、存储目录、Logging 设置。公开 API、Schema、MCP 和后端门控不变。

Debug 已由配置完整控制，保存刷新生效，无 --debug。普通维护动作需要维护空闲、无错误、无模型要求；Sync 允许修复维护错误但不能越过模型要求；Restart/Shutdown 在维护空闲时允许错误/模型未就绪；Exit 必须无任务/错误/模型要求。模型未就绪时保存配置后，沿用前端调用 model/retry 流程。代理 URL 允许空路径或单个 /，空输入通过省略字段保留凭据。

## 实施顺序

1. 修正设计契约，保存本计划。
2. Settings：Appearance 主题单选及 Service Configuration。Maintenance：Maintenance Mode、Model Management、Data Transfer、Data Management、Server、Danger Zone。
3. 当前页面会话保留 Tab、草稿；F5 恢复默认，不持久化页面状态。主题仍使用 remember-me.theme.v1。折叠表单结果保留到主动收起或离开页面，任务运行中结果保持可见。
4. 设置加载基线/草稿/校验/保存状态，合法且有改动才能保存；轮询不覆盖草稿。代理不回填凭据/脱敏值，禁用隐藏输入并保留已存值；开放局域网即时警告及保存确认。保存与模型重试反馈分开。根据已知变更提示重启及Debug刷新，不伪造运行配置。
5. 状态、表单合法性与本地提交锁统一门控；失败后刷新状态，禁止无条件启用。保留任务ID，查询失败允许重查而不重发。Recover/Clear 共用随机8位确认，锁定对象、焦点约束、Escape取消和焦点恢复。
6. Restart确认后2秒一次、请求最多5秒、总60秒有限重连；只说明服务可访问，不虚构实例确认。提示端口候选地址及--port覆盖，不自动跳转。Shutdown接受后执行控件禁用，需终端启动。
7. 明暗主题/窄屏/键盘回归，更新文档进度；提交与生产重启另按用户指令。

## 验收

状态矩阵：正常、维护空闲、动作运行、sticky error、模型等待/下载/验证/失败/取消、状态不可用及恢复。设置：干净/非法/合法脏态、代理凭据保留、LAN确认、保存失败、保存成功但重试失败、Debug真实刷新。操作：确认对象锁定、随机码错误/取消/重复提交、Import/Recover状态查询恢复、Export下载头、Sync及迁移刷新。重启：可访问/超时/端口提示；关闭：不虚构网页启动。1440/1024/390px双主题、长文本、焦点、Debug ID、Memory/Stats功能兼容。
