# 53.4 Statistics 双视图 Coding Plan 与实施记录

日期：2026-10-10。状态：用户已验收并明确授权提交；实现与定向验证完成，随本次提交归档。生产未重启。

设计依据：[最终设计包](../../design/REMEMBER_ME_STATS_FINAL/README.md)，后端依据：[53.3 Retrieval Statistics API](53.3-retrieval-stats-api-coding-plan.md)。本文件整理本轮已批准的执行计划及实际完成结果。

## 1. 已确认决定

- Statistics 增加 Memory / Retrieval 两个同级视图，共享顶部 Namespace。Memory 维持已验收的五指标、Namespace 分布及三个元数据面板。
- Namespace 候选读取既有全局 registry，并合并配置默认空间；scoped API 的响应不能缩小全局候选。已选但不再存在的空间保留选择，错误提供 All 返回入口。
- 移除 Stats 自己的 Refresh，使用 Shell 顶部全局 Refresh 刷新当前视图及全局候选，保留当前设置。
- 不支持 F5 恢复 Stats 上下文，不使用 sessionStorage / localStorage 存储 Stats 状态。站内切页、切换 Memory / Retrieval 时保留 Namespace、天数、Memory Top 与列表滚动、各视图页面滚动；整页刷新仍从默认 Memories 入口开始，下次进入 Stats 为 Memory / All / 7 Days / Top 5。
- Retrieval 仅展示现有 API 统计的 MCP 搜索与显式反馈；Admin 搜索不纳入，不新增或改变审计口径。
- Overview：Searches、Rated Searches、Feedback Coverage。单一 Search Activity 趋势；Search Modes 按调用数排名；Feedback 使用 −10..10 数值、有效评分数及正／中／负分布。
- 7 / 30 天按日；90 天按周一开始的自然周，首尾允许不完整。日期、分桶和时区取实际 API；当前日未结束明确标注，不将周桶的下一个午夜误当完整数据截止点。
- Data notes 入口只在服务器 `--debug` 下显示，与是否打开元素检查器无关。普通用户仍看到 API 错误、Retry、All。
- Namespace 分布行仍下钻 Memory List Browse；Category / Keyword / Anchor 下钻沿用既有语义。
- Samples 只参考布局、间距和主题，不采用其中的假数据、增长指标、星级评分或错误 Top 档位。

## 2. API 与页面映射

只复用 `GET /api/stats/metadata`、`GET /api/stats/retrieval` 和既有 `/api/stats` registry。All 不传 namespace；具体空间由 URLSearchParams 编码。Retrieval 显式传 days 与浏览器 IANA timezone，不使用固定时区或硬编码历史起点。

| 数据 | 页面用途 |
| --- | --- |
| `scope` | 响应范围校验、日期范围、时区、截止点、Debug 中保留历史说明 |
| `search.total_searches` | Searches；趋势与模式总数校验 |
| `search.trend` | API 已聚合的日／周单线趋势，不二次分桶 |
| `search.modes` | 四种模式按 count 排名，含 0 次模式 |
| `feedback.rated_searches` | Rated Searches |
| `feedback.coverage_percent` | Feedback Coverage；分母 `eligible_searches`，无分母为 — |
| `feedback.average_rating`、`rating_count` | 平均分与有效评分数；保留负分与 0，null 显示 — |
| `feedback.distribution` | 正／中／负数量及比例，分母为 `rating_count` |
| `data_quality` | Debug Data notes；坏行、测试反馈排除、未匹配反馈、冲突及历史覆盖警告 |

无搜索与有搜索无反馈分别呈现。只用 textContent / DOM API 插入用户数据；无效结构和范围不显示成有效统计。数据质量说明明确诊断可能来自全保留日志，并不等同于当前 Namespace 的异常数量。

- Overview 五个指标增加 document / layers / tag / hash / anchor SVG 图标及柔和圆形底色，固定蓝／紫／绿／金／粉身份配色。窄屏图标上置，名称与数值保留完整宽度。
- Namespace 圆环由 24 加粗到 44 SVG 单位；占比至少 7% 的扇区显示百分比，小扇区避免文字堆叠，全部比例仍列在右侧。中心保持 Memory 总数。颜色按空间名排序分配，避免调用量排名变化引起颜色交换；超过八种空间循环 palette。

### 第二轮复核：圆环裁切、摘要间距及 Keyword 色彩

- 加粗后圆环外半径为 `80 + 44 / 2 = 102`，超出旧 `0..200` viewBox 两边各 2 单位，导致四边出现平切。本轮将 viewBox 调整为 `-6 -6 212 212`，保留粗细、中心与比例，并为完整 stroke 留出四边余量。
- Unique Count 不再与 Coverage 等分可用宽度；它按自身内容占宽，后接 12px 间距和竖线，Coverage 内侧保留 12px padding，避免分隔线被额外空白推远。大数仍允许收缩／换行，Top 的整组换行规则不变。
- 仅 Keywords 排名条改为按排名循环八色 palette，Top 5 使用五种可区分颜色；长度和排序仍按原 API 记忆数量。配色表达条目区分，不增加语义、评分或新统计。
- Memory Stats 功能及 24 项明暗布局复验；增加 stroke 全部落在 viewBox 内、分隔间距与关键词 Top 5 色彩的浏览器断言。截图继续保存于 `/tmp/remember-stats-refinement/`。

用户后续确认 Categories 与 Anchors 也需采用同样的多色排名条。本轮将八色循环规则统一应用于三个元数据维度；同一排名位置使用同一 palette 色，长度、排序和统计口径保持原实现。验证三个面板 Top 5 条目颜色区分及跨面板 palette 一致性，复验 Stats 功能和明暗宽／窄布局。

Retrieval Overview 同步补齐三项 SVG 图标：Searches 蓝色搜索、Rated Searches 紫色评价、Feedback Coverage 绿色覆盖目标。复用 Memory 指标图标 badge 和响应式排版，图标为装饰，不改变指标或可访问名称。定向验证 Retrieval 功能及明暗宽／窄布局。

Retrieval 下方卡片按用户最新要求增加颜色区分：Search Modes 固定 Semantic 蓝／Lexical 紫／Anchor 绿／Meta 金，颜色跟随模式，不随数量排序改变；Feedback 中性条从灰改蓝，对照 sample 的正面绿／中性蓝／负面红，继续使用实际 −10..10 评分口径。只调整 Stats CSS，无 API 或指标变化。定向验证功能、明暗宽窄屏、空数据和无反馈场景，检查模式色及情绪色区分。
