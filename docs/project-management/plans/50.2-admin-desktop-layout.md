# [50.2] 管理台桌面布局调整

2026-10-01 确定方案。基线：`a506fd6`（[50.1] 前端模块拆分已完成）。状态：已实施并验证，未部署。
本项是 [50] 第二阶段的第一项布局改动。参考图为 `~/tmp/a.png`：顶部是全局区域，
左侧是菜单，右侧工作区尽量利用窗口宽度。参考其空间组织，不复制业务内容或视觉细节。

## 已确认决策

1. 维护门控以服务端 `app/operations/maintenance.py` 为唯一权威，前端与文档
   与之对齐（含 `error` 语义，见下文）。
2. 顶部状态控件使用 `<button type="button" id="btn-status" aria-describedby="status-tooltip">`，
   不绑定业务动作；`#status-tooltip[role="tooltip"]` 的显隐由 CSS 控制，
   JS 只写 `textContent`。
3. 导航 `<button>` 内同时包含内联 SVG 图标（`aria-hidden`）与文本节点，折叠时
   仅用 CSS 隐藏文本，按钮保留 `aria-label`／`title` 提供可访问名称。
4. 回归产生的多尺寸／缩放截图写入临时目录，仅 review 时查看，不入仓库。

## 目标与布局

面向桌面浏览器和不同窗口尺寸，采用顶部通栏、左侧可折叠导航、右侧自适应工作区。
当前 `.content` 的 `max-width:1200px` 和居中留白取消。

```text
┌──────────────────────────────────────────────────────────┐
│ Branding / 服务信息           全局状态 · Refresh · Debug │
├────────────┬─────────────────────────────────────────────┤
│ 折叠按钮   │                                             │
│ Memories   │            当前页面工作区                   │
│ Search     │                                             │
│ Add Memory │            独立纵向滚动                     │
│ Keywords   │                                             │
│ Stats      │                                             │
│ 配置       │                                             │
│ Audit      │                                             │
└────────────┴─────────────────────────────────────────────┘
```

顶部 Branding 与全局状态处于**同一条区域**：左侧是品牌和服务信息；右侧依次为
全局状态、Refresh、Debug。状态项始终显示，正常态也显示“运行中”；没有单独占
一行的状态横幅。

## 实现

- `app-shell` 使用两行 CSS Grid：顶部高度随内容变化，下方占满剩余视口；
  高度使用 `100dvh`，并提供 `100vh` 回退。`body` 不承担页面纵向滚动。
  下方 `app-main` 再分为左侧导航和右侧工作区；顶部和左侧始终可见。
- 将现有 `maintenance-banner` 放入顶部右侧状态区，改为可聚焦的状态按钮。
  按钮文字和完整说明按下文状态矩阵确定；说明放在关联的 `role="tooltip"`
  元素中，以 `aria-describedby` 关联，悬停或键盘聚焦状态按钮时显示，离开时隐藏。
  动态说明只通过 `textContent` 写入。状态按钮不触发业务操作；模型详细进度
  仍在配置页面。
- 顶部右侧空间不足时在同一顶部容器内换行，下方区域按实际顶部高度自动缩放。
- 左侧导航展开宽度 180px、折叠宽度 64px；菜单过长时自身滚动。菜单项使用
  内联 SVG 图标和现有名称；折叠后只显示图标，同时保留可访问名称和悬停提示。
  选中项用背景色和左侧标记突出。
- 导航元素由 `<a>` 改为 `type="button"` 的 `<button>`，保留现有 ID 和
  `data-page`；更新路由选择器、选中状态及 `aria-current="page"`。折叠按钮
  提供 `aria-expanded` 和明确名称，Enter／Space 均可操作。
- 用户控制折叠，不按窗口宽度自动切换。桌面默认展开；选择写入 `localStorage`，
  存储不可用时保留当前页面的内存状态。键为
  `remember-me.sidebar.collapsed.v1`，仅字符串 `"true"` 视为折叠；折叠不重载
  页面或清空表单。
- 右侧工作区占用剩余宽度，设置 `min-width:0`、`min-height:0`，内边距 20px；
  独立纵向滚动，切换页面时将工作区的 `scrollTop` 设为 0；折叠菜单不改变
  当前滚动位置。记忆列表、搜索结果和 Audit 表格在各自容器内横向滚动，
  不撑宽站点。
- DOM 顺序固定为：`app-shell` 包含 `header` 与 `app-main`；`app-main` 包含
  `nav` 与 `main.content`，七个 `page-*` 留在 `main.content`。`detail-modal`、
  `clear-modal` **移至 `app-shell` 之后，作为其直接兄弟节点**，继续以
  `position:fixed` 覆盖整个视口。移除菜单旧的 `position:sticky`；固定效果由
  外壳网格实现，`nav` 内容过长时独立滚动。

后端 API、现有菜单顺序和页面业务功能沿用。**新增
`web/static/js/layout.js`，由它独占折叠状态、按钮属性与持久化；`main.js`
只调用一次 `layout.mount()`。**折叠状态不放入 `store.js` 或 `router.js`，
业务页面不管理它。

## 顶部状态与控件矩阵

### 门控权威与 `error` 语义

维护门控以服务端 `app/operations/maintenance.py` 为**唯一权威**，前端本项将前端
按钮状态与该权威对齐（现有 `ops.js` 与文档在此处曾有措辞偏差，本项一并收敛）：

- `state.error` 是**维护动作失败后留下的粘性失败标记**（`finish_action` 仅在
  `sticky=True` 时写入字符串），不是瞬时请求错误；它与 `state` 正交，直到
  `clear_error()` 或成功修复动作才清除。
- 存在 `error` 时：`exit` 被拒绝（`maintenance.py:100`）；`start_action` 仅放行
  `sync`、`restart`、`shutdown`，其余维护动作拒绝（`maintenance.py:113`）。
- `required_reason` 存在时：`start_action` 仅放行 `restart`、`shutdown`
  （`maintenance.py:107`），`exit` 拒绝（`maintenance.py:98`）。

因此下方矩阵中“维护异常”行的 Sync／Restart／Shutdown 放行条件**直接取自
`maintenance.py`**，不再附加文档自拟的额外前提。

下表以 `/api/maintenance` 返回值为准。`Refresh` 保持现有 Stats＋列表刷新，
`Debug` 保持现有 ID 调试；这两个按钮、侧栏折叠按钮及状态说明始终可用。
配置保存仍由 `serviceConfigLoaded` 和 `configSaving` 决定。维护动作的具体门控
以服务端 `maintenance.py` 为准，本项把前端按钮状态与之一致，并补齐状态失败时的
显式禁用和状态展示。

| 状态判定 | 顶部标签；完整说明 | Refresh／Debug／折叠／状态说明 | 配置保存 | 普通写入、维护控件 |
|---|---|---|---|---|
| `state=normal` 且无错误 | **运行中**；服务正常运行 | 均可用 | 已加载且未保存中时可用 | Add 可用；Enter Maintenance 可用；Exit、Retry Model 和维护动作禁用 |
| `state=maintenance`，无 `required_reason` 和 `error` | **维护中**；写入暂停、查询可用，附当前 `action` | 均可用 | 同左 | Add、Enter 禁用；空闲时 Exit 和维护动作按现有策略可用；有 `action` 时禁用 |
| `required_reason=model_not_ready`，无 `error` | **模型未就绪**；记忆读写与搜索不可用，附模型状态或错误 | 均可用 | 同左 | Add、Enter、Exit、普通维护动作禁用；无 `action` 时 Restart／Shutdown 可用；Retry Model 按现有模型准备状态规则可用 |
| 响应含 `state.error` | **维护异常**；显示错误原文及当前 `state`／`action` | 均可用 | 同左 | Add、Enter、Exit、Retry Model 禁用；Sync、Restart、Shutdown 按下方条件判定，其余维护动作禁用 |
| 请求失败、响应无法解析或未知 `state` | **状态不可用**；显示读取失败信息 | 均可用 | 已加载且未保存中时可用 | Add、Enter、Exit、Retry Model 和全部维护动作禁用，直到下次成功轮询 |

判定优先级：**请求失败／无效响应 → `state.error` →
`required_reason=model_not_ready` → `state=maintenance` → `state=normal`**。
每次成功轮询重算状态及控件可用性；失败时覆盖旧状态和旧按钮状态，不沿用
过期的“运行中”。状态说明文本以 `textContent` 设置，不拼入 HTML。

维护控件按下表逐项判定。“空闲”指 `!state.action`；`Retry Model` 在模型
状态为 `downloading`、`validating` 或 `cancelling` 时禁用。

| 状态 | Enter | Exit | Retry Model | Restart／Shutdown | Sync | Recover／Import／Export Full／Export Namespace／Clear／Migrate |
|---|---|---|---|---|---|---|
| 正常 | 可用 | 禁用 | 禁用 | 禁用 | 禁用 | 禁用 |
| 维护中 | 禁用 | 空闲可用 | 禁用 | 空闲可用 | 空闲可用 | 空闲可用 |
| 模型未就绪 | 禁用 | 禁用 | 非上述准备状态时可用 | 空闲可用 | 禁用 | 禁用 |
| 维护异常 | 禁用 | 禁用 | 禁用 | 维护中且空闲，或模型未就绪且空闲时可用 | 维护中，或模型就绪且空闲时可用 | 禁用 |
| 状态不可用 | 禁用 | 禁用 | 禁用 | 禁用 | 禁用 | 禁用 |

`Add Memory` 提交按钮与记忆列表的 `Clear` 快捷按钮仅在确认
`state=normal` 且无 `error` 时可用。状态读取失败或响应无效时，向共享
maintenance store 写入 `{state:'unavailable'}` 作为安全快照，通知各页面禁用
这些普通写入入口（`add.js`／`memories.js` 现有 `state !== 'normal'` 订阅天然覆盖
`unavailable`，无需新增分支）；成功轮询再用真实状态替换。`Refresh`、`Debug`、
折叠和状态说明在上表所有状态均可操作。

## 桌面适配与验收口径

宽度统一按运行时 `window.innerWidth` 测得的 **CSS 像素**判定，
不按显示器物理像素或窗口外框尺寸。本轮合格范围为 `innerWidth >= 1024`。
浏览器缩放后须重新测量 `innerWidth`；低于 1024 CSS px 的组合不计入本轮
通过／失败。大屏工作区持续扩展，不增加最大宽度；较窄桌面窗口的工具栏、
表单按内容换行，表格保持局部横向滚动，外壳不产生横向滚动。

| 场景 | 设置与判定 |
|---|---|
| 常规 CSS 视口 | 分别设为 1024×768、1280×720、1366×768、1920×1080、2560×1440；每种检查菜单展开和折叠 |
| 浏览器缩放 125% | 调整桌面窗口，使缩放后实测 `innerWidth >= 1024`，目标约 1280 CSS px；记录实测宽高后执行同一布局断言 |
| 浏览器缩放 150% | 同上，使缩放后实测 `innerWidth >= 1024`，目标约 1280 CSS px；记录实测宽高后执行同一布局断言 |

例如物理窗口约 1024px 宽、缩放至 150% 时，CSS 视口可能不足 1024；
该组合不属于本轮验收范围。清理现有 768px 样式中与新桌面外壳冲突的规则；
不开发平板、手机专用导航或触控交互。

## 实施结果

- 外壳：`body` 改为 `div.app-shell`（`header.app-header` + `div.app-main(nav#nav + main.content)`）；
  `#maintenance-banner` 移除，改为顶部右侧 `#btn-status`（`<button type="button">`）+
  `#status-tooltip[role="tooltip"]`，说明经 `aria-describedby` 关联、CSS `:hover`／
  `:focus-visible` 显隐；`#detail-modal`、`#clear-modal` 移为 `.app-shell` 兄弟节点。
- 导航：`<a>` 全部改为 `<button type="button" data-page>`，保留 ID，含内联 SVG(`aria-hidden`)
  + `.nav-label` 文本；新增 `#btn-sidebar-toggle`（`aria-expanded`）。选中态加 `aria-current="page"`。
- 新增 `web/static/js/layout.js`：独占折叠状态与 `localStorage['remember-me.sidebar.collapsed.v1']`
  （仅 `"true"` 折叠，读写 try/catch 回退内存），`main.js` 调一次 `layout.mount()`。
- `router.js`：`.nav button[data-page]` 选择器、`aria-current` 同步、切页将 `#content.scrollTop`
  置 0；`ops.js`：新增 `deriveStatus`/`applyControls`，五状态（运行中／维护中／模型未就绪／
  维护异常／状态不可用）与门控对齐 `maintenance.py`（`required_reason` 仅放行 restart/shutdown；
  粘性 `error` 额外放行 sync；轮询失败写 `{state:'unavailable'}` 安全快照）。`add.js`／
  `memories.js` 依赖现有 `state !== 'normal'` 订阅，无需改动。
- CSS：`app-shell` 用 `100vh`/`100dvh` 两行 Grid，`app-main` 为 `180px/64px + 1fr`；
  `.content` 独立纵向滚动（`min-width/height:0`、`overflow-y:auto`）；删除旧 `.nav` sticky 与
  `.content` 的 `max-width/margin`；`@media(max-width:768px)` 仅保留表单换行与内边距；宽表格加
  `.table-scroll` 局部横向滚动。
- 回归：`tests/browser/admin_regression.js` 选择器改 `button`，新增状态矩阵、`unavailable`
  兜底与恢复、外壳结构、`aria-current`、切页归顶、折叠/持久化/表单保留、键盘激活、
  `scrollWidth <= innerWidth` 断言。`tests/run_admin_browser.py` 支持 `--window-size`／
  `--force-device-scale-factor`，遍历 5 尺寸 × 3 缩放（含越界提示），截图写临时目录不入库。
- 验证：隔离 Chrome 回归 15/15 组合通过；全量 `pytest` 710 项通过；`node --check` 全部模块通过；
  1024/1440/1920 截图人工确认布局（展开态）。未执行生产重启或部署。
