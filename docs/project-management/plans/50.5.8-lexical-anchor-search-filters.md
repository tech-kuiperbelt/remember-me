## 1. 目标与共同契约

为 Lexical／Anchor 补齐公共筛选及最低相关性分数，供 Memories 三模式搜索使用。Storage、Service、Admin HTTP 和 MCP 同步支持，避免同一检索在不同入口行为不一致。

| 模式 | 搜索参数 | 前端指标 |
|---|---|---|
| Semantic | Top-K、最低相似度 | `Semantic <score>` |
| Lexical | Top-K、最低相关性分数 | `FTS <score>` |
| Anchor | Top-K、最低相关性分数 | `Anchor <score>` |

三种模式共享 Namespace、Categories、Keywords、Updated after／before。Semantic 保留分类／关键词的现有语义解析；Lexical／Anchor 使用精确匹配，同维度 OR、跨维度 AND。候选筛选及分数门槛在 Top-K 截取前应用。

不增加检索模式、结果融合、数据库 schema 或索引迁移。BM25 与余弦分数不跨模式比较、不转换为百分比。

## 2. 接口与校验

- 扩展 Lexical／Anchor 的 Storage、Service、Admin HTTP、MCP 入口，新增可选 `min_score`、`categories`、`keywords`、`updated_after`、`updated_before`，保留现有参数位置和默认行为。
- `min_score` 省略或 null 表示不限制；接受有限、非负 JSON 数字，没有 1 的上限，支持科学计数法。拒绝字符串、布尔、负数、NaN、Infinity。
- Top-K 保持默认 10、范围 1–100；两条入口统一拒绝布尔和非整数，不通过强制转换截断小数。
- 分类／关键词复用现有过滤参数归一化；不调用 embedding 或语义解析器。时间复用 UTC 微秒归一化和严格开区间校验。
- 非法筛选参数映射为 `InvalidSearchFilter`；HTTP 返回 400 `invalid_request`，查询语法错误保留 `invalid_query`。MCP 保留现有错误信封和未知 Namespace 行为。

## 3. 查询、返回与兼容性

- 在共享 FTS 查询中组合 MATCH、Namespace、分类、关键词和时间条件。元数据只约束候选，不参与正文／anchors 的文本匹配。
- 使用 `score = -bm25(...)`，按 `score >= min_score` 过滤，再按相关性排序并取 Top-K；同分以记忆 ID 升序稳定排序。
- BM25 仍基于原 FTS 索引统计量，不为每组筛选条件重新构建或归一化分数。
- 移除 Lexical／Anchor 的 `score` 与 `match_info.raw_bm25` 六位小数舍入，返回原始有限浮点值；阈值比较使用同一精度。这是有意的数值精度变化，响应字段结构不变。
- 保留 HTTP 数组、MCP 搜索信封、search_id、report 和审计关联。同步工具 schema、golden fixture、说明及新增参数的审计覆盖。
- 复用先行 SQLite 锁修复的保护边界；查询、取行及需要访问数据库的结果转换均不得绕过锁。

## 4. 后端测试与验收

| 测试范围 | 必须覆盖 |
|---|---|
| 公共筛选 | 两种模式分别覆盖单项／组合筛选、维度 OR 与跨维度 AND、未知过滤值为空、正文与 anchors 匹配范围隔离 |
| 分数与 Top-K | 高分但不满足筛选的记录不能占据 Top-K；阈值等于分数包含、略高排除；极小正分数不归零；同分稳定顺序 |
| 时间 | 微秒、时区等价、单边界、非法范围及历史缺失／无效时间 |
| 输入与兼容 | 分数类型／范围校验，Top-K 非整数／布尔拒绝，HTTP／MCP 一致，旧参数调用兼容 |

| 并发 | 新增过滤组合与其他读取并发，沿用独立子进程、超时和自动抓栈保护 |
