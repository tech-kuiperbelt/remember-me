# 50.5.9 Memories 三模式搜索与列表指标

日期：2026-10-02

状态：前端完成。浏览器交互回归、完整桌面视觉矩阵及真实服务三模式只读联调通过；用户已确认最终布局，本次提交归档。

关联：[后端接口计划](50.5.8-lexical-anchor-search-filters.md)、[SQLite 锁修复](50.5.7-sqlite-concurrency-lock-fix.md)、[设计包](../../design/remember-me-memory-list-search-ui-package/README.md)。后端计划是本计划的接口依据。

## 1. 目标与范围

仅调整 Memories 内的搜索和列表指标，不增加 Search 菜单，不改站点外壳、现有筛选布局及详情交互。设计图中的独立 Search 导航不采用。

| 模式 | 搜索参数 | 列表指标 |
|---|---|---|
| Semantic（默认） | Top-K、最低相似度 | `Semantic <score>` |
| Lexical | Top-K、最低相关性分数（正文 BM25） | `FTS <score>` |
| Anchor | Top-K、最低相关性分数（anchors BM25） | `Anchor <score>` |

三种模式共享 Namespace、Categories、Keywords 和时间范围。Semantic 保留现有关键词／分类语义解析展示；Lexical／Anchor 精确匹配。分数直接使用后端返回值，不转换百分比，不融合结果或跨模式比较。

搜索只按后台相关性顺序展示；Browse 保留原有时间排序。三种搜索都沿用 Top-K 结果本地分页。

## 2. 状态与请求规则

- 默认 Semantic；搜索框、Search、Clear search 保持同一行；模式控件位于下一行，与公共筛选同处一行并靠右对齐。筛选项较多时在左侧区域换行。
- 保留输入草稿与已提交查询分离。输入不请求；Enter／Search 提交；清空查询返回 Browse。
- 有已提交查询时，切换模式立即用同一查询、当前已应用筛选及目标模式已应用参数请求，重置第一页；不提交尚未应用的查询或 Advanced 草稿。
- 无已提交查询时，切换只更新模式，不发搜索或重复 Browse 请求。
- 三种模式分别保存 Top-K 和阈值的草稿／已应用值。Top-K 默认 10，Semantic 阈值默认 0，另两种默认空。只保存在当前页面会话，不新增本地持久化。
- 时间草稿／已应用值跨模式共享，保留现有 Apply 规则：搜索使用已提交查询；Browse 应用时间筛选。Reset 只清公共筛选，保留模式、已提交查询及搜索参数。
- 数据模块集中选择现有三个 API，将 Semantic 信封及另两种数组归一化为内部集合；展示模块不决定 API。
- 请求版本保护覆盖模式、查询和筛选；旧请求成功或失败均不能覆盖当前模式。切换至 Lexical／Anchor 时清除旧 Semantic 筛选映射。
- Loading、空结果和错误保留查询、模式及筛选；Retry 使用已应用状态。

## 3. 控件、列表及分页

- 复用 Advanced 布局与现有字段 ID。阈值标签随模式显示“最低相似度”或“最低相关性分数”，提示 BM25 无统一 0–1 范围。
- Top-K 为 1–100 整数；Semantic 最低相似度沿用 0–1。BM25 阈值接受有限非负数字、小数和科学计数法，空值不发送 `min_score`；校验与后端一致。
- 新增模式控件具有唯一 ID、单选语义和键盘操作；Debug 可显示 ID，保留已有控件契约。
- Browse 不显示检索指标。搜索在底部信息行最左侧显示当前模式的蓝色分数徽标，统一保留三位小数、不乘 100；悬停显示后台原值（可为科学计数法），排序与阈值始终使用原精度。极小非零值可能显示为 0.000。
- 搜索移除更新时间重排，仅保留后台顺序；Browse 排序不变。
- 三种搜索翻页／改页大小均对已返回 Top-K 集合本地分页，不重复搜索。数量明确表示返回结果数，不宣称全库命中总数。
- 详情打开、标签交互及其他列表内容保持现有行为。
