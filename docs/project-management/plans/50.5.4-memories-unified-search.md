# [50.5.4] 3.4：Memories 统一搜索与迁移

2026-10-02。状态：已实施，隔离回归通过；独立 review 通过，待重启后的实际服务验证。基线为 `6e2e52a`，3.3 已完成并通过独立 review。

依据 [50.5 总体计划](50.5-memories-workspace.md)、[50.5.1 交互与数据契约](50.5.1-memories-interaction-and-data-contract.md)及[设计包](../../design/remember-me-memory-ui-package/README.md)。本文细化实施顺序和验收，不改变已确认的 Top-K 集合内分页、默认收起高级选项和共用筛选规则。

## 1. 目标和范围

Memories 成为浏览、语义搜索、筛选和查看记忆的唯一工作区。输入非空查询并提交进入搜索，清空查询返回浏览，不新增模式切换按钮。

本阶段完成搜索输入、高级选项、搜索结果展示、实际筛选映射说明、Keywords 跳转迁移，以及旧 Search 页清理。保留现有详情、编辑、删除和 Clear Namespace 流程；不扩展为 lexical／anchor 检索界面，不新增框架、URL 状态、持久化偏好或存储字段。

## 3. 页面布局和控件

顺序固定为：标题及 Clear Namespace → 搜索表单 → 共用筛选 → Advanced 折叠区 → 结果数量及排序 → 筛选映射说明 → 记忆行 → 分页。

- 搜索表单：带可访问名称的输入框、Search、Clear search；Clear search 在输入或已提交查询非空时可用。输入框占剩余宽度，按钮不挤压为不可读宽度。
- Advanced 使用原生 details／summary，初始关闭，展开状态仅保留在当前会话。内部含 Top-K、threshold、Updated after／before 和 Apply；不得嵌套表单。
- 搜索表单 Enter 提交搜索；高级字段 Enter 等同 Apply。中文输入法组合输入期间 Enter 不提交。
- Browse 排序选项为 Updated time／Created time；Search 为 Relevance／Updated time。切换模式恢复该模式上次排序。
- 日期时间输入使用 datetime-local，精度到秒；空值代表无边界。按浏览器本地时区转为 UTC ISO 8601。严格校验日期组成、有效性和 after < before；因夏令时跳变不存在的本地时间拒绝，重复时段遵循浏览器 Date 的本地时区规则。
- 字段错误紧邻字段，以 aria-invalid／aria-describedby 关联；提交失败聚焦首个无效字段，不改变已应用条件、不发请求。控件保留用户原输入供修正。
- 展开 Advanced 不应让结果区产生页面横向滚动。维持 Light／Dark、侧栏两态和等效 CSS 宽度 ≥1024px 的验收范围。

建议稳定 ID：`memories-search-form`、`memories-query`、`memories-search-submit`、`memories-search-clear`、`memories-advanced`、`memories-k`、`memories-threshold`、`memories-updated-after`、`memories-updated-before`、`memories-advanced-apply`、`memories-filter-resolution`。保留现有 `nav-memories`、`page-memories`、`memories-filters`、`memories-sort`、`memories-count`、`memories-list`、`memories-pagination`、`btn-clear-ns`。

## 4. 状态归属和高级选项规则

`memories-data.js` 继续独占工作区已应用状态和结果请求：

```text
inputQuery = ''                    # 正在输入的查询
submittedQuery = ''                # 驱动结果的查询；非空即 Search
namespace = '', categories = [], keywords = []
browseSort = 'updated_at', searchSort = 'relevance'
page = 1, pageSize = 20
k = 10, threshold = 0              # 已应用搜索参数
updatedAfter = '', updatedBefore = ''  # 已应用浏览时间条件，UTC ISO
status = idle | loading | ready | error
items, total, totalKind, filterResolution, error
```

完整 Top-K 集合及原始 API 顺序由 data 模块私有保存，供本地排序／分页；`items` 始终表示当前页。Browse 的 `totalKind=exact`、`filterResolution=null`；Search 的 `totalKind=top_k_results`。

新增 `memories-search.js` 管理搜索表单、Advanced 的 DOM、未应用字段草稿、字段错误和展开状态；通过回调提交意图，不直接调用 API。已应用高级值来自 data，草稿不进入 store。共用筛选仍由 memories-filters.js 管理。

| 操作 | 高级字段处理 |
|---|---|
| 修改高级输入 | 只改草稿，不请求、不改变已应用状态 |
| 提交非空搜索词 | 校验当前 Top-K／threshold 草稿，与 submittedQuery 一次性应用并请求；即使之前在 Browse 中控件禁用也采用其保留值 |
| Search 中 Apply | 校验并应用 Top-K／threshold 草稿，使用原 submittedQuery；不提交新的 inputQuery |
| Browse 中 Apply | 校验并应用日期草稿，只请求浏览；不提交非空但尚未提交的 inputQuery |
| 改共用筛选／Refresh／Retry | 使用已应用高级值，保留未应用草稿 |
| Search ↔ Browse | 保留两组已应用值及草稿，禁用当前模式不支持的一组；切换不会自动应用日期草稿 |
| Reset filters | 清 Namespace／Categories／Keywords，以及日期已应用值和日期草稿；保留查询、Top-K／threshold 已应用值与草稿、各模式排序和 pageSize |
| Keywords 跳转 | 清两种查询、共用筛选和日期值／草稿，再设置目标 Namespace＋唯一关键词；保留 Top-K／threshold、排序和 pageSize |

Top-K 必须为十进制整数 1–100，不用 parseInt 截断小数；threshold 必须为有限数字 0–1。空输入不静默回默认值。当前模式禁用的一组字段不阻断 Apply。若从 Browse 提交搜索遇到之前保留的无效 Top-K／threshold 草稿，展开 Advanced 并临时允许修正这两个字段，聚焦首个错误；修正后重新 Search，不使用户困在禁用的错误字段中。Search 提交只校验搜索参数，时间范围保持但不发送到搜索 API。

共用筛选 Reset 的可见性需要包含日期条件；在 Search 中存在保留的浏览日期条件时也可清除。日期条件在 Search 中不算当前有效筛选，不影响空结果文案。

## 5. 事件与请求矩阵

| 事件 | 状态／页码 | 请求和展示 |
|---|---|---|
| 输入非空查询 | 只改 inputQuery | 零结果请求；不重新渲染结果或移动输入光标 |
| Enter／Search 提交非空词 | 应用 trim 查询及搜索参数，page=1 | 一次 POST 搜索；再次提交同词也视为显式刷新 |
| 输入清空／仅空白／Clear search | 清 inputQuery 和 submittedQuery，page=1，保留筛选 | 一次 Browse；已经是同条件第一页 Browse 时零重复请求 |
| 修改 Namespace／Categories／Keywords | 保留输入与已提交词，page=1 | 按 submittedQuery 请求一次；共用候选仍按 3.3 独立刷新 |
| Reset | 按第 4 节清筛选，page=1 | 按当前模式请求一次；原本无任何筛选时不另发请求 |
| Apply | 只应用当前模式参数，page=1 | 一次当前模式请求；相同参数允许显式重新查询 |
| 排序变化 | 保存当前模式排序，page=1 | Browse 请求；Search 在完整 Top-K 集合本地排序 |
| pageSize 变化 | page=1 | Browse 请求；Search 本地切页 |
| 翻页 | 设置 page | Browse 请求；Search 本地切页 |
| Refresh／Retry | 保留查询、筛选、排序、页码、草稿 | 当前模式一次请求；全局 Refresh 同时刷新 Stats |
| 增删改事件 | 保留当前条件和页码 | 当前模式一次请求；结果缩小时纠正页码 |
| 离开 Memories | 保留会话状态 | 关闭筛选／标签弹层，不主动请求，不夺取其他页面焦点 |
| 返回 Memories | 保留会话状态 | onShow 刷新一次；重复导航不重复注册事件 |

加载时清除旧行和旧映射、显示骨架；错误时不显示之前的 Top-K 集合。搜索和筛选控件可继续操作并发起新请求，分页导航禁用。Search 加载中修改排序／pageSize 只更新展示偏好，不重复搜索；最新响应按当前偏好生成第一页。Search 错误时更改本地排序／pageSize 不得恢复旧结果或清掉错误，需 Retry／新提交。

每个网络结果请求递增版本并捕获不可变请求条件；成功、失败、映射和加载状态均只接受最新版本。普通输入和 Search 本地排序／分页不改变网络请求版本。切回 Browse／改筛选／重新提交立即使旧搜索失效；旧成功与旧失败都不得覆盖新模式。未提交 inputQuery 不得被请求完成时的快照覆盖。

Browse 保持 3.2 最多一次越界纠正；Search 刷新后按新集合长度直接限制页码，不再次搜索。全局 Refresh 与 Stats 注册表更新各自保持职责，Stats 候选更新不能触发第二次结果请求。记录变更即使发生在其他页面也沿用现有订阅刷新工作区；返回页面再刷新属于独立导航动作。

## 6. API 和搜索展示

### HTTP 兼容扩展

`POST /api/memories/search` 增加可选 `include_resolution`：

| 参数 | 返回 |
|---|---|
| 省略或 false | 保持现有数组，既有调用行为不变 |
| true | 将 `return_resolution=True` 传给 Service，返回 `{items, filter_resolution}` |
| 非布尔，包括 null、0、1、字符串 | HTTP 400，`response_code=invalid_request` |

工作区固定发送 true；只发送非空 Namespace、选中 Categories／Keywords，以及 query／k／threshold，不发送日期、分页或排序参数。仍使用既有业务线程池、读门禁和异常映射，不增加 MCP 工具、schema 或 Service 搜索算法。无维度筛选时 filter_resolution 为 null；有筛选时透传 Service 的结构。

前端验证对象包络、items 数组、有限数值 score 以及映射所需字段；非法响应显示可重试错误，不静默降级为不带映射的成功。兼容性由服务端旧数组分支提供。

### 数量、分页和排序

- 数量显示“本次搜索 N 条 · 最多 K 条”；K 使用本次已应用值，不采用未提交的草稿。N 是返回集合长度，不称全库命中总数。
- 页码和每页数量复用已有控件；搜索页脚明确为本次结果中的范围。
- Relevance 保持 API 顺序；Updated time 对完整集合排序后切页，不能只排当前页。
- 时间排序沿用有效 updated_at → 有效 created_at → 无有效时间置末；相同时保持 API 相对顺序。保留微秒并归一化时区，不能只用 Date.parse 的毫秒值比较；实现 UTC 整数微秒比较辅助函数（BigInt），历史无时区按 UTC 解释，覆盖服务返回 ISO 时间、时区偏移、缺失及非法值。展示相对时间仍可用 Date。
- Browse 隐藏 score；Search 在行右侧显示有限 score 的两位小数和 Semantic，使用低强调样式，不干扰行点击与标签弹层。

### 实际筛选映射

仅在最新 Search 成功后展示 keywords／categories 中 match_type 为 semantic 或 none 的项；exact 不显示。semantic 列出所有 accepted 的值，如“关键词：locking → optimistic-lock、lock”；none 显示“关键词 locking 未找到匹配值”。不改写选中值、不展示 resolver 配置或把映射分数当记忆分数。

说明区放在数量栏下，以 textContent 构建，采用礼貌的状态播报；Browse、loading、error 时清空。无结果时也保留本次有效映射，帮助解释原因。

### 空结果与错误

| 状态 | 文案及入口 |
|---|---|
| 无任何有效条件的 Browse 空库 | 暂无记忆 |
| 有共用筛选或日期的 Browse 空结果 | 当前搜索或筛选没有匹配的记忆；Clear filters |
| 纯 Search 空结果 | 当前搜索或筛选没有匹配的记忆；清空搜索 |
| Search＋共用筛选空结果 | 同上；Clear filters；清除后仍搜索原 submittedQuery |
| 请求失败 | 保留条件和草稿，展示安全文本错误及 Retry |
| 未知 Namespace | 同上，并提供返回全部范围；保留查询及其他筛选 |

普通 maintenance 继续遵循后端读许可；model_not_ready／切库／关闭导致的读拒绝按错误展示。状态不可用不由前端额外禁止搜索。Clear Namespace 仍仅在 normal 且选中 Namespace 时可用。

## 7. Keywords 跳转和旧页面退场

由 main 注入 `showKeyword` 回调给 keywords；keywords 不导入 memories，也不直接修改其 DOM。

Memories 提供不发请求的 `prepareKeywordBrowse(keyword, namespace)`：关闭弹层，按第 4 节原子更新状态并使旧请求失效。main 回调先调用 prepare，再 `switchPage('memories')`；唯一请求由 Memories 的 onShow 发起。即便已有进行中的旧搜索或当前已在 Memories，也只能发起一次目标分页请求，不能先加载旧状态再加载新条件。

迁移通过后删除 `web/static/js/search.js`、main 的 import／mount／register、`nav-search`、`page-search` 和专属事件绑定。检查 `detail.bindMemoryRows` 的剩余引用；若已无调用者，一并删除旧表格适配函数，保留详情 CRUD。只清理已确认无引用的 CSS，避免误删其他页使用的 table／ns-tab 样式。

router 在变更 active 状态前验证注册页面与目标 DOM；未知页面（包括 search）保持当前页不变并返回 false，不能先清空 active 再抛异常。不提供新的 search 路由别名。

## 10. 可判定验收矩阵

| 场景 | 必须观察到的结果 |
|---|---|
| 输入连续字符／IME Enter | 未显式提交时搜索请求为 0；组合输入不误提交 |
| A 已搜索，输入 B 未提交，随后改筛选／Apply／Refresh | 请求 query 仍为 A，输入框保留 B |
| 提交 B／清空／仅空白 | 分别一次 B 搜索／Browse；旧 A 响应不能覆盖 |
