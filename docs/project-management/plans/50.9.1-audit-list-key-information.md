# 50.9.1 Audit List 关键信息 Coding Plan

日期：2026-10-11。状态：用户已验收并明确授权提交；定向验证通过，随本次提交归档。生产未重启。

## 目标与已确认事实

用户需要从列表判断每次调用在哪个 Namespace、执行什么操作、操作对象或查询条件以及返回结果，再决定是否打开 JSON。现有列表仅工具名、状态、时间、Namespace、耗时，无法有效浏览操作内容。

代码核对依据：`app/audit.py` 的参数/结果裁剪与事件记录规则、工具适配器及维护任务的 audit 调用位置。

- Audit 主字段包括 `tool/status/ts/duration_ms/namespace/params/result/error/response_code/memory_refs`。
- 新增和更新的请求正文 `text`、`summary` 会被主动移除，不能承诺展示记忆正文或用户输入 summary；不根据 `summary_mode` 推断准确的修改字段。
- 搜索保留 query/筛选条件及 result.total/items；get_details 保留 found/missing；report 保留 ratings 和关联 search_id。
- status=ok 表示调用成功，不代表结果非空、目标已删除或后台任务已经完成。列表必须区分调用状态与业务结果。

## 列结构与视觉规则

列表继续使用 Memory 风格的独立行卡片，宽屏增加统一表头与对齐列：

| 列 | 内容 |
|---|---|
| 时间 | 本地日期、时间，允许两行 |
| Action | 原始 tool 名，保持可识别，不改名掩盖具体搜索模式 |
| Namespace | 事件归属空间，独立列 |
| 关键信息 | 按 Action 提取的对象、查询或参数摘要，最多两行 |
| 结果 | 仅原始调用状态，例如 ok、error；其他结果信息只在 JSON 详情中展示 |
| 耗时 | duration_ms，保留合法的 0，缺失显示 — |
| 详情箭头 | 保持整行点击和可聚焦详情按钮 |

以 Audit 列表容器宽度为响应式依据：达到 1100px 时显示列标题，网格宽度依次为 140px / 176px / 144px / minmax(220px,1fr) / 140px / 72px / 24px，列间距 12px，行内边距 16px。不足 1100px 时隐藏表头，切为有字段标签的纵向卡片：Action 与状态在首行，Namespace/时间/耗时为元信息，关键信息与业务结果依次展示。避免拥挤横向表格与页面横向滚动。

沿用当前 Memory 字号层级、行间距、8px 圆角、边框、Hover 阴影和 Focus 描边。长 Action、Namespace 与 ID 允许安全换行；摘要使用两行省略。动态文本仅以 textContent 或统一转义输出。每个单元格提供稳定 Debug ID，例如 audit-row-1-namespace、audit-row-1-summary、audit-row-1-result。

## Action 摘要与结果规则

新增纯展示模块 `web/static/js/audit-presentation.js`，由 audit.js 调用；输入单个原始事件，输出 namespace、summary、outcome、status 的展示文本。模块不发请求、不改原对象、不拼 HTML。

| Action | 关键信息来源与顺序 | 业务结果 |
|---|---|---|
| search_semantic / search_lexical / search_anchor | params.query；随后为存在的 keywords、categories、updated_after/before 条件 | result.items 为数组时展示“返回 N 条”；否则回退到有限非负 result.total；两者同时存在且不同，追加“total N”，不把 total 无条件称为全库匹配数 |
| search_meta | keywords、categories、更新时间范围；均缺失时显示“浏览记忆” | 同上；不把 params.limit/offset 当作返回数量 |
| add | result.id，回退 memory_refs 的 ID；metadata 中 categories、keywords、anchors（存在才展示） | created=true 为“已创建”；false 为“已存在”；缺失则仅显示调用状态 |
| update | params.memory_id；请求中保留的 namespace、metadata.categories/keywords/anchors；有 namespace_before 与 namespace 且不同时显示空间迁移 | result.success=true 为“已更新”，false 为“未更新”；不能判断正文或 summary 是否修改，不查询当前记忆来补历史信息 |
| delete | params.memory_id | result.success=true 为“已删除”，false 为“未删除”；不能因 status=ok 就宣称删除成功 |
| get_details | params.memory_ids，缺失时使用 found/missing 中的 ID | found/missing 为数组时显示“找到 N / 缺失 M”；缺哪个不补 0 |
| report | event.search_id，回退 params.search_id；评分条目以 m_id: rating 展示前 3 项；保留负数和 0 | result.recorded=true 时显示“已记录 N 条评分”（count 缺失不编数量）；false 为“未记录”；不新增平均分等统计 |
| list_keywords | params.mode、queries、categories | 按 result.results 的每个查询组展示 query: total（最多 3 组）；不合计成去重总数、不以已裁剪 items 长度代替 total |
| stats | “读取统计” | 有 result.total 则展示记忆总量，否则只显示调用状态 |
| memory_import / memory_export / online_recover_start / online_recover | params 中存在的 filename、type、namespace_prefix、job_id/import_id；结果中的任务 ID 可补充 | 存在的 result.status、phase、records、imported、count；有多少展示多少，不把“已受理/运行中”描述为完成 |
| maintenance_enter / maintenance_exit | “进入维护模式” / “退出维护模式” | result.state，缺失时仅显示调用状态 |
| ndjson_health_check | params.trigger | result.in_sync=true/false 明确显示“一致/不一致”；缺失则只显示调用状态 |
| ndjson_compact | params.trigger | result.outcome（compacted/skipped），及实际存在的 file_bytes、after_bytes、reclaimed_bytes；没有字段则只显示调用状态 |
| model_config | “保存配置”；result 中存在的 port、language、auto_download_model、local_only，最多展示 3 项 | 仅显示调用状态，不展示 proxy 地址 |
| model_prepare / model_retry | “准备模型” / “重试准备模型” | result.status/phase/ready 中实际存在的值 |
| embedding_reindex / index_value_reindex | params.profile 中 provider/model、params.batch_size | result 中实际存在的 status、completed、total、count；CLI 独立日志不会因此被合并到页面 |

最后两类和维护任务中的可选键只做白名单读取，缺失即省略，不访问 config 或 storage 来补值。

### 共用边界规则

- Namespace 首选非空 event.namespace；缺失时使用 params.namespace；仍缺失时从 memory_refs.namespace 去重：一个显示名称，多个显示“多空间”并附名称摘要，没有则显示 —。不将缺失空间称为 All，不将反馈关联搜索空间冒充该事件的直接归属。后端筛选仍严格沿用原 event.namespace 语义，不增加 Namespace 点击筛选。
- 数组展示最多 3 项，剩余使用 +N。日志有对应 `*_total` / `*_truncated` 标记时优先保留真实总量或显示“日志已截断”，不凭保留片段编造剩余数量。
- `null`、缺失、不合法类型不参与拼接；0 和 false 必须保留其语义。只有有限非负数才能作为数量和耗时；ratings 可为负数。
- 错误结果优先展示 event.error 的 type/message；结构化 response_code（event 优先、result 回退）作为结果说明保留，即使 status=ok 也不能隐藏 namespace_not_found 等业务信息。status 只读取原值，不根据 result.error 或空结果重写。
- 未知 Action 使用通用白名单：params 中 query、memory_id、memory_ids、filename、type、trigger，以及 result 中 status、phase、count、records；无可用参数时显示“查看 JSON”。不直接 JSON.stringify 整个 params/result 放回列表。
- 不渲染 hint、完整路径、完整 metadata 或批量返回的记忆摘要。完整 API 事件继续由现有 JSON 抽屉展示，打开前后对象保持一致。

## 测试与验收

- 搜索：四种模式、关键词/分类/时间过滤、空结果、items/total 不同、未知空间结构化空结果。
- 写入与查看：新增去重、更新 true/false、删除 true/false、多个详情 ID、缺失记忆、跨 Namespace 的 memory_refs；证明不需要已裁剪的正文和 summary。
- 反馈/词表/后台：负评分/0/多条评分；多个词表查询组；运行中与完成任务区分、健康检查不一致、未知 Action、旧记录缺失字段及类型异常。
- 安全与显示：中文、HTML 字符、超长 query/ID/Namespace、数组 +N、日志截断标志、零耗时。打开的 JSON 与 API 原始对象完全一致。
- 浏览器：1440px 宽屏明暗主题、1100px 容器切换两侧、820px 与390px 窄屏；列头对齐、两行省略、内容不溢出，鼠标/键盘都能打开详情。
- 复跑 Audit 功能、debug-disabled 和综合 Admin 场景；只有修改共享抽屉/picker 时才额外重跑 Memory detail/create。

完成标准：无需打开抽屉即可识别 Action、空间、操作对象/条件和业务结果；缺失数据如实留空；整体保持应用风格。实施后标记待视觉验收，不自动 commit 或重启生产。
