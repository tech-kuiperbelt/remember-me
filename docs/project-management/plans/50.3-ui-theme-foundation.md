# [50.3] UI 第一步：主题基础

2026-10-01 记录计划并实施，已通过隔离验证，待用户 review。本项承接 [50.2 桌面布局](50.2-admin-desktop-layout.md)，
是后续“主题基础 → Shell 视觉 → Memories”三步工作的第一步。
设计依据为 [UI 设计规范](../../design/UI_DESIGN.md)、
[UI 实施规则](../../design/UI_IMPLEMENTATION_RULES.md) 和
[风格示意图](../../design/UI.png)。

## 目标与边界

建立统一的主题颜色和基础控件样式，实现 Light／Dark／System，为后续 Shell 视觉与
Memories 改造提供基础。

现有前端使用原生 HTML、CSS 和 ES modules，Shell 已完成。此次覆盖所有现有页面、
动态内容及弹窗的主题兼容；保留页面结构、导航、滚动方式和业务行为，不改后端、
不增加依赖。

## 主题入口与行为

- 按已确认选择，在配置页顶部新增独立的“外观”区域，位于“服务配置”之前。
- 使用有明确标签的原生下拉框：跟随系统、浅色、深色。选择立即生效，无需保存或
  进入维护模式。
- 提示“仅影响当前浏览器”；不提交到配置 API，不触发模型重试。
- 默认 `system`；保存到 `localStorage` 的 `remember-me.theme.v1`，仅接受
  `system`、`light`、`dark`，缺失或非法值回退为 `system`。
- `system` 随系统配色变化；手动选择不被系统变化覆盖。存储不可用时，本次页面内
  仍可正常切换。
- 切换只更新主题属性，不重建页面、不请求业务数据，保留表单、筛选、分页、滚动
  位置和弹窗状态。

## 实现方案

### 主题所有权与启动

- 新增 `web/static/js/theme.js`，独占主题偏好、系统监听及外观控件绑定，不进入
  业务 store 或布局模块。
- 为首次绘制及时应用主题，在 HTML 的样式表之前通过同步经典脚本加载；脚本使用
  封闭作用域，不暴露全局接口。
- 脚本立即为根元素设置实际的 `data-theme="light|dark"`，DOM 就绪后绑定选择框。
  它是专用于首屏主题的启动入口，现有业务入口保持原有职责。
- 使用 CSS `color-scheme` 适配原生控件。脚本未生效时，CSS 默认配色跟随系统。

### 颜色与基础控件

- 新增 `web/static/theme.css` 集中维护两套语义 token，初始色板采用 UI 设计规范；
  现有 `app.css` 通过 token 消费颜色。
- 补齐实际需要的危险按钮、状态浅背景、遮罩、焦点、disabled 和浮层阴影 token；
  主题色值集中定义。
- 统一系统字体及中文 fallback：正文与控件 13–14px、元数据不低于 12px；常规按钮
  和输入高度 32–36px、控件圆角 6px。
- 完整覆盖按钮 hover／active／disabled／focus-visible、输入框、select、checkbox、
  progress、分页和滚动条。
- 顶栏与侧栏先应用中性 Shell 配色；其尺寸、信息排列、图标和导航密度留给第二步。

### 现有内容兼容

- 清理 HTML 及详情、Memories、Search、Stats、Audit 动态模板里的硬编码颜色，改用
  语义 class；保留与布局有关的必要样式。
- 覆盖详情与清空确认弹窗、提示消息、状态 tooltip、命名空间下拉、代码与 JSON
  区域、搜索高亮和 Debug 标记。
- 状态颜色保持原有含义，普通标签使用中性配色；不增加数据或交互。
- 更新设计文档中的实际路径与图片引用，记录本步范围及主题所有权，保留已有
  未提交内容。

## 验证与验收

- 验证默认跟随系统、手动覆盖、系统动态变化、刷新恢复、非法存储值和存储读写失败。
- 首屏测试在主题脚本执行前预置偏好；确认业务入口尚未运行时，根元素已应用正确主题。
- 验证切换主题不会清空表单、改变页面或关闭弹窗；外观控件在维护、模型未就绪及
  API 失败时仍可用。
- Light／Dark 下遍历全部页面与两个弹窗，检查真实状态、动态数据、键盘焦点及关键
  操作。正文对比度至少 4.5:1，必要控件边界和焦点至少 3:1。
- 检查实测 CSS 视口 1440×900、1280×800、1024×768，以及 768×800 窄窗口；两种
  侧栏状态下主题入口和主要操作可达。窄窗口仅做兼容修复，不重排页面信息架构。
- 扩展现有隔离浏览器回归，支持主题场景与截图保留；截图写入临时目录，交付前
  实际查看，不使用生产数据。
- 运行 `.venv/bin/python tests/run_admin_browser.py`、
  `.venv/bin/python -m pytest -q`，并检查修改的 JavaScript 语法；不为纯颜色和
  间距增加机械测试。

本步可独立审查和回退；回退前端变更即可，遗留的浏览器主题偏好不会影响旧版应用。

## 执行决策

以下为实施前确认的口径，作为上面各节的落地细化：

1. **主题入口位置**：外观区放在配置页 `#page-ops` 顶部、位于“服务配置”之前；不放到顶栏。
2. **样式文件**：主题 token 独立为 `web/static/theme.css`，`app.css` 通过 `var(--…)` 消费颜色。
3. **首屏脚本严格限量**：`<head>` 内联脚本只做“读存储 + 设属性”一件事，硬约束：
   - 单一 IIFE，约 ≤12 行、≤500 字节，不暴露任何全局。
   - 仅读取 `localStorage['remember-me.theme.v1']`，取值只接受 `system`／`light`／`dark`，
     缺失或非法回退 `system`；为 `system` 时用 `matchMedia('(prefers-color-scheme: dark)')`
     解析；随后设置 `documentElement.dataset.theme`（实际）与
     `dataset.themePreference`（选择）。
   - 不含 DOM 就绪绑定、事件监听、控件绑定或任何业务/网络逻辑；这些全部在 `theme.js`。
   - 后续若逻辑超出该范围，必须迁入 `theme.js`，内联只保留“读值 + 设属性”。
4. **主题属性模型**：`data-theme` 只取 `light`／`dark`（实际生效）；`data-theme-preference`
   取 `system`／`light`／`dark`（用户选择）。`system` 变化只更新 `data-theme`，不改 preference。
5. **token 化范围（分期）**：本步 token 化核心控件、Shell（顶栏/侧栏/状态 chip）、弹窗/浮层/
   tooltip 与表格；页面级零散内联色在硬编码清理范围内处理，其余留第二、三步。
6. **硬编码颜色清理口径**：只清理暗色下不可读或对比度不足的颜色（固定浅底+深字、失效状态
   HEX、弹窗/tooltip/ns-dropdown/metadata/JSON/搜索高亮），替换为语义 class；`debug-ids`/
   `debug-focus` 保持不动；剩余清单记录在实施结果中。
7. **回归矩阵**：现有 5 尺寸 × 3 缩放功能回归保持不变（不翻倍主题）；新增主题专项
   `1440×900` 与 `768×800` × `{light, dark}`，覆盖默认/手动覆盖/系统变化/刷新恢复/非法值/
   存储失败、切换不清空表单与弹窗、外观控件在正常/维护/状态失败下可用、主题属性断言。
8. **首屏注入顺序**：`theme-boot（内联） → theme.css / app.css → （测试注入 harness）→ main.js`。
9. **外观区独立性**：外观控件不依赖 `loadOpsPage()` 的数据路径与 `model_not_ready` 早退，
   维护、模型未就绪、API 失败时均可操作。
10. **目标浏览器**：Chrome（沿用现有隔离回归，Chrome 149）；滚动条用 `scrollbar-color` 与
    `-webkit-scrollbar` 双写，`accent-color` 覆盖 checkbox／progress。
11. **设计文档路径**：本步不改 `UI_DESIGN.md` 的 `docs/ui/` 路径与两张参考图命名，仅在本文
    记录实际路径（`docs/design/`、单张 `UI.png`），路径统一留待专门小修正。

## 实施结果（2026-10-01）

- 配置页顶部增加独立“外观”选择框；切换即生效，偏好保存在浏览器。首屏内联脚本
  314 字节，只读取偏好并设置主题属性；`theme.js` 负责运行时交互和系统变化监听。
  存储不可用时仍可在当前页面切换，非法偏好回退到 `system`。
- `theme.css` 提供 Light／Dark 语义 token；基础控件、Shell、表格、弹窗、动态详情、
  Search／Stats／Audit 内容已接入。危险与成功提示分别使用满足白字对比度的实色
  token，状态文字保留较亮的暗色主题颜色。Debug 标记样式保持原样。
- 对比度抽查：深色危险按钮白字约 5.37:1、深色成功提示白字约 5.41:1；
  其余常规正文、控件和焦点以设计规范的 4.5:1／3:1 为验收目标。
- `.venv/bin/python -m pytest -q`：710 通过。隔离浏览器回归：原有 15 组
  尺寸／缩放场景与新增 13 组主题场景全部通过，覆盖系统变化、存储异常、非法值、
  刷新持久化、弹窗保持打开和主题截图。修改的 JavaScript 通过 `node --check`，
  `git diff --check` 通过。
- 实际浏览器截图保存在 `/tmp/remember-theme-review/`，已检查同尺寸明暗配置页、
  明暗 Memories、暗色详情弹窗、折叠侧栏和 768px 窄窗口。截图使用隔离服务的
  测试数据，不入仓库。配置页截图中的“状态不可用”来自该隔离服务的真实状态。
- 后续 Shell 视觉与 Memories 列表重排按原三步路线分别规划；本步保留这些页面的
  现有功能和结构。
